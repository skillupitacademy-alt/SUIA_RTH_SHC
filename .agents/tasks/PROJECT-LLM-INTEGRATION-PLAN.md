## Phase 1: Schema Reconciliation ✅ IN PROGRESS

### Understanding Current State

**Drizzle Schema Location**: `packages/db-tutorial/src/schema/project-ai-persistence.ts`

**Existing Tables** (already defined in Drizzle):
1. ✅ `project_ai_workflows` - Workflow lifecycle state
2. ✅ `project_ai_state_transitions` - Audit trail of state changes
3. ✅ `project_ai_contracts` - Immutable engineering contracts
4. ✅ `project_ai_candidates` - Candidate block packages
5. ✅ `project_ai_manifests` - Placement decisions
6. ✅ `project_ai_approvals` - Implementation approvals

**SQLAlchemy Models Location**: `services/project-ai/app/persistence/models.py`

**Schema Mismatch - Brand Columns**:

| Table | Drizzle Has | SQLAlchemy Expects | Status |
|-------|-------------|-------------------|--------|
| `project_ai_candidates` | ❌ Missing | `brand`, `uploader_brand` | **NEED TO ADD** |
| `project_ai_workflows` | ❌ Missing | `requester_brand` | **NEED TO ADD** |

### Why No Brands Table?

After investigating the schema, **there is NO brands table** in the tutorial database. The brand values are simple string identifiers:
- `"realtutorialhub"`
- `"skillupitacademy"`
- `"skillhubcore"`

These are **NOT foreign keys** - they're just `varchar` columns for tenant isolation.

## Risk Mitigation

### Risk 1: Schema Migration Breaks Existing Data

**Mitigation**:
- Columns are nullable (safe to add)
- No existing data in Project AI tables yet
- Migration is additive only (no deletions)
- Can rollback with `ALTER TABLE DROP COLUMN`

### Risk 2: Merge Conflicts Between Branches

**Mitigation**:
- Sequential merge (not parallel)
- Canonical-wiring has priority (most complete)
- Foundation unique features cherry-picked
- Test after each merge

### Risk 3: Test Failures After Integration

**Mitigation**:
- Run tests after each merge
- Schema fix resolves 7 known failures
- E2E tests verify end-to-end flow
- Can revert merges if needed
