feat: Security Hardening - CSRF, Worker Auth, Gateway & Origin Validation

This commit implements comprehensive security hardening across the entire platform architecture, introducing defense-in-depth mechanisms for CSRF protection, worker authentication, gateway proxy security, safe error responses, learner mutation origin validation, and extensive test coverage. This cross-cutting security enhancement protects all applications (API Server, RealTutorialHub, SkillUp, Gateway, Events, and SHC Admin) against common attack vectors including cross-site request forgery, worker request forgery, credential exposure, and enumeration attacks.

EXECUTIVE SUMMARY

This security hardening effort establishes multiple security layers across the platform:

1. CSRF Protection (API Server): Token-based validation for state-changing operations with self-healing token issuance when sessions exist but tokens are missing. Includes origin validation, internal API key bypass for service-to-service calls, and exemptions for public telemetry endpoints that cannot carry CSRF tokens.

2. Worker Authentication (RealTutorialHub & Events Package): QStash signature verification with destination validation prevents worker request forgery. All worker endpoints now verify signatures before processing, with comprehensive test coverage ensuring signature validation, tampered body rejection, expired token rejection, and cross-worker replay prevention.

3. API Gateway Security: Authentication middleware improvements with role-based access control, SHC admin portal verification, brand mismatch prevention, and comprehensive gateway health diagnostics. Gateway now properly validates token types, enforces admin role requirements, and preserves verified SHC portal identity.

4. Safe Error Responses (RealTutorialHub): Sanitization of error messages prevents credential exposure and stack trace leakage. All BFF routes now redact sensitive provider details (database connection strings, passwords, internal paths) while preserving request correlation for diagnostics.

5. Learner Mutation Origin Validation (Share Branding): Browser mutation endpoints validate origin headers to prevent CSRF attacks. Rejects cross-origin requests unless they carry internal gateway secrets, with special handling for Next.js localhost rewrites and worker endpoints.

6. Login Security (SHC Admin): Progressive enhancement with disabled form controls until hydration completes, safe error messages that hide upstream diagnostics, native POST fallback for no-JavaScript scenarios, and comprehensive E2E security tests.

7. Test Coverage Expansion: 381 new lines of test code including QStash security tests (87 lines), safe error response tests (47 lines), gateway security tests (50 lines), remediation service tests (53 lines), and E2E security tests (127 lines across 2 files).

8. Evidence Collection: Critical security evidence directories capturing gateway baseline comparisons, login security screenshots, and security test execution results for audit trails and security reviews.

SECURITY OVERVIEW

Multi-Layered Defense Architecture:

Layer 1 - Request Origin Validation: All browser-initiated mutations validate Origin/Referer headers against trusted request origins to prevent cross-site request forgery.

Layer 2 - CSRF Token Protection: API Server validates CSRF tokens on state-changing operations with cookie + header validation and self-healing token issuance.

Layer 3 - Worker Signature Verification: QStash workers verify JWT signatures with body hash validation, temporal claim validation (nbf/exp), issuer validation, and destination path/query validation to prevent request forgery.

Layer 4 - Gateway Authentication: API Gateway authenticates all protected routes with JWT verification, role-based access control, brand boundary enforcement, and portal identity preservation.

Layer 5 - Safe Error Responses: BFF routes sanitize all error responses to prevent credential exposure, with request correlation for diagnostics and proper cache-control headers.

Layer 6 - Test Coverage: Comprehensive test suites validate all security boundaries with positive and negative test cases, ensuring security mechanisms fail closed.

    Role Normalization:
    ```typescript
    /**
     * 🔥 UNIFIED ROLE NORMALIZATION (STRICT MODE)
     * 
     * RULES:
     * 1. ALWAYS return array (never undefined)
     * 2. ALWAYS lowercase
     * 3. ALWAYS deduplicate
     * 4. ❌ NO FALLBACK to ['user'] - empty roles = denial
     * 5. Support legacy 'role' field for backward compatibility
     */
    function normalizeRoles(payload: Partial<SkillHubCoreTokenPayload> & { role?: unknown }): string[] {
      const rawRoles = Array.isArray(payload.roles)
        ? payload.roles
        : typeof payload.role === 'string'
          ? [payload.role]
          : [];

      const roles = rawRoles
        .filter((role): role is string => typeof role === 'string' && role.trim().length > 0)
        .map((role) => role.trim().toLowerCase());

      // 🔥 CRITICAL FIX: NO FALLBACK - empty roles should be handled by RBAC
      return Array.from(new Set(roles));
    }
    ```

    Security Validation:

    - ✅ Rejects username/password in URL

    - ✅ Validates query parameters match exactly
    - ✅ Allows public and internal origins to differ (gateway proxy)
    - ✅ Throws SignatureError on mismatch

    Implementation:
    ```typescript
    export function assertWorkerDestination(signature: string, requestUrl: string): void {
      try {
        const payload = JSON.parse(Buffer.from(signature.split('.')[1], 'base64url').toString('utf8')) as { sub?: unknown };
        if (typeof payload.sub !== 'string') throw new Error('Missing destination');
        const signed = new URL(payload.sub);
        const actual = new URL(requestUrl);
        // Public and internal origins can differ behind the gateway
        if (!['http:', 'https:'].includes(signed.protocol) || signed.username || signed.password || signed.hash ||
            signed.pathname !== actual.pathname || signed.search !== actual.search) {
          throw new Error('Destination mismatch');
        }
      } catch {
        const error = new Error('Invalid worker destination');
        error.name = 'SignatureError';
        throw error;
      }
    }
    ```
