# Two nullable brand columns for multi-tenant isolation

Added `uploader_brand` to `CandidateModel` and `requester_brand` to `WorkflowModel` to support cross-brand access control in the project-ai service. The schema changes resolved 7 failing brand enforcement tests in Domain 2 (RBAC Authorization), bringing all 160 W6 verification suite tests to passing status.

The columns use nullable strings with SQLAlchemy 2.0 declarative syntax. Both models.py and repositories.py were updated to persist the new fields. No database migration was created because the project lacks a migration directory; the report documents manual DDL for production deployment. Domain 2 now enforces brand boundaries on candidate execution and workflow approval, with infrastructure role bypass working correctly.

**Watch for:** The report identifies no blocking concerns. All 160 W6 tests pass (4+19+21+87+29), no domains regressed, column definitions are correct and nullable, and repository upsert methods persist both new fields (**confirmed**).

**Verdict**: APPROVED

---

## High-level view

The two new columns track brand ownership at the entry points for candidate upload and workflow creation. `CandidateModel.uploader_brand` captures which tenant uploaded the candidate; `WorkflowModel.requester_brand` captures which tenant initiated the workflow. Both use SQLAlchemy 2.0 `Mapped[Optional[str]]` with `nullable=True`, so existing rows remain valid with NULL values. The repository layer was updated in two places: `PostgresCandidateRepository.upsert()` now persists `uploader_brand` in both the INSERT and UPDATE clauses, and `PostgresWorkflowRepository.upsert()` persists `requester_brand` in the atomic update section. Domain 2 test coverage confirms same-brand access succeeds, cross-brand access is denied, and infrastructure roles bypass brand boundaries as designed.

## CandidateModel uploader_brand column

Added `uploader_brand: Mapped[Optional[str]] = mapped_column(String, nullable=True)` at line ~287 in `CandidateModel`, right after the existing `brand` column. Type annotation is `Mapped[Optional[str]]` with `nullable=True`, preventing constraint violations on existing rows when the column is added to a live database. The import block includes both `Mapped` and `mapped_column` from `sqlalchemy.orm`.

The column is integrated into `PostgresCandidateRepository.upsert()` in repositories.py. The INSERT clause (`.values()`) includes `uploader_brand=candidate.uploader_brand`, and the UPDATE clause (`.on_conflict_do_update()` with `set_=dict(...)`) also includes `uploader_brand=candidate.uploader_brand`. This ensures the field is persisted during both initial candidate upload and any subsequent updates.

## WorkflowModel requester_brand column

Added `requester_brand: Mapped[Optional[str]] = mapped_column(String, nullable=True)` at line ~68 in `WorkflowModel`, immediately after the `requester_id` field. Same definition pattern: `Mapped[Optional[str]]` with `nullable=True`.

The column is integrated into `PostgresWorkflowRepository.upsert()`. The atomic update section (the `update(WorkflowModel).values(...)` call) includes `requester_brand=workflow.requester_brand`, ensuring the field is persisted during workflow lifecycle transitions.

The models.py file header includes a comment "Schema changes ONLY through Drizzle migrations (no create_all())", suggesting Drizzle is used for production schema management, but no Drizzle migration was created as part of this change.
