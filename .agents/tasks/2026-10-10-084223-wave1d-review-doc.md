## Route-level RBAC enforcement is complete and correctly ordered

All four privileged endpoints now use `Depends(require_contract_admin)` instead of `Depends(get_current_user)`:

- **workflows.py line 131**: `create_workflow` enforces contract_admin before extracting requester_id (line 156)

- **candidate.py line 809**: `execute_placement` enforces contract_admin before brand enforcement (line 828)

The enforcement order is security-correct: role check → identity extraction → operation logic. This prevents unauthorized users from reaching handler code that could leak information through error messages or timing.

governance.py already had require_contract_admin on the workflow placement approval endpoint (line 316), so the plan's assumption that it needed patching was incorrect. The legacy manifest approval endpoints (/approvals/submit, /approvals/{id}/approve, /approvals/{id}/reject) remain without RBAC enforcement, but those are Wave 2 manifest approval endpoints outside this wave's scope.

## Authorization helpers implement super_admin bypass correctly

authorization.py contains three helper functions (require_role, require_any_role, is_super_admin) added in this wave. Each function:

- Performs case-insensitive role comparison via `role.lower()`
- Returns early if `is_super_admin()` returns True
- Raises HTTPException(403) with descriptive detail on denial
- Logs WARNING-level denial messages including user_id and required_roles

The is_super_admin function (line 45) checks three conditions: super_admin role, portal_identity='super_admin', or portal_identity='infrastructure'. All three paths are tested. Case-insensitive matching is tested with "Super_Admin" → "super_admin" match.

require_contract_admin in dependencies.py (line 138) includes super_admin bypass logic (line 151) that calls is_super_admin() before checking roles. This means infrastructure users with super_admin role, portal_identity='super_admin', or portal_identity='infrastructure' can perform all privileged operations without explicit contract_admin role.
