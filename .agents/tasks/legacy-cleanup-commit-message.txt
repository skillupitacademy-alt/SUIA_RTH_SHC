refactor(rth): Remove V1 Tutorial System & Refine Shared Auth [Legacy Cleanup]

EXECUTIVE SUMMARY

This commit represents a major architectural cleanup that removes the deprecated 
RealTutorialHub (RTH) V1 tutorial system after successful V2 migration. The work 
spans 32 files with a net reduction of 2,021 lines of legacy code (-2,107 deletions, 
+86 additions) across 17 deleted files and 15 modified files.

The cleanup removes 8 legacy tutorial pages, 9 dedicated V1 components, and 3 
associated test files that were built for the original `/learn/` URL structure. 
These routes have been fully replaced by the V2 tutorial system which uses 
`/tutorial`, `/tutorial-v2/`, `/remediation`, and `/tutorial/assignments/` paths.

Alongside the legacy removal, this commit refines the shared authentication system 
used by both RealTutorialHub and SkillUp IT Academy brands. These refinements 
improve hydration safety, eliminate redundant Suspense wrappers that prevented 
no-JS form rendering, and update middleware to protect the new canonical paths.

The V1 system cleanup reduces maintenance burden, eliminates route confusion, 
clarifies the codebase architecture, and sets a clear foundation for V2-only 
development going forward. Evidence of the changes, verification testing, and 
security validation is documented in `.evidence/closure-20261112/`.

ARCHITECTURAL RATIONALE

The RealTutorialHub V1 tutorial system was built around a hierarchical URL 
structure at `/learn/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]/` 
with dynamic route parameters and specialized components like `TutorialExperience`, 
`TutorialSidebar`, `BlockNavPills`, and `TutorialKeyboardNav`. This system served 
learners accessing tutorial content through deep-linked paths.

The V2 tutorial system replaced this architecture with a query-parameter-based 
approach (`/tutorial?domain=...&subject=...&topic=...&subtopic=...`) and node-based 
navigation (`/tutorial-v2/[...path]/[nodeId]`). V2 introduced improved state 
management, better progress tracking, enhanced accessibility, and a unified 
component architecture shared across brands.

With the V2 system now fully operational and all learner traffic migrated, the V1 
pages, components, and tests became dead code. Retaining them created:
- Route ambiguity (two systems serving similar content)
- Maintenance overhead (keeping outdated components operational)
- Codebase confusion (developers unsure which system to modify)
- Testing complexity (redundant test coverage for deprecated flows)

This cleanup is safe because:
1. All V1 routes now return 404 (verified by E2E tests)
2. Canonical replacements exist for all functionality:
   - `/learn/remediation/` → `/remediation`
   - `/learn/[...]/assignments` → `/tutorial/assignments/[...]/`
   - `/learn/[...]/[subtopicSlug]` → `/tutorial?...` or `/tutorial-v2/[...]/[nodeId]`
3. Sitemap, robots.txt, and middleware have been updated to reference V2 paths only
4. All unit tests, lints, type-checks, and production builds pass
5. 17 Playwright E2E tests verify login security and route retirement across both brands

The auth refinements improve security and progressive enhancement:
- Hydration gates prevent form submission before client JS loads
- Synchronous double-submit locks prevent duplicate authentication requests
- Redundant Suspense wrappers removed so SSR renders native `<form method="post">` 
  correctly when JavaScript is disabled or delayed
- Middleware updated to protect new canonical paths (`/remediation`, 
  `/tutorial/assignments`)

18. src/share-branding/AuthPage.tsx (21 changes)
    WHAT CHANGED:
    - Added hydration state management with `isHydrated` state and `useEffect` 
      hook that sets `isHydrated` to `true` only after client mount
    - Added synchronous double-submit prevention with `submittingRef` using 
      `useRef<boolean>` to lock form submission during processing
    - Added `method="post"` and `action={mode === 'signup' ? '/signup' : '/login'}` 
      attributes to `<form>` element to enable native HTML form submission when 
      JS is disabled
    - Added `noValidate` attribute to form to prevent browser validation (handled 
      by our validation logic)
    - Added `disabled={!isHydrated || isLoading}` to all form inputs (`#email`, 
      `#password`, `#full-name`), password visibility toggle button, and submit 
      button to prevent interaction before hydration completes
    - Added `initial={false}` to Framer Motion `AnimatePresence` component so 
      SSR HTML is rendered without motion transforms that would hide content 
      before JS loads
    - Integrated `sanitizeLearnerRedirect` function to validate and sanitize 
      redirect query parameter after successful login, preventing open redirect 
      vulnerabilities
    - Set `navigating = true` flag before navigation to prevent clearing 
      `submittingRef` and `isLoading` state during redirect
    - Added `sessionStorage.setItem('skip_initial_refresh', 'true')` before 
      navigation to signal to V2 pages that session is fresh and doesn't need 
      redundant validation
    
    WHY CHANGED:
    - Hydration gate ensures form controls remain disabled until React has 
      hydrated the page, preventing submission with incomplete client state
    - Synchronous double-submit lock prevents race conditions from rapid clicks 
      or repeated Enter key presses
    - Native `method="post"` and `action` attributes ensure forms still declare 
      their submission intent even when JavaScript is disabled or delayed (progressive 
      enhancement)
    - `initial={false}` on motion prevents Framer Motion from hiding form content 
      during SSR/hydration, ensuring visual accessibility
    - Redirect sanitization closes security vulnerabilities where attackers could 
      craft phishing URLs like `/login?redirect=//evil.example/phish`
    
    SECURITY IMPACT:
    - Prevents submission with incomplete client state
    - Eliminates duplicate authentication requests
    - Closes open redirect attack vectors
    - Maintains visual form availability during hydration delay
    - Reduces attack surface by preventing premature form interaction

19. apps/realtutorialhub-web/src/app/login/page.tsx (7 changes - wrapper removal)
    WHAT CHANGED:
    - Removed redundant outer `<Suspense fallback={...}>` wrapper that wrapped 
      the `<AuthPage>` component
    - Now returns `<AuthPage brand="realtutorialhub" initialMode="login" />` 
      directly
    
    WHY CHANGED:
    - The Suspense wrapper was preventing native `<form method="post">` from 
      rendering in SSR HTML when React couldn't resolve the boundary
    - With Suspense removed, Next.js SSR renders the form element directly in 
      the initial HTML, enabling no-JS form submission
    - `<AuthPage>` is a client component ('use client') and doesn't need Suspense 
      wrapping; its internal state and effects handle hydration
    
    PROGRESSIVE ENHANCEMENT IMPACT:
    - Form element now appears in initial SSR HTML
    - Disabled form controls are visible but non-interactive when JS is delayed
    - Native POST to `/login` endpoint is declared in HTML markup
    - Users with JavaScript disabled see a visible form (though controls are 
      disabled by the `disabled` attribute until JS hydration)

BREAKING CHANGES
================================================================================

V1 TUTORIAL URLS REMOVED (404 RESPONSES)
All legacy `/learn/` URLs now return 404 Not Found. These URLs have been 
deprecated and replaced by V2 canonical paths:

DELETED URLS:
- /learn
- /learn/remediation
- /learn/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]
- /learn/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]/[blockType]
- /learn/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]/assignments

CANONICAL REPLACEMENTS:
- /learn/remediation → /remediation
- /learn/[...]/assignments → /tutorial/assignments/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]
- /learn/[...]/[subtopicSlug] → /tutorial?domain=...&subject=...&topic=...&subtopic=...
- /learn/[...]/[subtopicSlug]/[blockType] → /tutorial-v2/[domainSlug]/[subjectSlug]/[topicSlug]/[subtopicSlug]/[nodeId]

IMPACT:
- Bookmarks to old `/learn/` URLs will break (404)
- External links to old `/learn/` URLs will break (404)
- Search engine indexed `/learn/` URLs will 404 until recrawled
- Internal application links have been updated to V2 paths
- Sitemap now contains only V2 URLs for future crawls

MIGRATION:
No automated redirect handling is provided. Users encountering 404s should:
1. Use site navigation to find content (all content remains accessible via V2 routes)
2. Use search functionality to locate specific topics
3. Use /start-learning page as entry point to tutorial system

AUTHOR NOTES
================================================================================

This commit represents the culmination of the V1 → V2 tutorial system migration 
that has been in progress over multiple releases. With all learner traffic now 
successfully migrated to the V2 system and comprehensive testing validating that 
all functionality has been preserved or improved, the legacy V1 codebase is now 
safe to remove.

The cleanup eliminates nearly 2,000 lines of code that would otherwise require 
ongoing maintenance, security updates, and mental overhead for developers trying 
to understand which system is authoritative. Going forward, there is one clear 
tutorial system (V2) with well-defined canonical paths and a unified architecture.

The auth refinements included in this commit improve security posture and 
progressive enhancement without introducing breaking changes to the authentication 
flow. The addition of comprehensive E2E security tests provides regression 
protection and serves as living documentation of expected security behavior.

Evidence artifacts and the delta closure report provide a permanent record of 
the architectural decisions made, security validations performed, and quality 
gates passed, supporting future audits and architectural reviews.
