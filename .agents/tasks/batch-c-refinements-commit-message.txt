ARCHITECTURAL SCOPE

The 5-tier academic hierarchy:
  Domain → Subject → Topic → Subtopic → Skill

All destructive operations centralized in AcademicHierarchyService:
- Single entity deletions: deleteDomain, deleteSubject, deleteTopic, deleteSubtopic, deleteSkill
- Batch deletions: batchDeleteDomains, batchDeleteSubjects, batchDeleteTopics, batchDeleteSubtopics, batchDeleteSkills
- Dependency verification: checkDomainDependencies, checkSubjectDependencies, checkTopicDependencies, checkSubtopicDependencies, checkSkillDependencies
- Concurrency safety: acquireRowLock using Drizzle .for('update')

Cross-database contracts:
- MainDB (PostgreSQL): Academic hierarchy canonical storage
- TutorialDB (PostgreSQL): Learner-facing content and navigation trees
- Identity mapping: topics.id ↔ tutorialTopics.externalId, subtopics.id ↔ tutorialSubtopics.externalId
- Multi-tenant isolation: skillup (SUIA) vs realtutorialhub (RTH)
- Brand precedence: brand-specific override > shared canonical > null

SERVICE ENHANCEMENTS & ARCHITECTURAL IMPROVEMENTS:

A. Concurrent Destructive Operation Safety (BC-CORR-03)

   Implemented acquireRowLock() function to acquire row-level exclusive locks
   using Drizzle ORM .for('update') before dependency verification:

   async function acquireRowLock(entityType: string, entityId: string, query: unknown): Promise<void> {
     try {
       if (query && typeof query === 'object' && 'for' in query && typeof (query as LockableQuery).for === 'function') {
         await (query as LockableQuery).for('update');
       }
     } catch (error) {
       if (error instanceof DependencyCheckUnavailableError) throw error;
       throw new DependencyCheckUnavailableError(entityType, entityId, error);
     }
   }

   This prevents race conditions where concurrent transactions insert child records
   between dependency check and parent deletion. Applied to all 10 deletion methods:
   - deleteDomain, batchDeleteDomains
   - deleteSubject, batchDeleteSubjects
   - deleteTopic, batchDeleteTopics
   - deleteSubtopic, batchDeleteSubtopics
   - deleteSkill, batchDeleteSkills

   Pattern: Wrap entire deletion in db.transaction → acquireRowLock → verify dependencies → delete

B. Physical Row Retention for CASCADE Protection (BC-CORR-02)

   Removed isNull(deletedAt) filters from ALL dependency check queries:
   - checkDomainDependencies: queries subjects without deletedAt filter
   - checkSubjectDependencies: queries topics without deletedAt filter
   - checkTopicDependencies: queries subtopics, questions, topicSkills without deletedAt filter
   - checkSubtopicDependencies: queries questions without deletedAt filter
   - checkSkillDependencies: queries topicSkills, questionSkills, questions without deletedAt filter

   Rationale: PostgreSQL foreign key constraints and ON DELETE CASCADE triggers
   operate at physical storage engine level. A soft-deleted child record (deletedAt IS NOT NULL)
   still has a physical foreign key reference. Deleting the parent would either:
   a) Physically cascade delete the soft-deleted child (unintended permanent data loss)
   b) Violate RESTRICT constraint (database error)

   Solution: Block parent deletion with HTTP 409 Conflict if ANY physical child row exists,
   regardless of soft-delete status. This guarantees referential safety without requiring
   schema changes or CASCADE configuration inspection.

F. Transaction-Wrapped Atomic Deletion Pattern

   All 10 deletion methods use consistent transaction wrapping:

   static async deleteDomain(id: string): Promise<HierarchyDeleteResult> {
     if (!isValidUuid(id)) {
       return { status: 400, error: 'Invalid UUID format for Domain ID' };
     }

     const db = getDb();
     const runInTx = async (tx: DbExecutor): Promise<HierarchyDeleteResult> => {
       // 1. Acquire row lock to serialize concurrent transactions and prevent concurrent child creation
       await acquireRowLock('domain', id, tx.select({ id: domains.id }).from(domains).where(eq(domains.id, id)));

       // 2. Verify dependencies within the transaction
       const conflict = await checkDomainDependencies(id, tx);
       if (conflict) {
         return {
           status: 409,
           error: conflict.message,
           conflictType: 'DEPENDENCY_CONFLICT',
           entityType: 'domain',
           entityId: id,
           dependencies: conflict.dependents,
         };
       }

       const [deleted] = await tx.delete(domains).where(eq(domains.id, id)).returning();
       if (!deleted) {
         return { status: 404, error: 'Domain not found' };
       }

       return { status: 200, message: 'Domain deleted successfully' };
     };

     try {
       if ('transaction' in db && typeof db.transaction === 'function') {
         return await db.transaction(runInTx);
       }
       return await runInTx(db);
     } catch (error) {
       if (error instanceof DependencyCheckUnavailableError) {
         return {
           status: 503,
           error: 'Dependency verification storage is temporarily unavailable. Deletion aborted to prevent unsafe cascade.',
         };
       }
       console.error('[AcademicHierarchyService] Error during domain deletion:', error);
       return {
         status: 500,
         error: 'Internal server error during domain deletion',
       };
     }
   }

   Batch deletion pattern wraps ALL dependency checks and delete in single transaction:

   static async batchDeleteDomains(rawIds: unknown): Promise<HierarchyDeleteResult> {
     const validation = validateBatchDeletePayload(rawIds, 'Domain');
     if (!validation.success || !validation.ids) {
       return {
         status: (validation.status ?? 400) as 400 | 413,
         error: validation.error ?? 'Invalid batch request',
       };
     }

     const ids = validation.ids;
     const db = getDb();

     const runInTx = async (tx: DbExecutor): Promise<HierarchyDeleteResult> => {
       // 1. Acquire row locks on target batch entities
       await acquireRowLock('domain', ids.join(','), tx.select({ id: domains.id }).from(domains).where(inArray(domains.id, ids)));

       const conflictingIds: string[] = [];
       const aggregatedDependencies: Record<string, number> = {};

       for (const id of ids) {
         const conflict = await checkDomainDependencies(id, tx);
         if (conflict) {
           conflictingIds.push(id);
           for (const [key, val] of Object.entries(conflict.dependents)) {
             aggregatedDependencies[key] = (aggregatedDependencies[key] ?? 0) + val;
           }
         }
       }

       if (conflictingIds.length > 0) {
         return {
           status: 409,
           error: `Cannot delete domains because dependent subjects exist for ${conflictingIds.length} item(s)`,
           conflictType: 'DEPENDENCY_CONFLICT',
           entityType: 'domain',
           conflictingIds,
           dependencies: aggregatedDependencies,
         };
       }

       await tx.delete(domains).where(inArray(domains.id, ids));
       return { status: 200, message: `${ids.length} domains deleted successfully` };
     };

     try {
       if ('transaction' in db && typeof db.transaction === 'function') {
         return await db.transaction(runInTx);
       }
       return await runInTx(db);
     } catch (error) {
       if (error instanceof DependencyCheckUnavailableError) {
         return {
           status: 503,
           error: 'Dependency verification storage is temporarily unavailable. Deletion aborted to prevent unsafe cascade.',
         };
       }
       console.error('[AcademicHierarchyService] Error during batch domain deletion:', error);
       return {
         status: 500,
         error: 'Internal server error during batch domain deletion',
       };
     }
   }
