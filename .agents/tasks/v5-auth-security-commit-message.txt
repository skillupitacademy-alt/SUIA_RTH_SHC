feat: V5 Auth Security & Content Blocks - Redirect Sanitization & State Validation

EXECUTIVE SUMMARY

This V5 commit delivers comprehensive authentication security hardening across the
shared learner authentication system (RTH and SkillUp), introduces redirect sanitization
to prevent open redirect attacks, expands auth state validation with SSR gateway support
and retry logic, enhances content block rendering with modular format support, and
establishes E2E security test coverage for learner login flows. The work addresses
critical security boundaries including credential exposure prevention, diagnostic
string leakage protection, auth loop mitigation, and multi-brand isolation enforcement.

Security improvements include a new sanitizeLearnerRedirect utility that blocks
protocol-relative redirects, backslash path traversal, URL-encoded attacks, control
characters, and auth page loops. Auth state validation now supports SSR with internal
gateway secrets, fail-closed behavior when gateway is unavailable, timeout handling,
retry logic with exponential backoff, and redacted logging to prevent identity leakage
in console output.

Content block components (CodeBlock, LaymanBlock, RealLifeBlock, TechnicalBlock) now
detect modular vs legacy format and route to appropriate renderers, maintaining backward
compatibility while supporting the new content schema. RTH tutorial sections API route
was added to proxy tutorial sections through the centralized API with brand context.

Comprehensive E2E security tests validate login flows without JavaScript (SSR-disabled
controls), hydration-delayed controls, native form POST interception, redirect
sanitization, diagnostic string redaction, signup double-submit protection, and
credential exposure prevention across request URLs, console logs, and page errors.

Test infrastructure improvements include Vitest configuration with path aliases,
setup file with jsdom environment and mock globals, and expanded test coverage for
assignment auth, sanitize redirect, student auth, and tutorial API routes.

2. src/share-branding/auth/sanitizeLearnerRedirect.ts (NEW - 62 lines)
   ────────────────────────────────────────────────────────────────────
   
   REDIRECT ATTACK PREVENTION:
   • sanitizeLearnerRedirect(raw, fallback = '/dashboard'): Returns sanitized
     internal path or fallback
   
   VALIDATION RULES (returns fallback on violation):
   • Type check: Only string values accepted
   • Must start with '/' (internal path required)
   • Must not start with '//' (protocol-relative redirect blocked)
   • Must not contain backslashes (path traversal blocked)
   • Control character check: Rejects ASCII 0x00-0x1f and 0x7f
   
   URL-ENCODED ATTACK PREVENTION:
   • Extracts raw path before query/hash with split(/[?#]/, 1)
   • Regex check for encoded attacks: /%2f|%5c|%00|%0a|%0d/i
   • Blocks encoded slashes (%2f), backslashes (%5c), null bytes (%0a), newlines (%0d)
   
   AUTH LOOP PREVENTION:
   • BLOCKED_AUTH_PATHS Set: /login, /signup, /register, /forgot-password, /reset-password
   • Normalized pathname (trailing slash removed) checked against blocked set
   • Case-insensitive comparison (.toLowerCase())
   
   ORIGIN VALIDATION:
   • URL parsed with learner.internal dummy origin
   • Parsed origin must match learner.internal (ensures relative path)
   • Returns pathname + search + hash (preserves query params and anchors)
   
   CONTROL CHARACTER DETECTION:
   • hasControlCharacter: Manual loop checking charCodeAt for 0x00-0x1f and 0x7f
   • Faster than regex for small strings, catches injection attempts

═══════════════════════════════════════════════════════════════════════════════

• Blocks auth page loops (/login, /signup, /register, /forgot-password, /reset-password)
• Validates origin to prevent absolute URLs
• Preserves query parameters and hash fragments

AUTH STATE VALIDATION EXPANSION:
• SSR gateway validation with internal secret authentication
• Fail-closed behavior when gateway unavailable
• Timeout handling (3 seconds per attempt)
• Retry logic with exponential backoff (max 3 attempts)
• Redacted logging (user identity not exposed in console)
• Browser validation uses relative /api/profile endpoint
• Supports multiple payload shapes for gateway compatibility
• Validates id and email presence before accepting payload

DIAGNOSTIC STRING PROTECTION:
• mapLoginError ignores response body entirely
• publicAuthErrorMessage maps HTTP status to fixed public messages
• No SQL errors, stack traces, or internal diagnostics exposed to frontend
• Error boundary in AuthPage catch block uses public messages only
• E2E tests validate diagnostic canary not visible on error pages

SSR CONTROL DISABLEMENT:
• Form controls disabled until React hydration completes
• Native form POST targets /login and /signup for no-JS fallback
• Prevents credential submission before JavaScript loads
• E2E tests validate controls stay disabled during script delay

DOUBLE-SUBMIT PROTECTION:
• submittingRef synchronous lock prevents race conditions
• Checked before async work begins
• Reset only when not navigating
• E2E test validates single submission with rapid double requestSubmit()

CREDENTIAL EXPOSURE PREVENTION:
• No credentials in query parameters
• No credentials in request URLs or referrers
• No credentials in console logs or page errors
• No credentials in frame navigation URLs
• E2E tests monitor all exposure vectors with synthetic canaries

DEVICE TRACKING:
• getDeviceHeaders() injected into login/signup requests
• Device context headers included in authentication
• Persistent device ID for security monitoring

CACHE-CONTROL ENFORCEMENT:
• All BFF routes return 'Cache-Control: private, no-store'
• Prevents public CDN caching of user-specific content
• Tutorial sections, progress, and content routes enforce private caching
