## CreationMode replacement with DesignSource

The old CreationMode enum defined three values that encoded workflow bypass logic:
- I2_ONLY: shortcut to duplicate existing I2 block structure without gates
- MIX_AND_MATCH: component selection bypass allowing arbitrary composition
- NEW_CANDIDATE: intended for External AI candidates but not distinguishable from other modes

The new DesignSource enum defines three values that describe content origin without bypassing workflow:
- REPOSITORY_CANONICAL: design copied from existing canonical blocks (I1-I6, C1-C5, etc.)
- EXTERNAL_AI_PROTOTYPE: design created by External AI from user requirements plus repository context
- USER_SPECIFICATION: design specified directly by user with explicit requirements

All three DesignSource values follow the same CanonicalWorkflowState lifecycle. The enum's docstring explicitly states: "All design sources follow the same CanonicalWorkflowState lifecycle: REQUESTED → DISCOVERY → BRIEF_READY → ... → CERTIFIED. DesignSource controls WHAT is discovered, not HOW workflow proceeds."

References to CreationMode in models, schemas, and routes are updated:
- `app/models/creation.py`: CompositionSpec.mode changed to design_source, CreationWorkflow.mode changed to design_source
- `app/api/schemas/creation.py`: CreateWorkflowRequest.mode removed, WorkflowResponse.mode removed
- `app/api/routes/creation.py`: import changed from CreationMode to DesignSource

The CreationWorkflow model is marked DEPRECATED. WorkflowStatus enum (CREATED, VALIDATING, CERTIFYING, CERTIFIED, FAILED) is also marked DEPRECATED with documentation stating it exists only for backward compatibility and maps to CanonicalWorkflowState.

## Legacy endpoint retirement via 405

All four /creation endpoints are disabled. The pattern is consistent:
1. Add `status_code=405` to the route decorator
2. Replace the entire function body with a single HTTPException throw
3. Include structured error detail with migration guidance

Example from POST /creation/workflows:

```python
@router.post("/workflows", response_model=WorkflowResponse, status_code=405)
async def create_workflow(request: CreateWorkflowRequest):
    """
    DEPRECATED (M2.9 Wave 0): Legacy workflow creation endpoint.
    
    This endpoint bypassed canonical workflow lifecycle and is now disabled.
    
    Use canonical workflow instead:
    1. POST /tasks/plan - initiate workflow with repository discovery
    2. Wait for AWAITING_GATE_1 state
    3. Approve GUI prototype
    4. POST /candidates/upload - upload candidate package
    5. POST /governance/{approval_id}/approve - approve placement
    6. Wait for CERTIFICATION_READY
    7. POST /governance/{approval_id}/approve - final certification
    
    Architectural Rule: All workflows follow CanonicalWorkflowState (17 states).
    No workflow bypass via mode/composition shortcuts.
    """
    raise HTTPException(
        status_code=405,
        detail={
            "error": "LEGACY_ENDPOINT_DISABLED",
            "message": "POST /creation/workflows is deprecated (M2.9 Wave 0). Use canonical workflow endpoints.",
            "canonical_workflow": {
                "initiate": "POST /tasks/plan",
                "status": "GET /tasks/{task_id}",
                "upload": "POST /candidates/upload",
                "approve": "POST /governance/{approval_id}/approve"
            },
            "reason": "CreationMode allowed workflow bypass (I2_ONLY, MIX_AND_MATCH), violating architectural requirement that all candidates follow same lifecycle."
        }
    )
```

Each endpoint's error message identifies the specific canonical replacement. POST /creation/workflows/{id}/validate explains validation now happens automatically in DISCOVERY and CANDIDATE_AUDIT states. POST /creation/workflows/{id}/certify explains certification now happens automatically across CANDIDATE_AUDIT, VERIFYING, and CERTIFICATION_READY states.

The changes remove approximately 300 lines of validation logic, compatibility checking, component resolution, snapshot loading, certification gate execution, and gate result aggregation. This code is deleted, not relocated. Canonical workflow implementation in other modules (certification/gates.py, orchestration/canonical_workflow.py, verification/runtime.py) provides equivalent functionality without the workflow bypass logic.
