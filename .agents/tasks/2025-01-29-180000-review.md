# W2 Engineering Contract Generation

W2 adds the EngineeringContract schema, wires contract generation through real W1A WorkflowTarget binding and real W1B RepositoryIntelligenceService, implements deterministic SHA-256 hashing with sort_keys=True, enforces contract immutability after workflow binding, transitions workflow state to BRIEF_READY with governance_service.transition_state, binds contract artifacts with SHA-256 via governance_service.bind_artifact, records evidence through the W1D harness, and ships prohibited behaviors for architectural boundaries. The contract route consumes TypeScript-produced snapshot.json (respecting the Python-must-not-scan-repository boundary). Hash calculation correctly excludes contract_hash field and uses sorted JSON serialization.

**Watch for**: Evidence harness receives placeholder commit hashes ("bb5fe7a6" before and after) instead of real git state (confirmed). Snapshot SHA-256 is computed from file bytes (deterministic and correct). Eight integration tests fail due to missing pytest-asyncio configuration — the tests themselves are architecturally sound, the failure is environmental. All prohibited behaviors ship as specified.

**Verdict**: NEEDS_CHANGES

## High-level view

Contract generation retrieves the workflow's actual target_family and target_version from governance_service.get_workflow — no placeholder Introduction/I7 hardcoding — and fails fast if target fields are empty or whitespace. The route calls build_contract(snapshot, family, version) from repository_intelligence.py, which extracts canonical_block evidence from the TypeScript snapshot without scanning repository files. Hash calculation uses json.dumps with sort_keys=True to ensure determinism across Python dictionaries. The contract_hash field is excluded from the hash input via model_dump(exclude={"contract_hash"}) to prevent circular dependency. After generation, the route calls governance_service.bind_artifact with artifact_type="contract" and the contract's SHA-256, then calls governance_service.transition_state with to_state=CanonicalWorkflowState.BRIEF_READY. Immutability enforcement checks if workflow_id already exists in contracts_store and returns the cached contract; on return, it verifies the workflow's current target hasn't drifted. The route calls record_agent_run with an AgentRun instance, but commitBefore and commitAfter are both hardcoded to "bb5fe7a6" rather than queried from git. Integration tests verify real W1A wiring, real W1B data, hash determinism under modification, immutability on second call, state transition, artifact binding with SHA-256, and prohibited behaviors — but all async tests fail because pytest-asyncio is not configured in pyproject.toml or conftest.py.

## Real W1A WorkflowTarget binding replaces placeholder Introduction/I7

The contract route calls governance_service.get_workflow(workflow_id) to retrieve the workflow's bound target, extracting target_family and target_version from workflow_obj fields (lines 370-383). If target_family is empty or whitespace, it raises HTTPException 400. The same check applies to target_version. WorkflowTarget is constructed from these validated fields, not hardcoded "Introduction"/"I7".

On second call (lines 358-368), the route verifies workflow_obj.target_family and workflow_obj.target_version haven't drifted from existing_contract.target fields. If drift is detected, it raises HTTPException 409. This guards against workflow mutation bugs or admin endpoints changing target after contract generation.

## Real W1B RepositoryIntelligenceService consumes TypeScript snapshot

The route loads snapshot.json via load_repository_snapshot(workspace_root) at line 396 (packages/project-llm-discovery/output/snapshot.json). If missing, it raises HTTPException 404. repository_snapshot_sha256 is calculated at line 399 by opening the snapshot file in binary mode and hashing actual file bytes (4KB chunks), making it deterministic regardless of JSON serialization order.

build_contract(snapshot, family, version) at line 402 extracts canonical_block evidence from snapshot['evidence'], filters by kind=='canonical_block', and searches for entries matching block_patterns[(family, version)]. canonical_references is populated from snapshot evidence. Required_artifacts, acceptance_criteria, and contract dicts come from hardcoded lists (lines 216-250).

repository_intelligence.py ships backward-compatibility shims compute_sha256(file_path) and build_contract_legacy(repo_root, family, version) that scan repository files directly, violating the architectural boundary. Docstrings mark them DEPRECATED for test compatibility only.

## Hash calculation is deterministic and excludes contract_hash field

calculate_contract_hash (lines 165-186) calls contract.model_dump(exclude_none=True, by_alias=True, exclude={"contract_hash"}, mode="json"), removing the contract_hash field to prevent circular dependency. The dict is serialized via json.dumps(contract_dict, sort_keys=True, ensure_ascii=False). sort_keys=True ensures determinism — Python dict insertion order is stable since 3.7, but Pydantic field order and nested dicts aren't guaranteed without explicit sorting. The UTF-8-encoded JSON is hashed with hashlib.sha256.

## Immutability enforcement prevents contract regeneration after binding

The route checks if workflow_id in contracts_store before generating (lines 357-368). If found, it verifies workflow_obj target fields match existing_contract.target fields. If drift detected, raises HTTPException 409. Otherwise returns existing_contract without regenerating.

contracts_store is a module-level dict (line 149) with comment "WARNING: This is a Wave 2 placeholder. Contracts are lost on server restart." On restart, contracts_store resets to {}, and the next create_engineering_contract call generates a new contract. If repository snapshot or build_contract logic changed, the new contract will have different hash. The workflow's contract_sha256 (set via bind_artifact) will mismatch the new hash, breaking later gates.

GET /workflows/{workflow_id}/engineering-contract retrieves from contracts_store and recalculates the hash (lines 470-482). If stored_hash != recalculated_hash, raises HTTPException 500. This detects in-memory tampering but doesn't protect against restart-induced regeneration.

## Workflow state transition to BRIEF_READY with evidence

After binding the contract artifact (line 424), the route calls governance_service.transition_state with to_state=CanonicalWorkflowState.BRIEF_READY, triggered_by="W2-EngineeringContract", evidence_id=contract.contract_id (lines 428-437). The call is wrapped in try/except ValueError for idempotency — if the workflow is already in BRIEF_READY or later, transition_state raises ValueError and the except block passes silently.

## Artifact binding records contract_sha256 in workflow

After generating the contract and calculating its hash (line 421), the route calls governance_service.bind_artifact with artifact_type="contract", artifact_id=contract.contract_id, artifact_sha256=contract.contract_hash (lines 424-428). bind_artifact sets workflow.contract_id and workflow.contract_sha256. This SHA-256 is the immutability anchor: later gates verify candidate_binding.contract_hash matches workflow.contract_sha256. If contracts_store resets on restart and a new contract is generated with different hash, this gate will fail.
