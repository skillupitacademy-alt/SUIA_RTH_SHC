## Routing rule

Critical work changes authentication, authorization, tenant/local identity, private data
ownership, credentials, sensitive cache lifecycle, approval/certification authority,
scoring, schema/persistence keys, migrations, publication/storage validation, concurrency,
idempotency, event delivery or a shared contract that can change those invariants.
Terra owns those production corrections under the already selected policies.

Noncritical work is bounded presentation, truthful labels/empty/error/reference display,
documentation, finding enumeration and compatibility inventory where it does not change
trusted identity, persisted results, permissions or domain contracts. Sonnet owns it.
A helper or UI change is critical if its effect crosses a critical invariant. The file
extension or line count does not determine risk. Escalate a discovered boundary before
crossing it and continue an independent assigned item.

Gemini owns independent regression design, test changes and execution, adversarial
composition controls and test evidence. Implementers supply expected invariants and
may run existing local checks to avoid submitting broken code. They do not assign their
own independent verification. Gemini does not repair production code during testing.
Failing tests go back to the responsible implementation owner with exact reproduction.
Required assertions are not inverted to accept a defect. Test changes that alter an
acceptance contract need Sol disposition.

Sol selects architecture, resolves policy conflicts, reviews the submitted implementation
and Gemini evidence, coordinates integration and issues final task/group disposition.
Gemini PASS or a workflow reviewer APPROVED is not Sol acceptance.

## File ownership and concurrent workflows

Before writers launch, record item ID, owner, exact paths, branch/worktree, base revision,
dependencies and next consumer. Tera and Sonnet must not edit the same file concurrently.
If a shared file is required, the critical production owner edits it and Sonnet supplies
its requested display/documentation change as an explicit handoff. Whole-task ownership
does not authorize duplicate competing implementations.

Use separate worktrees/branches for genuinely independent concurrent writers. If that
isolation is unavailable, serialize all writes in the shared checkout. Read-only
investigation can proceed independently. No workflow changes branches or resets another
workflow's working directory. Run Gemini against an exact frozen submitted revision or
isolated review checkout. Record production source revision separately from test revision.

Gemini owns test files during independent testing. Implementation owners coordinate needed
fixture updates rather than racing Gemini's edits. The integration owner alone updates
the consolidated handoff/master ledger/execution plan after collecting role evidence.
Each worker writes its own scoped packet first. Sonnet compiles the proposed final ledger
when that integration window is assigned. Sol reviews its accuracy and integration.

Sol integrates reviewable commits sequentially and requires Gemini affected regression
checks after dependent integration. Never merge unverified snapshots solely because
individual branches have passing unit tests. No main merge, production deployment or
physical migration authority follows from this routing update.
