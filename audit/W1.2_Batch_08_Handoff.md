### Work Package 2 — B08-B: Mid-Session Account Lifecycle Transitions
- **Governing Architecture:** `audit/FinalAechitecture.md` § Tenant Learner Identity & Real-Time Lifecycle Checks (`W1.2-REFRESH-06`).
- **Target Suite:** `apps/api-server/src/modules/auth/__tests__/batch-08-lifecycle-transition.test.ts`.
- **Entry Points:** `LoginService.login`, `TokenRefreshService.refresh`, `UserRepository.findActiveUserWithRoles`.
- **Invariants Verified:**
  1. Positive control: Active learner session established and rotated; parent token consumed and revoked.
  2. Transition 1 (Blocked User): User marked `isBlocked: true` mid-session denies refresh with `access_denied:user_blocked`. Parent token remains unconsumed; zero child tokens persisted; foreign-tenant canary unmutated.
  3. Transition 2 (Soft-Deleted User): User marked `deletedAt != null` mid-session denies refresh with `Account has been deactivated`. Parent token unconsumed; zero child tokens; foreign canary unmutated.
  4. Transition 3 (Missing / Purged User): Deleted user record denies refresh fail-closed with `Invalid refresh token`. Parent unconsumed; zero child tokens; foreign canary unmutated.
  5. Transition 4 (Transient DB Outage): Database failure refuses refresh without consuming parent token, enabling safe client retry.
  6. Contrast Check: Proves stateless access token verification mathematically succeeds until expiration, confirming refresh token exchange is the real-time lifecycle enforcement boundary.
- **Observed Result:** 6 / 6 PASSED.

### Work Package 5 — B08-E: Legacy Tutorial Progress Subject & Tenant Binding
- **Governing Architecture:** `audit/FinalAechitecture.md` § Tenant Learner Identity & Gateway Exemption Boundaries.
- **Target Suite:** `apps/api-server/src/app/api/tutorial/progress/__tests__/batch-08-identity-binding.test.ts`.
- **Entry Points:** `GET` and `POST` in `apps/api-server/src/app/api/tutorial/progress/route.ts`.
- **Controls & Defect Reproduction:**
  1. Positive Control: Legitimate user with matching progress reads data -> 200 PASSED.
  2. Positive Control: Legitimate user updates block progress via POST -> 200 PASSED.
  3. Missing Identity Control: Request without `x-user-id` -> 401 PASSED.
  4. **SECURITY INVARIANT (DEFECT EXPOSED):** Unauthenticated request with forged `x-user-id: victim-uuid` must NOT access victim progress.
     - **Observed Result:** FAILED (`AssertionError: expected 200 to be 401`).
     - **Exploit Preconditions:** Attacker sends `GET /api/tutorial/progress?subtopicId=xxx` with header `x-user-id: <victim-id>`. Because `apps/api-server/src/proxy.ts` exempts `/api/tutorial` via `isGatewayExemptRoute`, no token verification occurs, and `route.ts` reads `request.headers.get('x-user-id')` directly.
     - **Smallest Bounded Correction Proposal:**
       1. In `apps/api-server/src/proxy.ts`: Remove `isTutorialRoute` from `isGatewayExemptRoute`.
       2. In `apps/api-server/src/app/api/tutorial/progress/route.ts`: Replace `extractUserId(request)` with `container.get(TokenService).getAccessToken(request, { scope: 'user' })` and `verifyUserAccessToken(token)`, reading `payload.userId`. Reject with 401 if token is absent/invalid.

### Work Package 6 — B08-F: Private Export Ownership & Tenant Isolation
- **Governing Architecture:** `audit/FinalAechitecture.md` § Tenant Isolation & Resource Ownership.
- **Target Suites:**
  - `apps/api-server/src/app/api/export/download/__tests__/batch-08-ownership.test.ts`
  - `apps/api-server/src/app/api/export/status/[jobId]/__tests__/batch-08-ownership.test.ts`
- **Entry Points:** `GET` in `export/download/route.ts`, `GET` in `export/status/[jobId]/route.ts`.
- **Download Route Invariants (`export/download`):**
  1. Authorized owner downloads completed export -> 200 PASSED.
  2. Non-owner user attempting download -> 403 Forbidden PASSED (`job.userId !== payload.userId`).
  3. Anonymous request -> 401 Unauthorized PASSED.
- **Status Route Invariants (`export/status/[jobId]`):**
  1. Authorized owner retrieves job status -> 200 PASSED.
  2. Anonymous request -> 401 Unauthorized PASSED.
  3. **SECURITY INVARIANT (DEFECT EXPOSED - IDOR):** Non-owner authenticated caller querying victim's `jobId` MUST receive 403 Forbidden.
     - **Observed Result:** FAILED (`AssertionError: expected 200 to be 403`).
     - **Exploit Preconditions:** Attacker with valid JWT session passes victim's `jobId` in path URL. The handler authenticates the attacker's token, but never checks `job.userId === payload.userId`. Attacker receives victim's job status and sensitive `downloadUrl`.
     - **Smallest Bounded Correction Proposal:**
       In `apps/api-server/src/app/api/export/status/[jobId]/route.ts`: After `JobsService.getJobStatus(jobId)`, add:
       ```ts
       if (job && !isInternal && job.userId !== userId) {
         return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
       }
       ```
