## 3. Minimal Runtime Correction Proposals for Unpatched Defects

### Defect 1: Proxy Anti-Downshift on Bad Internal Key (`apps/api-server/src/proxy.ts`)
- **Current Behavior:** Line 102 checks `isValidInternalKey = internalKey !== null && internalKey === process.env.INTERNAL_API_KEY`. When `internalKey` is invalid, `isSystemBypass` is `false`, and proxy falls through to user token verification, returning 200.
- **Minimal Correction Proposal:**
  In `apps/api-server/src/proxy.ts` lines 99–106:
  ```ts
  const internalKey = request.headers.get('x-internal-key');
  if (internalKey !== null) {
    const internalSecret = process.env.INTERNAL_API_KEY;
    if (!internalSecret || internalKey !== internalSecret) {
      const response = NextResponse.json(
        { error: 'Forbidden: Invalid internal key' },
        { status: 403 }
      );
      response.headers.set('x-request-id', requestId);
      return corsMiddleware(request, response);
    }
  }
  ```
  This immediately denies invalid internal key presentations with HTTP 403 Forbidden without downshifting.

### Defect 2: Foreign-Brand Colliding ID on Export Download (`apps/api-server/src/app/api/export/download/route.ts`)
- **Current Behavior:** Lines 53 and 76 check `job.userId !== payload.userId` and `exam.userId !== payload.userId`, but do not verify tenant brand context. A user with colliding local ID on a foreign brand can download the victim's export artifact.
- **Minimal Correction Proposal:**
  In `apps/api-server/src/app/api/export/download/route.ts`:
  1. For jobs: Verify `job.brand === payload.brand`. If `job.brand` column is missing, migrate `jobs` schema to include `brand: varchar(32)` or enforce globally unique UUIDs.
  2. For exams: Bind exam query to tenant DB via `getAuthBrandContext(payload.brand)`.
