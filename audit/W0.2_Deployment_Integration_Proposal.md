# W0.2 Deployment Integration Proposal

**Authority Required**: Sol (Principal Architect)  
**Scope**: Editing deployment script (NOT executing deployment)  
**Target Script**: `scripts/deploy-smart.ps1`  
**Current Entrypoint**: `.\scripts\deploy-smart.ps1 -Services "..." -SkipChecks -NoCache`

---

## Current Deployment Path (from W0.2_Deployment_Path_Investigation.md)

1. **Step 1-2**: Environment preparation, VPS connection validation
2. **Step 3**: ESLint (bypassed by `-SkipChecks`)
3. **Step 4**: TypeScript check (bypassed by `-SkipChecks`)
4. **Step 5**: Docker image build via `build-save-images.ps1`
   - Calls `docker build` for each service
   - Creates `manifest.json` with `gitCommit`, `buildTimestamp`, `services`
5. **Step 6-8**: Image transfer to VPS, deployment via Docker Compose

**Key Finding**: `-SkipChecks` bypasses lint/typecheck but also bypasses ALL quality gates, including architecture guards, security tests, and unit tests that are NOT in the current script.

---

## Problem Statement

**Quality-Artifact Binding Gap**:
- Quality gates run against working directory source
- Docker images built from same source (in theory)
- BUT: No enforcement that tested source = built artifact
- Pre-built images deployed to VPS have NO quality evidence binding

**Current Risks**:
1. Developer can bypass ALL quality checks with `-SkipChecks`
2. No guarantee that quality-tested code matches deployed image
3. Mixed services (e.g., `skillhubcore-admin` + `rthtutorial-web`) have no aggregate quality validation
4. `manifest.json` records `gitCommit` but NOT quality gate results

---

## Proposed Integration Design

### Option A: Minimal Pre-Build Enforcement (RECOMMENDED)

**Insertion Point**: Between Step 4 and Step 5 (before Docker build)

**Pseudocode**:
```powershell
# Step 4.5: Quality Gates (REQUIRED before build)
Write-Host "`nStep 4.5: Running quality gates..." -ForegroundColor Cyan

if (-not $SkipChecks) {
    # Run quality gates for each service being deployed
    $servicesToCheck = @()
    
    if ($Services -match "skillhubcore-admin") {
        Write-Host "  Quality check: skillhubcore-admin" -ForegroundColor Gray
        & pnpm quality:skillhubcore
        if ($LASTEXITCODE -ne 0) {
            Write-Error "skillhubcore-admin quality gates failed (exit $LASTEXITCODE)"
            Write-Error "  1=architecture, 2=security, 3=lint, 4=typecheck, 5=test, 6=build"
            exit $LASTEXITCODE
        }
        $servicesToCheck += "skillhubcore-admin"
    }
    
    # Future: Add other service quality gates as they're implemented
    # if ($Services -match "rthtutorial-web") { ... }
    
    Write-Host "  ✅ All quality gates passed for: $($servicesToCheck -join ', ')" -ForegroundColor Green
    
    # Record quality evidence in manifest
    $qualityEvidence = @{
        timestamp = (Get-Date -Format "yyyy-MM-ddTHH:mm:ssZ")
        gatesPassed = $true
        services = $servicesToCheck
        baseline = @{
            directDBRoutes = 26
            commit = (git rev-parse HEAD)
        }
    }
    
    # Will be merged into manifest.json during Step 5
    $script:QualityEvidence = $qualityEvidence
    
} else {
    Write-Warning "  ⚠️  Quality gates SKIPPED (-SkipChecks flag)"
    Write-Warning "     Deployment proceeds WITHOUT quality verification"
    $script:QualityEvidence = @{
        gatesPassed = $false
        reason = "Skipped by -SkipChecks flag"
    }
}
```

**Manifest Enhancement** (in `build-save-images.ps1`):
```powershell
$manifest = @{
    buildTimestamp = (Get-Date -Format "yyyy-MM-ddTHH:mm:ssZ")
    gitCommit = (git rev-parse HEAD)
    services = $services
    quality = $script:QualityEvidence  # NEW: Quality gate evidence
}
```

**Example Enhanced Manifest**:
```json
{
  "buildTimestamp": "2026-11-02T00:45:00Z",
  "gitCommit": "b035aceac448c504ed676dd9b87ab88ff8afa06d",
  "services": ["skillhubcore-admin", "gateway"],
  "quality": {
    "timestamp": "2026-11-02T00:44:30Z",
    "gatesPassed": true,
    "services": ["skillhubcore-admin"],
    "baseline": {
      "directDBRoutes": 26,
      "commit": "b035aceac448c504ed676dd9b87ab88ff8afa06d"
    }
  }
}
```

### Option B: Separate Pre-Deploy Validation Script

**Alternative**: Create `scripts/validate-deployment-readiness.ps1` that:
1. Runs quality gates for requested services
2. Creates quality evidence file
3. `deploy-smart.ps1` checks for evidence file before proceeding

**Trade-offs**:
- Pro: Cleaner separation of concerns
- Pro: Easier to test quality validation independently
- Con: Two-step deployment process
- Con: Evidence file can become stale

## Mixed Service Handling

**Current Challenge**: Deploying multiple services (e.g., `skillhubcore-admin` + `gateway`) requires running quality gates for each.

**Proposed Solution**:
- Parse `-Services` parameter
- Run quality gate for EACH service that has one implemented
- Aggregate results before proceeding to build
- Record per-service quality evidence in manifest

**Fail-Fast Policy**:
- ANY service quality gate failure → ABORT deployment
- Exit with service-specific error code

**Example**:
```powershell
$Services -split ',' | ForEach-Object {
    $service = $_.Trim()
    switch ($service) {
        "skillhubcore-admin" {
            & pnpm quality:skillhubcore
            if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
        }
        # Future services...
    }
}
```

## SkipChecks Behavior

**Current Behavior**: Bypasses lint + typecheck (Steps 3-4)

**Proposed Behavior** (Option A):
- `-SkipChecks` STILL bypasses Steps 3-4 (lint/typecheck only)
- Step 4.5 (quality gates) runs UNLESS `-SkipChecks`
- Records `gatesPassed: false, reason: "Skipped"` in manifest

**Rationale**:
- Maintains backward compatibility
- Makes `-SkipChecks` bypass MORE obvious (quality evidence shows skip)
- Allows emergency deployment with explicit evidence of bypass

**Alternative Strict Behavior**:
- Rename `-SkipChecks` to `-SkipLintTypecheck`
- Add new `-SkipQualityGates` (requires explicit opt-in)
- Require `-Force` for deployment without quality gates

## Tested-Source / Artifact Binding

**Challenge**: How to ensure quality-tested source = Docker image source?

**Solution 1: Git Commit Matching**
```powershell
# Step 4.5
$qualityCommit = (git rev-parse HEAD)

# Step 5 (in build-save-images.ps1)
$buildCommit = (git rev-parse HEAD)

if ($qualityCommit -ne $buildCommit) {
    Write-Error "Quality gates tested $qualityCommit but building $buildCommit"
    Write-Error "Source changed between quality check and build. Re-run deployment."
    exit 1
}
```

**Solution 2: Quality Evidence as Build Arg**
```powershell
# Pass quality evidence hash to Docker build
$evidenceHash = (ConvertTo-Json $qualityEvidence | Get-FileHash -Algorithm SHA256).Hash
docker build --build-arg QUALITY_EVIDENCE_HASH=$evidenceHash ...
```

**Solution 3: Lock File**
```powershell
# Step 4.5: Create lock file
$lockFile = "quality-lock.json"
@{
    commit = (git rev-parse HEAD)
    timestamp = (Get-Date)
    evidence = $qualityEvidence
} | ConvertTo-Json | Set-Content $lockFile

# Step 5: Validate lock file
$lock = Get-Content $lockFile | ConvertFrom-Json
if ($lock.commit -ne (git rev-parse HEAD)) {
    Write-Error "Source changed after quality check"
    exit 1
}
```

---

## Rollback and Recovery

**If Quality Gate Fails During Deployment**:
1. Deployment aborts before image build (no partial deployment)
2. Previous deployment remains active
3. Developer fixes issue, re-runs quality gates locally
4. Re-attempts deployment with clean quality evidence

**Emergency Bypass**:
- Use `-SkipChecks` for emergency hotfix
- Manifest records `gatesPassed: false, reason: "Emergency bypass"`
- Follow-up ticket to verify quality post-deployment

## Evidence Tracking

**Three Evidence Layers** (per W0.2 Scope Revision):

1. **Repository Evidence**: Quality gate results (THIS PROPOSAL)
   - `pnpm quality:skillhubcore` exit code
   - Stage-by-stage results
   - Baseline compliance

2. **Deployment Evidence**: Manifest + lock file
   - Quality evidence bound to commit
   - Timestamp of quality check
   - Services validated

3. **Runtime Evidence**: NOT IN SCOPE (future)
   - Health checks
   - Authorization tests
   - Data isolation tests

## Recommended Decision

**Adopt Option A (Minimal Pre-Build Enforcement)** with:
- Step 4.5 integration in `deploy-smart.ps1`
- Manifest enhancement with quality evidence
- Git commit matching for tested-source binding
- Phased rollout (SkillHubCore Admin first)

**Rationale**:
- Minimal script changes
- Clear failure point (before Docker build)
- Backward-compatible with `-SkipChecks`
- Evidence preserved in deployment artifact (manifest.json)
- Extensible to multi-service deployments
