### Gap #3: Freshness accepts future receipts (FULLY FIXED)

**Sol's Finding**: "Builder rejects age >60 minutes but accepts arbitrary future completion times (negative age). Reject future or invalid timing with an explicit bounded clock-skew policy."

**Correction**: build-save-images.ps1 lines 340-352

**Implementation**:
```powershell
# Freshness check with bounded clock-skew policy:
# - Accept receipts up to 60 minutes old
# - Reject future-dated receipts (allow max 5 minutes clock skew)
# - Reject invalid/unparseable timing
$ageMinutes = ($now - $completionTime).TotalMinutes

# Reject future receipts beyond allowed clock skew
if ($ageMinutes -lt -5) {
    throw "Evidence has future completion time (appears $([Math]::Round(-$ageMinutes, 1)) minutes in the future, max clock skew: 5 minutes). Check system clocks or reject tampered evidence."
}

# Reject stale receipts
if ($ageMinutes -gt 60) {
    throw "Evidence is too old (completed $([Math]::Round($ageMinutes, 1)) minutes ago, max age: 60 minutes). Run deployment orchestrator or quality gate helper to create fresh evidence."
}
```

**Bounded Clock-Skew Policy**:
- **Max future**: 5 minutes (allows reasonable clock drift)
- **Max age**: 60 minutes (prevents stale receipt reuse)
- **Invalid timing**: Caught by try/catch, fails closed

**Before** (lines 343-346):
```powershell
$ageMinutes = ($now - $completionTime).TotalMinutes
if ($ageMinutes -gt 60) {
    throw "Evidence is too old"
}
# MISSING: No check for negative age (future receipts)
```

**After** (lines 340-352):
- Explicit future check: `if ($ageMinutes -lt -5)`
- Clear error messages for both future and stale
- Applied at both build time AND publication time

**Evidence**: Receipts with completion time >5min in future are rejected with explicit error.

**Test**: Scenario #7 in production path tests validates future receipt rejection

**Status**: FULLY FIXED

### Gap #4: Invalidation doesn't precede every Git failure (FULLY FIXED)

**Sol's Finding**: "The helper performs rev-parse --git-dir before removing old success. A Git failure at that point leaves previous evidence."

**Correction**: enforce-shc-quality-gate.ps1 lines 10-51

**Implementation**:

**Before** (incorrect order):
```powershell
# 1. Filesystem checks
if (-not (Test-Path $RepositoryRoot)) { exit 1 }

# 2. Git validation (CAN FAIL HERE)
$gitDir = git -C $RepositoryRoot rev-parse --git-dir
if ($LASTEXITCODE -ne 0) { exit 1 }

# 3. Invalidation (TOO LATE)
if (Test-Path $evidencePath) {
    Remove-Item -Force $evidencePath
}
```

**After** (correct order, lines 10-51):
```powershell
# 1. Filesystem checks ONLY (no Git)
if (-not (Test-Path $RepositoryRoot)) {
    Write-Err "Repository root does not exist"
    exit 1
}

if (-not (Test-Path $EvidenceDir)) {
    New-Item -ItemType Directory -Force -Path $EvidenceDir | Out-Null
}

# 2. INVALIDATE BEFORE ANY GIT OPERATIONS
$evidencePath = Join-Path $EvidenceDir "quality-gate-skillhubcore-admin-$ImageTag.json"
if (Test-Path $evidencePath) {
    Write-Info "Invalidating previous evidence before gate attempt"
    try {
        Remove-Item -Force $evidencePath
        Write-Info "Previous evidence invalidated"
    } catch {
        Write-Err "Cannot invalidate previous evidence: $_"
        exit 1
    }
}

# 3. NOW validate git repository (after invalidation)
Write-Info "Validating git repository..."
try {
    $gitDir = git -C $RepositoryRoot rev-parse --git-dir 2>&1
    if ($LASTEXITCODE -ne 0) {
        Write-Err "Not a git repository: $RepositoryRoot"
        exit 1
    }
}
```

**Key Changes**:
- Invalidation moved to lines 25-46 (BEFORE git validation)
- Git validation moved to lines 48-58 (AFTER invalidation)
- Only filesystem/path checks before invalidation
- ALL Git operations (including rev-parse --git-dir) after invalidation

**Evidence**: No Git failure can leave reusable old success. Invalidation is first operation after filesystem checks.

**Test**: Scenario #4 in production path tests validates Git failure leaves no evidence

**Status**: FULLY FIXED
