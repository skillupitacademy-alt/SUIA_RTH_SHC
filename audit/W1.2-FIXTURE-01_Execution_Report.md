## 1. Executive Summary

This report documents the design, execution, and verification of **FIXTURE-01**, testing the identity and session boundary between the two independent learner tenants—SkillUp IT Academy (`skillup`) and RealTutorialHub (`realtutorialhub`).

The test suite constructs two independent in-memory tenant database adapters with:
1. **Identical synthetic email:** `learner@example.test` on both SUIA and RTH.
2. **Colliding local user ID:** `'100'` on both SUIA and RTH.
3. **Distinct synthetic passwords:** `Password-SUIA-Secret!1` vs `Password-RTH-Secret!2`.
4. **Distinct profile markers:** `SUIA Learner Profile` vs `RTH Learner Profile`.
5. **Separate in-memory session arrays:** `suiaStore.sessions` and `rthStore.sessions`.

All 7 required controls were executed against the actual `LoginService.login` engine, real `PasswordService` (bcryptjs), and real `TokenService`. **All 7 tests passed cleanly.**

## 3. Detailed Results by Invariant Control

### Control 1: SUIA Positive Control
- **Input:** `brand: 'skillup'`, `email: 'learner@example.test'`, `password: 'Password-SUIA-Secret!1'`.
- **Observed:**
  - Resolved `_user.id === '100'`.
  - Resolved profile name: `SUIA Learner Profile`.
  - Stored 1 session record in `suiaStore.sessions` with `userId: '100'` and `deviceId: 'dev-suia-1'`.
  - `rthStore.sessions.length` remained strictly `0`.
- **Status:** **`PASSED`**.

### Control 2: RTH Positive Control
- **Input:** `brand: 'realtutorialhub'`, `email: 'learner@example.test'`, `password: 'Password-RTH-Secret!2'`.
- **Observed:**
  - Resolved `_user.id === '100'`.
  - Resolved profile name: `RTH Learner Profile`.
  - Stored 1 session record in `rthStore.sessions` with `userId: '100'` and `deviceId: 'dev-rth-1'`.
  - `suiaStore.sessions.length` remained strictly `0`.
- **Status:** **`PASSED`**.

### Control 3: Cross-Tenant Password Rejection (SUIA with RTH Password)
- **Input:** `brand: 'skillup'`, `email: 'learner@example.test'`, `password: 'Password-RTH-Secret!2'`.
- **Observed:**
  - `LoginService.login` compared the candidate password against the SUIA bcrypt hash.
  - Threw `Error: Invalid credentials`.
  - `suiaStore.sessions.length === 0`; `rthStore.sessions.length === 0`.
- **Status:** **`PASSED`**.

### Control 4: Cross-Tenant Password Rejection (RTH with SUIA Password)
- **Input:** `brand: 'realtutorialhub'`, `email: 'learner@example.test'`, `password: 'Password-SUIA-Secret!1'`.
- **Observed:**
  - `LoginService.login` compared the candidate password against the RTH bcrypt hash.
  - Threw `Error: Invalid credentials`.
  - `suiaStore.sessions.length === 0`; `rthStore.sessions.length === 0`.
- **Status:** **`PASSED`**.

### Control 5: Denied Attempts Create No Sessions
- **Input:** Unknown email `unknown@example.test` on `skillup`.
- **Observed:**
  - Rejection throws `Invalid credentials`.
  - Zero session records were persisted to either store.
- **Status:** **`PASSED`**.

### Control 6: Store Isolation under Sequential Writes
- **Action:**
  - Executed two consecutive logins on SUIA for device `suia-d1` and `suia-d2`.
  - Asserted `suiaStore.sessions.length === 2`, `rthStore.sessions.length === 0`.
  - Executed one login on RTH for device `rth-d1`.
  - Asserted `suiaStore.sessions.length === 2`, `rthStore.sessions.length === 1`.
  - Verified prefix segregation: all SUIA session IDs start with `sess-skillup`, all RTH session IDs start with `sess-realtutorialhub`.
- **Status:** **`PASSED`**.

### Control 7: Fixture Sensitivity Check
- **Action:**
  - Programmatically inverted the brand context resolver: requesting `skillup` routed to the `rthStore`.
  - Invoked `loginService.login` for `skillup` with `Password-SUIA-Secret!1`.
- **Observed:**
  - The attempt failed fail-closed with `Error: Invalid credentials` because the RTH store holds the RTH hash.
  - Proves that the fixture detects wrong-store binding and does not pass trivially.
- **Status:** **`PASSED`**.

   - Passing FIXTURE-01 proves that `LoginService` and its tenant repository wiring correctly segregate identical emails and colliding user IDs at the application logic layer.
   - It does **not** prove physical PostgreSQL schema isolation or connection pooling isolation on deployed databases.
2. **Does Not Close Browser Scenario AQ-08:**
   - AQ-08 requires live browser GUI login journeys with real dual-tenant accounts in a Playwright Chromium harness. That remains unexecuted and separately gated.
