## 2. Root Cause Analysis & Solution Architecture

### 2.1 Same-Second Refresh Collision Defect
- **Root Cause**: `generateRefreshToken` invoked `new SignJWT(...)` without a `jti` (JWT ID) claim. When multiple tokens were generated for the same user with identical options within the same unix second, `SignJWT` generated identical JWT strings and identical SHA-256 hashes, violating the `refresh_tokens_token_unique` database constraint.
- **Remediation**: Added `.setJti(globalThis.crypto.randomUUID())` to `generateRefreshToken` in [`packages/auth/src/token.service.ts:329`](file:///E:/onlinewebsites/quiz-platform/packages/auth/src/token.service.ts#L329). Verified backward compatibility: legacy refresh tokens without `jti` continue to verify cleanly.

### 2.2 Concurrency Race & Token Branching Defect
- **Root Cause**: Pre-fix `TokenRefreshService.refresh` executed `findByHash` outside the database transaction. Inside the transaction, it called `tokenRepo.revokeToken`, which was an unconditional `UPDATE refresh_tokens SET revoked = true WHERE token = $1` with no active check (`revoked = false`), no expiration check, and no row count verification. Two concurrent HTTP requests reading the active parent concurrently both succeeded and inserted two valid successor tokens.
- **Remediation**:
  1. Implemented `consumeToken(tokenHash: string, expectedUserId: string)` in [`TokenRepository`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/repositories/token.repository.ts#L67-L95):
     ```typescript
     const result = await this.dbInstance.update(this.refreshTokensTable)
       .set({ revoked: true, lastUsedAt: now })
       .where(and(
         eq(this.refreshTokensTable.token, tokenHash),
         eq(this.refreshTokensTable.userId, expectedUserId),
         eq(this.refreshTokensTable.revoked, false),
         gt(this.refreshTokensTable.expiresAt, now)
       ))
       .returning();
     if (Array.isArray(result) && result.length === 1) {
       return result[0] as RefreshTokenRow;
     }
     return null;
     ```
  2. Updated [`TokenRefreshService.refresh`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/token-refresh.service.ts#L175-L183) inside the brand database transaction:
     ```typescript
     const consumedParent = await txTokenRepo.consumeToken(oldTokenHash, userId);
     if (!consumedParent) {
       throw new Error('Refresh token has been revoked or already consumed');
     }
     await txTokenRepo.createRefreshToken({ ... });
     ```
  3. If another request consumed the token first, the CAS condition `eq(revoked, false)` returns 0 rows (`result.length === 0`), causing `consumeToken` to return `null`. The transaction throws, rolling back any successor creation.

Proved that stripping the CAS predicates from production source allows concurrent race branching, while post-fix code enforces a single winner.
- **B5 (Repaired Stale Mock in Blocked Branch Test)**: In `auth.refresh.blocked.branch.test.ts`, updated `mockTokenRepo` to supply `updateLastUsed`, `consumeToken`, `createRefreshToken`, and `withDb`. The test now executes fully and fails with `AssertionError: promise resolved instead of rejecting 'access_denied:user_blocked'`, documenting the exact pre-existing architectural limitation without throwing a mock error.

Documented that in test environments, `brandBinding` is disabled by default to permit lightweight testing against the mock DB.
