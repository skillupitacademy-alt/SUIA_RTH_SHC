## 5. Root Cause Analysis: Cookie Non-Clearance Discrepancy

Inspection of the response pipeline revealed the exact defect in [`apps/skillup-web/src/app/api/auth/logout/route.ts`](file:///E:/onlinewebsites/quiz-platform/apps/skillup-web/src/app/api/auth/logout/route.ts):

1. **Stripping Backend `Set-Cookie`**:
   In `apps/skillup-web/src/app/api/auth/logout/route.ts` lines 21-25:
   ```typescript
   backendResponse.headers.forEach((value, key) => {
     if (key.toLowerCase() !== 'set-cookie') {
       response.headers.set(key, value);
     }
   });
   ```
   The BFF explicitly strips all `Set-Cookie` headers returned by the upstream API server (which carried the proper domain-scoped cookie clearing instructions).

2. **Missing `Domain` in BFF `clearCookie`**:
   In `apps/skillup-web/src/app/api/auth/logout/route.ts` lines 28-36:
   ```typescript
   const clearCookie = (name: string) => {
     response.cookies.set(name, '', {
       httpOnly: true,
       secure: true,
       sameSite: 'none',
       maxAge: 0,
       path: '/',
     });
   };
   ```
   During login, cookies are established with `Domain=.skillup.localhost`.
   However, the BFF's `clearCookie` helper omits the `domain` option, issuing a host-only clearing instruction (`Set-Cookie: accessToken=; Max-Age=0; Path=/`). Under RFC 6265, a host-only `Set-Cookie` cannot clear a domain-scoped cookie (`.skillup.localhost`). Consequently, Chromium retains the original domain cookie in the browser context after logout.

Per Sol's governing instructions ("*do not change runtime code*", "*report the discrepancy rather than modifying the expected result merely to pass*"), runtime code was **not** altered. The test asserts correct security behavior (cookies must be absent), and the failure documents an actual runtime defect for remediation.
