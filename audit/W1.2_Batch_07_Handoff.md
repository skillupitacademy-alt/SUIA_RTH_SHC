### 2.1 Task A + B: `W1.2-ADMIN-01` (Strict Tenant-Admin Helper & Proxy Routing)
- **Commit:** `a7d59877`
- **Files Modified:**
  - [`apps/api-server/src/modules/auth/rbac.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/rbac.service.ts)
  - [`apps/api-server/src/proxy.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/proxy.ts)
  - [`apps/api-server/src/modules/auth/admin-audience.util.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/admin-audience.util.ts)
  - [`apps/api-server/src/modules/auth/__tests__/rbac.service.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/rbac.service.test.ts)
- **Implemented Contracts:**
  1. `_verifyActiveAccount(userId, brand)`: Shared non-privileged account eligibility validator ensuring tenant brand is canonical (`'skillup' | 'realtutorialhub'`), subject is non-empty, and account exists and is unblocked in the tenant database. Fails closed on DB errors.
  2. `_verifyAdmin(_payload)`: Strict preconditions executed before any database query:
     - Canonical tenant brand (`brand === 'skillup' || brand === 'realtutorialhub'`).
     - Non-empty tenant-local subject (`typeof userId === 'string' && userId.trim().length > 0`).
     - Runtime admin class consistency (`tokenType === 'admin' && isAdmin === true`).
     - Admin audience requirement: scalar `'admin'` or array containing `'admin'` (e.g. `['admin', 'internal']`). Arrays containing `'internal'` alone are rejected. Arrays containing foreign audiences (`'user'`, `'infra'`, `'shc-admin'`) are rejected.
     - Obsolete role-fallback is removed: principals failing class/audience preconditions are never elevated by database role queries.
  3. `proxy.ts`:
     - SHC Admin on tenant analytics (`/api/analytics/admin`) is explicitly denied (HTTP 403) before tenant database lookup.
     - Infra factory/analytics requests are routed through their separate permission contract (`ADMIN_PANEL`), retaining the tenant missing/blocked-account check via `_verifyActiveAccount`.
     - Preserves existing `/api/admin` infra behavior without extending tenant lookups to unrelated machine identities.
     - Preserves missing-header path-based admin compatibility and signed-claim authority.

### 2.2 Task C: `W1.2-LOGIN-01` (Server-Fixed Tenant Learner Purpose)
- **Commits:** `b967e6be`, `1fe36579`
- **Files Modified:**
  - [`apps/api-server/src/modules/auth/login.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/login.service.ts)
  - [`apps/api-server/src/modules/auth/auth.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/auth.service.ts)
  - [`apps/api-server/src/app/api/auth/login/route.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/app/api/auth/login/route.ts)
  - [`apps/api-server/src/app/api/auth/signup/route.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/app/api/auth/signup/route.ts)
  - [`apps/api-server/src/modules/auth/__tests__/login-01-purpose.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/login-01-purpose.test.ts)
- **Implemented Contracts:**
  1. Server-fixed learner purpose: Public learner ingress (`POST /api/auth/login` and `POST /api/auth/signup`) supplies `options: { purpose: 'learner' }`. Client-supplied body or headers cannot request admin issuance.
  2. Signature preservation: Preserves 5th positional `deviceContext` and 3rd `ip` precedence; adds 6th `options?: LoginOptions`. Facade in `AuthService` cleanly forwards options.
  3. Empty-role baseline without manufactured roles: When an account holding admin roles logs into learner ingress under `purpose: 'learner'`, administrative roles (`'admin'`, `'super_admin'`, `'infrastructure'`) are stripped. If no legitimate learner roles remain in the DB, the token issues with `roles: []`. The backend never synthesizes a `'student'` role.
  4. Cryptographic claims: Minted tokens enforce `aud: 'user'`, `tokenType: 'user'`, `isAdmin: false`. Admin verifiers reject these tokens.
  5. Persistence invariant: PostgreSQL `refresh_tokens` persists only current owner, hash, tenant, and device fields (`deviceId`, `ipAddress`, `userAgent`, `deviceName`). No new `tokenType` or `isAdmin` columns or migrations are introduced.
  6. Standard learner cookies written: `setAuthCookies` writes learner cookies (`accessToken`, `refreshToken`).
  7. Error handling: `InvalidPurposeError` is mapped to HTTP 400 Bad Request in route handlers.

### 2.3 Task D: `W1.2-SESS-04` (Legacy Logout-All Compatibility Adapter)
- **Commit:** `c1f10081`
- **Files Modified:**
  - [`apps/api-server/src/app/api/auth/logout-all/route.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/app/api/auth/logout-all/route.ts)
  - [`apps/api-server/src/modules/auth/global-logout.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/global-logout.service.ts)
  - [`apps/api-server/src/modules/auth/__tests__/sess-04-logout-all.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/sess-04-logout-all.test.ts)
- **Implemented Contracts:**
  1. Complete removal of broken unbound `SessionService`: `authMiddleware` and `SessionService` are replaced by a thin adapter delegating directly to `GlobalLogoutService.logoutAllDevices`.
  2. Verified tenant credentials & brand parity: Extracts token with credential precedence (Bearer / cookies); enforces verified `user` or `admin` class (excludes `infra` and `shc-admin`); enforces canonical tenant brand (`'skillup' | 'realtutorialhub'`); enforces canonical request/token brand parity via `validateBrandOrThrow`.
  3. Pre-operation snapshot count: Queries `getActiveSessions(userId, tenantBrand)` before revocation. A failure here is the only guaranteed pre-commit failure (HTTP 500 `{"error":"Unable to inspect sessions; revocation not attempted"}`).
  4. Typed stage error attribution:
     - `RevocationStageError`: Thrown if `brandTokenRepo.revokeAll(userId)` fails. Route maps to HTTP 500 `{"error":"Session revocation outcome unknown; retry with valid credentials"}`.
     - `PresenceStageError`: Thrown if `brandUserRepo.updateLastActive(...)` fails after `revokeAll` succeeded. Route maps to HTTP 500 `{"error":"Sessions revoked; presence update could not be confirmed"}`.
     - Neither error leaks SQL, driver details, or token hashes.
  5. Audit log failure absorption: `AuditService.log` internally catches and logs insertion failures, retaining HTTP 200 success behavior without manufacturing an audit-success flag.
  6. Legacy success JSON: Returns `{ message: 'Logged out from all devices successfully', revokedSessions: sessionCount, timestamp }`. Zero new Set-Cookie headers.
  7. Offline safety constraint: Strictly tested offline with mocks and synthetic tokens. Zero live Neon calls.
