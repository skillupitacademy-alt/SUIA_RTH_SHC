  - [`apps/api-server/src/modules/auth/__tests__/admin-01-proxy.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/admin-01-proxy.test.ts)
- **Implemented & Verified Contracts:**
  1. `_verifyActiveAccount(userId, brand)`: Shared non-privileged account eligibility validator ensuring tenant brand is canonical (`'skillup' | 'realtutorialhub'`), subject is non-empty, and account exists and is unblocked in the tenant database. Fails closed on DB errors.
  2. `_verifyAdmin(_payload)`: Strict preconditions executed before any database query:
     - Canonical tenant brand (`brand === 'skillup' || brand === 'realtutorialhub'`).
     - Non-empty tenant-local subject (`typeof userId === 'string' && userId.trim().length > 0`).
     - Runtime admin class consistency (`tokenType === 'admin' && isAdmin === true`).
     - Admin audience requirement: scalar `'admin'` or array containing `'admin'` (e.g. `['admin', 'internal']`). Arrays containing `'internal'` alone are rejected. Arrays containing foreign audiences (`'user'`, `'infra'`, `'shc-admin'`) are rejected.
     - Obsolete role-fallback is removed: principals failing class/audience preconditions are never elevated by database role queries.
  3. `proxy.ts` Routing & Route-Guard Matrix:
     - SHC Admin on tenant analytics (`/api/analytics/admin`) is explicitly denied (HTTP 403) before tenant database lookup.
     - SHC Admin on `/api/admin` is permitted for SkillHubCore governance without tenant lookup.
     - Infra factory/analytics requests are routed through their separate permission contract (`ADMIN_PANEL`), retaining the tenant missing/blocked-account check via `_verifyActiveAccount`.
     - Preserves existing `/api/admin` infra behavior without extending tenant lookups to unrelated machine identities.
     - Preserves missing-header path-based admin compatibility and signed-claim authority.
     - Covered by 10/10 tests in `admin-01-proxy.test.ts` executing actual `proxy()` and `requireAdminRouteAccess` with disposable-key-signed tokens.

- **Files Modified:**
  - [`apps/api-server/src/modules/auth/login.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/login.service.ts)
  - [`apps/api-server/src/modules/auth/auth.service.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/auth.service.ts)

  - [`apps/api-server/src/app/api/auth/signup/route.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/app/api/auth/signup/route.ts)
  - [`apps/api-server/src/modules/auth/__tests__/login-01-purpose.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/login-01-purpose.test.ts)
- **Implemented & Verified Contracts:**
  1. Fail-fast purpose validation: Unsupported options (e.g. `options?.purpose !== 'learner'`) fail immediately with `InvalidPurposeError` at the very entry of `login()`, before database lookups, password hashing/comparison, or audit logging.
  2. Scoped tenant ingress: Server-fixed learner purpose is strictly applied when `brand` is a canonical tenant (`'skillup' | 'realtutorialhub'`). In `login/route.ts`, `{ purpose: 'learner' }` is passed only for canonical tenant brands, passing `undefined` for `skillhubcore`.
  3. Generic `skillhubcore` preservation: Login under generic `skillhubcore` brand retains default-DB admin detection behavior without learner role-stripping.
  4. Empty-role baseline without manufactured roles: For tenant logins under `purpose: 'learner'`, administrative roles (`'admin'`, `'super_admin'`, `'infrastructure'`) are stripped. If no legitimate learner roles remain in the DB, the token issues with `roles: []`. The backend never synthesizes a `'student'` role.
  5. Cryptographic claims: Minted tokens enforce `aud: 'user'`, `tokenType: 'user'`, `isAdmin: false`. Admin verifiers reject these tokens.
  6. Explicit disposable keys: Test suite exercises actual cryptographic issuance and verification with both distinct-key and shared-key configurations; zero reliance on ambient secrets.

- **Implemented & Verified Contracts:**
  1. Audience & class boundaries: Helper `isTenantAudienceValid(tokenType, aud)` strictly rejects excluded audiences (`'infra'`, `'shc-admin'`) and invalid scalar/array audiences, even when `tokenType === 'admin'`.
  2. Cookie-authenticated mutation origin/CSRF enforcement: When authenticated via cookies (`accessToken` or `admin_accessToken`), the handler enforces exact parsed origin comparison against approved origins (`localhost:3000..3003`, `skillup.test`, `realtutorialhub.test`, and request host). Rejects foreign origin, missing origin, and deceptive substring host spoofing (e.g. `http://skillup.test.attacker.com`).
  3. Fail-fast Bearer authorization: Non-browser clients using Bearer tokens are exempt from browser Origin checks. If an invalid or unparseable Bearer header is present, it fails fast with HTTP 401 and never falls through to ambient cookies.
  4. Stateful `GlobalLogoutService` engine proof:
     - Real in-memory repository tests covering colliding user IDs across SUIA and RTH.
     - Stage failure generation: `PresenceStageError` (revocation committed then presence fails), `RevocationStageError` (revocation fails), and pre-operation inspection failure.
     - Audit log error absorption: database error during audit logging is caught and does not fail the revocation response.
     - Idempotent retry: subsequent calls confirm 0 remaining active sessions without altering another tenant or un-revoking tokens.
  5. Zero live Neon execution: All tests executed entirely in-memory with disposable signing keys.
