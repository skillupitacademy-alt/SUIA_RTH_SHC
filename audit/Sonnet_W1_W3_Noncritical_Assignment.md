## Scope and escalation

Before editing any file, record its owner and exact bounds. Shared files such as
skillup-data.ts, shared type modules, provider lifecycle, schema and API handlers belong
to the critical production owner. Request the required change in Tera's handoff instead
of editing the same file. A misleading financial/assessment/identity value may require
a domain contract fix, even if it is displayed in a simple component. Notify Tera/Sol
and continue an independent assigned item.

Use existing views and components, readable code, applicable SOLID/DRY/KISS/YAGNI and
separation of concerns. No broad redesign or replacing genuine functionality with a
placeholder solely to obtain a passing text assertion. Update docs for code that actually
exists. A complete inventory cannot be claimed from an unsupported row total.

Gemini authors/runs the independent tests. Supply expected display/caller invariants and
run existing local checks as needed. Send stable noncritical commits and exact file scope
to Gemini. Gemini failures concerning display/docs return to Sonnet; private/domain
failures route to Tera. Notify the user of that transfer using the central protocol.

Use isolated worktrees/branches for parallel writing. Shared checkout writes are sequential.
Do not race updates to the consolidated ledger or stage other workers' changes. Only
explicit slice paths are staged. No live infrastructure, credential output, migrations,
push, deployment or self-assigned Sol approval. These routing rules retain all original
implementation and acceptance requirements across the complete thirty-task assignment.
