## Deployment Flow Analysis

### Step Sequence (from deploy-smart.ps1)

1. **Step 0:** Determine services to deploy (auto-detect or explicit)
2. **Step 1:** Get git commit hash (short 12-char tag)
3. **Step 2:** Verify git status (warn on uncommitted changes)
4. **Step 3:** Run ESLint checks **← BYPASSED by `-SkipChecks`**
5. **Step 4:** Run TypeScript checks **← BYPASSED by `-SkipChecks`**
6. **Step 5:** Build Docker images via `build-save-images.ps1`
7. **Step 6:** Verify build artifacts (tar, sha256, manifest.json)
8. **Step 7:** Upload to production server (72.61.115.49)
9. **Step 8:** Verify checksum on server
10. **Deploy:** Execute `deploy-load-production.sh` on VPS

### Build Script

**Location:** `infra/hostinger/scripts/build-save-images.ps1`

**Process:**
1. Reads service map from `infra/hostinger/config/service-map.json`
2. Merges environment files (but NOT for build-time quality checks)
3. Builds Docker images using `docker compose build`
4. Tags images with commit hash
5. Saves images to tar archive
6. Generates manifest.json with commit provenance
7. Computes SHA-256 checksum

**Critical:** Build occurs INSIDE Docker images. No quality verification inside the Docker build process itself.

## `-SkipChecks` Flag Analysis

**When Provided:**
```powershell
if ($SkipChecks) {
    Write-Warn "Step 3/8: Skipping ESLint checks because -SkipChecks was provided"
} else {
    # Run npm run lint for each service
}

if ($SkipChecks) {
    Write-Warn "Step 4/8: Skipping TypeScript checks because -SkipChecks was provided"
} else {
    # Run npx tsc --noEmit for each service
}
```

**What `-SkipChecks` Bypasses:**
- ✅ ESLint checks (Step 3)
- ✅ TypeScript compilation checks (Step 4)

**What `-SkipChecks` Does NOT Bypass:**
- ❌ Git status verification (Step 2)
- ❌ Docker image build (Step 5)
- ❌ Artifact verification (Step 6-8)
- ❌ Architecture guards (NOT in deploy-smart.ps1)
- ❌ Security tests (NOT in deploy-smart.ps1)
- ❌ Unit tests (NOT in deploy-smart.ps1)

**Script Comment:**
> `-SkipChecks`: Skip ESLint and TypeScript checks. Use only after running checks/builds separately.

## Recommended Integration Point

### Option A: Pre-Build Quality Gate (Recommended)

**Location:** Before Step 5 (build images)

**Implementation:**
```powershell
# New Step 3a: Architecture & Security Guards
Write-Info "Step 3a/9: Running architecture and security guards..."
pnpm quality:skillhubcore:guards
if ($LASTEXITCODE -ne 0) {
    Write-Err "Architecture/security guards failed"
    exit 1
}

# Existing Step 3: ESLint (if not -SkipChecks)
# Existing Step 4: TypeScript (if not -SkipChecks)

# New Step 4a: Safe Unit Tests & Build
Write-Info "Step 4a/9: Running tests and build..."
pnpm quality:skillhubcore:verify
if ($LASTEXITCODE -ne 0) {
    Write-Err "Tests or build failed"
    exit 1
}
```

**Benefits:**
- Fail-fast before Docker build
- Quality verified against source being deployed
- No Docker build resources wasted on failing code
- `-SkipChecks` would need explicit override (not recommended)

### Option B: Separate Pre-Deployment Verification (Alternative)

**Location:** Manual step before `deploy-smart.ps1`

**Implementation:**
```powershell
# Run separately before deployment
pnpm quality:skillhubcore

# Then deploy with evidence
.\scripts\deploy-smart.ps1 -Services "skillhubcore-admin" -SkipChecks
```

**Drawbacks:**
- No enforcement (relies on operator discipline)
- No binding between quality evidence and deployed artifact
- `-SkipChecks` bypasses even lint/typecheck with no verification
