### B1: Privileged Roles Bypass Proposed Learner Flag Restriction
- **Source Fact**:
  - In [`apps/api-server/src/modules/auth/rbac.service.ts:11-15`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/rbac.service.ts#L11-L15), `_verifyAdmin` computes:
    ```typescript
    const tokenRoles = _payload.roles !== undefined && _payload.roles.some(r =>
        ['admin', 'super_admin', 'infrastructure'].includes(r.toLowerCase())
    );
    const isAdminInToken = _payload.isAdmin === true || tokenRoles;
    if (isAdminInToken === true) return true; // Fast payout
    ```
  - Simply setting `successorIsAdmin = false` while copying `userEligibility.roles` into a learner token allows a promoted learner to bypass administrative restrictions via `tokenRoles`!
  - Furthermore, `_verifyAdmin:54-66` queries the live database (`authContext.tables.userRoles`), authorizing any promoted account.
- **Corrected Rule**:
  - Successor authority is strictly capped to the authenticated credential scope: learner successor tokens **MUST filter out** administrative roles (`['admin', 'super_admin', 'infrastructure']`) from `successorRoles`.
  - Harmonized the administrative role set across both contracts to strictly match `rbac.service.ts:13-14` (`['admin', 'super_admin', 'infrastructure']`). Removed `'faculty'`.
  - **Honest System Limitation**: Disclosed that live database queries in `_verifyAdmin:54-66` can still recognize a promoted account; a token refresh check alone cannot enforce a universal portal isolation guarantee. A dedicated guard review is recommended for downstream portal enforcement.
- **Test Matrix Reference**: `TC-LIFE-05` in REFRESH-06 Section 8.
- **Remaining Uncertainty**: Extent of live DB vs. JWT-only checks across non-admin API routes.

## Detailed R1–R9 Review Findings Summary

- **R1 (Ingress Context & Header Resolution)**: Ingress fails closed on missing, invalid, conflicting, or `'shared'` headers with HTTP 400 at route resolution before reaching `AuthService`.
- **R2 (Absent vs. Malformed Claims)**: `brand === undefined` is the only legacy candidate. Malformed claims (including `null`, numbers, booleans, objects, empty strings, and unknown strings) fail closed with HTTP 401. Option B progressive upgrade is a conditional proposal awaiting Sol acceptance.
- **R3 (Distinct Identity Stores)**: Tenant `UserRepository` never queries `@quiz/db-people` or handles SHC principals. SHC specialized tokens rotate via Redis and `people_db`. Generic default-table flows are preserved.
- **R4 (Actual TTLs & Impact)**: Access token TTL is hardcoded to 8 hours (`'8h'`). Refresh eligibility checks are point-in-time checks at $t_{\text{refresh}}$ preventing successor issuance.
- **R5 (Strict Role Lookup Contract)**: `UserRepository` error swallowing is bypassed via a dedicated `findActiveUserWithRoles` method using `this.dbInstance`. Database query errors throw and abort refresh without consuming parent tokens.
- **R6 (Principal Boundaries & Non-Escalation)**: Learner sessions cannot escalate to admin scope; administrative roles (`['admin', 'super_admin', 'infrastructure']`) are stripped from learner successor tokens. Demoted admin sessions fail closed with 401.
- **R7 (Lifecycle Mutation Callers & Scope)**: Accurately mapped soft vs. hard delete in `drizzle-admin-user.repository.ts`, clarified initial user creation role assignment, noted absence of automated runtime role demotion triggers, and identified tenant schema bindings.
- **R8 (HTTP, Audit & Test Compatibility)**: Mapped route error handling to HTTP 401. Differentiated zero session state writes from allowed security audit logging. Preserved constructor arity and authorized necessary mock updates.
- **R9 (Authoritative 6-Row Matrix)**: Fully integrated the owner-confirmed 6-row matrix covering SUIA, RTH, and SHC across production and local environments, using variable `<port>` and citing actual source facts.
