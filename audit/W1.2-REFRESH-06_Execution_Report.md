## 2. Implementation Details

### 2.1 Strict User Eligibility Lookup (`user.repository.ts`)
- Added typed interface `StrictUserEligibility`:
  ```ts
  export interface StrictUserEligibility {
    id: string;
    email: string;
    isBlocked: boolean;
    deletedAt: Date | null;
    roles: string[];
  }
  ```
- Implemented `findActiveUserWithRoles(userId: string)`:
  - Uses `this.dbInstance` directly with tenant-bound tables (`this.tables.users`, `this.tables.roles`, `this.tables.userRoles`).
  - Does **not** query `userProfiles`, keeping the hot refresh path fast and focused.
  - Queries `users` by primary key `id = userId`. Returns `null` if user record is missing.
  - Queries `userRoles` joined with `roles` to collect active role names as lowercase strings.
  - Distinguishes missing user (`null`) from legitimate empty roles (`roles: []`).
  - Propagates database query errors directly (does not swallow DB outages as missing users).

### 2.2 Optional Fourth Dependency & Tenant Binding (`token-refresh.service.ts`)
- Appended `private userRepo = container.get(UserRepository)` as the 4th optional/defaulted constructor parameter:
  - Preserves positions 1–3 (`tokenRepo`, `tokenService`, `auditService`) exactly.
  - Avoids breaking any existing DI or instantiation paths.
- Binds tenant database context via `this.userRepo.withDb(brandContext.db, brandContext.tables)` for in-scope tenant requests.

### 2.3 Account Lifecycle Verification & Zero State Writes (F1, F4)
- Invokes **only** the typed strict eligibility method `brandUserRepo.findActiveUserWithRoles(userId)`. Removed `findByIdWithDetails` fallback entirely.
- Executes tenant-local eligibility check:
  - **Missing User**: Throws HTTP 401 `Invalid refresh token` with audit action `token_refresh_failed` (reason `user_not_found`).
  - **Soft-Deleted User (`deletedAt !== null`)**: Throws HTTP 401 `Account has been deactivated` with audit action `token_refresh_failed` (reason `user_deleted`).
  - **Blocked User (`isBlocked === true`)**: Throws HTTP 401 `access_denied:user_blocked` with audit action `token_refresh_failed` (reason `user_blocked`). Resolves baseline test `auth.refresh.blocked.branch.test.ts`.
- **Zero Session Writes on Rejection**: `updateLastUsed` is placed at Step 2.8, executing only **after** all checks succeed. On denied/missing/deleted/blocked/demoted/query-error requests, `updateLastUsed` is never called, `consumeToken` is never called, and `createRefreshToken` is never called.

### 2.4 Role Freshness & Principal Boundary Defense (B1)
- Revalidates dynamic roles from tenant DB on refresh while defending principal boundaries:
  - **Learner Principal Scope (`requestedAudience === 'user'`)**:
    - Retains `isAdmin: false`, `tokenType: 'user'`, and `aud: 'user'`.
    - **Defense against RBAC Bypass**: In `rbac.service.ts:11-15`, `_verifyAdmin` evaluates `payload.isAdmin === true || tokenRoles`. To prevent an out-of-band DB admin promotion from converting a learner session into an admin session, administrative roles (`['admin', 'super_admin', 'infrastructure']`) are strictly filtered out of learner successor tokens (`successorRoles`).
  - **Admin Principal Scope (`requestedAudience === 'admin'`)**:
    - Checks whether DB roles include an administrative role (`admin`, `super_admin`, or `infrastructure`).
    - If user was demoted (no admin roles in DB), refresh fails closed immediately with `access_denied:insufficient_permissions` and logs `admin_session_demoted_denied`. Admin sessions are **never silently downgraded** to learner tokens. Current parent token remains unconsumed.
  - **Out-of-Scope Flows (F2)**:
    - Generic infra (`aud: 'infra'`) and SHC default-DB flows are preserved without tenant lookup.
