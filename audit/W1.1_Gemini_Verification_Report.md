- **Claim**: `TokenService.assertIdentityClaims` strictly asserts that `shadowUserId` and `originalUserId` are non-empty strings.
- **Verification**: Lines 116–124 in [`packages/auth/src/token.service.ts`](file:///E:/onlinewebsites/quiz-platform/packages/auth/src/token.service.ts#L116-L124):

  ```typescript
    if (typeof payload.shadowUserId !== 'string' || payload.shadowUserId.trim().length === 0) {

      throw new TokenInvalidError('Missing originalUserId claim');

  ```
  **Result**: **CONFIRMED** ✅.

### 3.2 Database Schema & Email Uniqueness (`packages/db/src/schema/auth.ts`)

## 5. Review of the 5 Unresolved Decisions Blocking W1.2

Sonnet correctly elevates 5 architectural decisions that cannot be decided by automated reconciliation and require project owner authorization:

1. **Database Schema & Email Strategy**:
   - *Conflict*: `users.email` is currently `UNIQUE` globally in `packages/db/src/schema/auth.ts`.
   - *Options*: (A) Physically separate databases for SUIA and RTH learners; (B) Shared table with composite unique constraint `(tenant_id, email)`; or (C) Global email registry with isolated tenant learner profiles.
2. **Multi-Platform (`platforms: ['skillup', 'realtutorialhub']`) Token Semantics**:
   - *Conflict*: Tokens with multiple platforms currently exist in tests.
   - *Requirement*: Must be formally classified as staff/service scope only, never a dual-tenant learner identity.
3. **`shadowUserId` vs `originalUserId` Semantics**:
   - *Conflict*: Mandatory in TokenService, but their relationship is undocumented.
   - *Requirement*: Owner must clarify whether `originalUserId` represents administrative impersonation, session delegation, or account migration.
4. **Interactive Learning Session (`ilsSessionId`) Authority**:
   - *Conflict*: Currently accepted from client request bodies/headers without cryptographic verification.
   - *Requirement*: Must be bound to tenant context and learner identity server-side.
5. **Header Trust Model vs Downstream Token Verification**:
   - *Conflict*: Downstream services trust `X-User-ID` and `X-Brand` when accompanied by internal gateway secret.
   - *Requirement*: Define whether service-to-service calls should continue using HMAC/gateway secret header transport or transition to signed service JWTs.
