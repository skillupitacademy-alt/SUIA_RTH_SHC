## Source conclusions and remaining gaps

Progress derives subject and canonical tenant from a verified user credential and denies
conflicting subject/brand headers. The helper uses an optional-result object followed by
non-null assertion, and permits absent false-like isAdmin values unless true. These
implementation choices do not expand this review's acceptance beyond the observed valid
issuer and rejection controls. Production caller compatibility needs a source-backed
integration test. The gateway injects originalUserId into X-User-ID while the route compares
that header to payload.userId. Tokens where those differ need explicit compatibility
qualification, preserving tenant-local authority rather than weakening the subject check.

The progress test named cross-tenant uses different local user IDs. Its mocked repository
ignores tenant when matching user/subtopic. That passing case establishes absence for a
different ID, rather than isolation for equal tenant-local IDs. The real repository keys
userId/subtopicId, and the real engine brand gate remains permissive. No namespace, shadow
ID substitution or global uniqueness assumption is accepted as the resolution.

The status owner guard precedes recovery and workflow reads for an existing job. Missing
job/exam fallback and legacy resource provenance require tenant-aware owner qualification.
The submitted status test file still has only three ordinary cases. Sol's seven-control
probe supplies focused stale/internal compatibility evidence, but broader resource routing
and cross-tenant storage authority remain separate requirements.

The export proposal to enforce globally unique IDs conflicts with the accepted independent
tenant model. getAuthBrandContext exposes auth tables, not a demonstrated tenant exam/job
repository. Adding a brand check against a nonexistent field is not an implementation
plan. Producers, queue payloads, recovery, legacy rows and storage references need an
explicit authority contract before schema or data changes are considered.

The revised map still calls plain string comparisons constant-time. It also conflates the
gateway-auth helper's INTERNAL_GATEWAY_SECRET with internal-auth's GATEWAY_TRUST_SECRET
selection. Verify these functions independently. Some source references name a nonexistent
middleware/csrf.middleware.ts instead of modules/auth/csrf.middleware.ts. The map must show
the actual production proxy, BFF/gateway rewrite and consumer behavior with accurate paths.

SHC policy correctly records 8h default issuance and absent refresh-row insert in login.
It still describes orphaned cookies as never consumed anywhere without tracing FetchClient,
labels sliding refresh an OWASP requirement, conflates individual token expiry with an
absolute session-family cap, and claims a <=15 minute theft bound while proposing 30 minutes
and issuing refresh credentials. Client idle lock alone does not enforce server inactivity.
TokenService already accepts an explicit custom expiry, so a new generic TTL API needs a
source justification. Cookie removal and session-family revocation require compatibility,
persistence and replay-classification design. None is approved by this review.
