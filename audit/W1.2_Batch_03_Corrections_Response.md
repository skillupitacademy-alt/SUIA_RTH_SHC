## 1. Response to Review Findings (F1 – F6)

### F1: Lifecycle rejection still mutates session state (Resolved)
- **Root Cause**: `updateLastUsed(oldTokenHash)` was previously executed at Step 2.5 before tenant user lookup, eligibility checks, and demotion policy.
- **Correction**: Moved `updateLastUsed` to Step 2.8, executing **only after** all scoped authority, cryptographic verification, user eligibility (missing/deleted/blocked), and demotion checks succeed.
- **Verification**: On every rejection (blocked, deleted, missing, demoted, role query error, core query error, claim conflict), `updateLastUsed` is **never called**; `consumeToken` is **never called**; zero session state writes occur.
- **Probe Evidence**: Verified via `python audit/W1.2_Batch_03_Sol_Probe.py` (all 5 failure checks assert `expect(mockTokenRepo.updateLastUsed).not.toHaveBeenCalled()` and pass).

### F2: New tenant policy changes SHC/infra/default-DB behavior (Resolved)
- **Root Cause**: The service previously applied tenant user repository lookup across all brands and audiences.
- **Correction**: Established a single, explicit scope predicate for tenant policy:
  ```ts
  const isScopedTenant =
    (brand === 'realtutorialhub' || brand === 'skillup') &&
    (requestedAudience === 'user' || requestedAudience === 'admin');
  ```
  Outside this scope (generic infrastructure `aud: 'infra'`, `brand === 'skillhubcore'`, default DB), the service does **not** invoke `userRepo.findActiveUserWithRoles` and preserves the exact claims and outputs of accepted base `8f419b0f`.
- **Verification**: `SOL: infra must not invoke tenant eligibility` probe passes. Added `TC-AUTH-15` in `token-refresh.authority.test.ts` and route test verifying successful infrastructure dispatch with `infra_refreshToken` cookie.

### F3: Present principal-class claims incompletely validated (Resolved)
- **Root Cause**: Inconsistent present claims (`aud: 'admin'` with explicit `isAdmin: false` when `tokenType` was absent, or unsupported `tokenType: 'unexpected-class'`) were normalized or accepted.
- **Correction**: Implemented runtime type and scope validation for all present claims in scoped tenant requests:
  - `oldPayload.isAdmin`: If present, must be boolean; explicit `false` with `aud: 'admin'` rejects; explicit `true` with `aud: 'user'` rejects.
  - `oldPayload.tokenType`: If present, must be strictly `'user'` or `'admin'`; unknown values reject; cross-scope contradictions reject.
  - Omissions supported: Genuinely absent legacy claims infer compatible defaults without contradiction.
- **Verification**: Both Sol probe checks (`explicit false admin flag conflicts with admin audience` and `unsupported present tokenType must be rejected`) reject with HTTP 401 `Invalid refresh token` before any session state writes.

### F4: Strict eligibility silently falls back to error-swallowing hydration (Resolved)
- **Root Cause**: `token-refresh.service.ts` included a fallback to `findByIdWithDetails` and a `map((ur: any) ...)` when the strict method was absent.
- **Correction**: Removed `findByIdWithDetails` fallback entirely. The service invokes only the typed strict method `brandUserRepo.findActiveUserWithRoles(userId)`. If absent, it fails closed immediately. Updated test mocks in `auth.refresh.branch.test.ts` and `auth.refresh.blocked.branch.test.ts` to supply `findActiveUserWithRoles` while strictly preserving their assertions.
- **Verification**: `SOL: strict method must not fall back to permissive hydration` probe passes.

### F5: Connected tenant/strict-query evidence (Resolved)
- **Correction**: Added `describe('Connected Service + Real UserRepository on Isolated Tenant Fixtures (F5)')` to `token-refresh.lifecycle.test.ts` featuring:
  - `TC-LIFE-10`: Colliding user ID `col-user-1` is active student in RTH store but blocked in SUIA store. RTH service succeeds; SUIA service fails closed (`access_denied:user_blocked`) with zero session writes, proving SUIA cannot borrow RTH active eligibility.
  - `TC-LIFE-11`: Core query failure (`users` query fails) propagates DB error directly without swallowing; zero session writes.
  - `TC-LIFE-12`: Role query failure (`userRoles` query fails) propagates DB error directly without swallowing; zero session writes.
  - `TC-LIFE-13`: Learner with empty roles succeeds; admin requested with empty roles fails closed (`access_denied:insufficient_permissions`); zero session writes.
  - `TC-LIFE-14`: Verifies `userProfiles` table is never queried during `findActiveUserWithRoles`.

### F6: Quality evidence, accurate diffs, and audit naming (Resolved)
- **Audit Event Renamed**: Changed demotion audit action from `admin_session_demoted_revoked` to `admin_session_demoted_denied`.
