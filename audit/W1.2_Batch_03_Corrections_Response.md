### Remaining Item 1: Scope Predicate Governing All New Policy & Lazy UserRepository
- **Issue**: Sol's review at `7a3b26ef` identified that while core lifecycle and denial ordering were fixed, new subject parity checks, brand claim validations, and `UserRepository` dependency construction were still evaluated outside the scoped tenant path (`isScopedTenant`).
- **Correction Applied**:
  1. **Lazy Dependency Resolution**: In `TokenRefreshService`, constructor parameter `userRepo?: UserRepository` is now strictly optional and not eagerly defaulted to `container.get(UserRepository)`:
     ```ts
     export class TokenRefreshService {
       private userRepo?: UserRepository;
       constructor(
         private tokenRepo = container.get(TokenRepository),
         private tokenService = container.get(TokenService),
         private auditService = container.get(AuditService),
         userRepo?: UserRepository
       ) {
         this.userRepo = userRepo;
       }
     ```
  2. **Single Predicate Scope Isolation**: Defined `isScopedTenant`:
     ```ts
     const isScopedTenant =
       (brand === 'realtutorialhub' || brand === 'skillup') &&
       (requestedAudience === 'user' || requestedAudience === 'admin');
     ```
  3. **Strict Policy Scoping**:
     - **Subject Parity** (`oldPayload.userId === existingSession.userId`): Evaluated **strictly inside `if (isScopedTenant)`**.
     - **Class Consistency** (`isAdmin` boolean validation, `tokenType` validation, cross-scope contradiction checks): Evaluated **strictly inside `if (isScopedTenant)`**.
     - **Brand Claim Validation** (rejecting malformed/mismatched brand claims, supporting legacy omission): Evaluated **strictly inside `if (isScopedTenant)`**.
     - **Repository Resolution & Tenant Binding**: `this.userRepo = this.userRepo ?? container.get(UserRepository)` and tenant `withDb` binding execute **strictly inside `if (isScopedTenant)`**.
  4. **Preservation of Excluded Paths**: Generic infrastructure (`aud: 'infra'`), SkillHubCore default database, and out-of-scope callers bypass all newly introduced subject parity checks, brand claim validations, and user eligibility queries. They execute cryptographic verification, audience verification, and atomic CAS rotation exactly as in accepted base `8f419b0f`.
- **Verification**: `python audit/W1.2_Batch_03_Sol_Probe.py` probe `infra must not invoke tenant eligibility` passes cleanly; route and service tests confirm infra preservation.

     ```ts
     for (const chunk of chunks) {

         if (chunk.name === 'email' && chunk.table?._?.name === 'users') { ... }
       }
     }
     ```
  4. **Distractor Rows**: Configured distinct user rows where `id !== email` (`id: 'col-user-1'`, `email: 'alice@rth.com'`, plus distractor `id: 'col-user-10'`, `email: 'distractor@rth.com'`). If the query filters by `email = 'col-user-1'`, it matches nothing and fails.
