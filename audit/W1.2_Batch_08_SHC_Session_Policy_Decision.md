## 1. Executive Summary & Problem Statement

In the accepted Phase 1 multi-tenant architecture, tenant learners (`skillup` and `realtutorialhub`) utilize short-lived access tokens (15 minutes) coupled with single-consumer, atomically rotating refresh tokens (7 days) bound to their respective tenant-local databases.

However, the internal governance administrative portal, **SkillHubCore Admin (`apps/skillhubcore-admin`)**, currently exhibits an architectural divergence:
1. `apps/skillhubcore-admin/src/app/api/auth/login/route.ts` proxies to the upstream `api/shc/auth/login` endpoint, which returns both an `accessToken` (8-hour TTL) and a `refreshToken` (7-day TTL).
2. `apps/skillhubcore-admin/src/lib/admin-session-cookies.ts` issues four HTTP-only cookies: `accessToken`, `admin_accessToken`, `refreshToken`, and `admin_refreshToken`.
3. **Critical Lifecycle Gap:** `apps/skillhubcore-admin` has **no refresh route** (`/api/auth/refresh` or `/api/admin/auth/refresh` does not exist).
4. `apps/skillhubcore-admin/src/components/auth/AdminLockScreen.tsx` implements a client-side idle lock. When the screen is locked, unlocking requires full password re-authentication via `loginPortalSession`.
5. Therefore, the issued refresh token cookies are currently orphaned: they are never consumed by any client background worker or BFF endpoint.

This document analyzes the viable session lifecycle options, compares trade-offs, and provides an authoritative recommendation with an exact file whitelist and acceptance test specification for subsequent implementation.

## 2. Source Evidence & Architectural Baseline

### 2.1 SkillHubCore Admin BFF & Handlers
- **Login Handler (`apps/skillhubcore-admin/src/app/api/auth/login/route.ts`)**:
  - Enforces `requireAdminMutationOrigin(request)`.
  - Proxies upstream to `FALLBACK_API_BASE_SKILLHUBCORE` at `api/shc/auth/login`.
  - Sets cookies via `setAdminSessionCookies`.
- **Cookie Setter (`apps/skillhubcore-admin/src/lib/admin-session-cookies.ts`)**:
  - Sets `accessToken`, `admin_accessToken`, `refreshToken`, `admin_refreshToken` as `httpOnly`, `sameSite: 'lax'`, `path: '/'`.
  - Also emits domain deletion headers for `.skillhubcore.in` to eliminate legacy cross-subdomain residue.
- **Admin Authentication Verifier (`apps/skillhubcore-admin/src/lib/auth-helpers.ts`)**:
  - Reads `accessToken` or `admin_accessToken` cookie.
  - Verifies token via `TokenService.verifyAdminAccessToken(token, { audience: 'shc-admin' })`.
  - Enforces `payload.brand === 'skillhubcore'`.
  - Enforces administrative roles via `RBACService.isAdminLevel(roles)`.
- **Client Idle Lock (`apps/skillhubcore-admin/src/components/auth/AdminLockScreen.tsx`)**:
  - Triggered by client inactivity in `useAuthStore`.
  - Traps user input; requires entering password to unlock.
  - Submits full re-login request via `loginPortalSession`.

### 2.2 Upstream API Server Handling
- **Proxy Boundary (`apps/api-server/src/proxy.ts`)**:
  - `/api/admin/*` and `/api/factory/*` with `portalIdentity: 'shc-admin'` are accepted if token has `brand: 'skillhubcore'`, `isAdmin: true`, and role in `['admin', 'super_admin', 'infrastructure']`.
  - `/api/analytics/admin/*` explicitly rejects `portalIdentity: 'shc-admin'` with HTTP 403 Forbidden to prevent cross-tenant data leakage.
- **Token Refresh Service (`apps/api-server/src/modules/auth/token-refresh.service.ts`)**:
  - Lines 390–399: Non-tenant principal path preserves legacy out-of-scope token refresh without tenant-local DB queries.
  - However, no SHC admin client calls this endpoint.

## 3. Policy Comparison: Absolute Session vs. Sliding Refresh Rotation

| Evaluation Criteria | Option 1: Absolute Session + Screen-Lock Re-auth | Option 2: Sliding Refresh Rotation (OWASP Standard) |
| :--- | :--- | :--- |
| **Access Token TTL** | 8 Hours (Static / Absolute) | 15–30 Minutes (Ephemeral) |
| **Refresh Token Existence** | None (Deprecated/Removed from cookies) | 7 Days (Single-use, rotated on each refresh) |
| **Client Idle / Inactivity** | `AdminLockScreen` locks screen after 15m idle; password re-auth required. | Sliding background refresh keeps active admin logged in; idle stops refresh. |
| **Max Session Lifetime** | Strictly 8 hours. After 8 hours, session expires regardless of activity. | Configurable max absolute cap (e.g., 24 hours), with sliding 15m renewals. |
| **Stolen Token Exposure** | High (Exfiltrated token valid for up to 8 hours without server-side check). | Low (Exfiltrated access token expires in ≤15 minutes). |
| **Immediate Revocation** | Requires explicit token blacklist or per-request database check. | Immediate on refresh: consuming already-used refresh token revokes session tree. |
| **Complexity & Rollout** | Minimal: Remove unused refresh cookies, align documentation. | Moderate: Requires new BFF `/api/auth/refresh` route and auto-refresh hook in SHC. |
| **CSRF / Origin Guard** | Protected by `SameSite=Lax` + `requireAdminMutationOrigin`. | Protected by `SameSite=Lax` + Origin/Referer check on refresh POST. |

## 4. Architect Recommendation

We recommend a **two-phase phased resolution**:

### Phase 1 (Wave 1 Status Quo Codification — Immediate)
1. **Retain 8-Hour Absolute Session for SHC Admin** as the approved operational baseline during Wave 1 remediation.
2. Formally recognize that `apps/skillhubcore-admin` operates on absolute session tokens backed by client-side `AdminLockScreen`.
3. In Phase 1, the unused `refreshToken` and `admin_refreshToken` cookies remain harmlessly in place or are scoped out of qualification, avoiding unnecessary runtime mutations.

### Phase 2 (Wave 4 Full Remediation — Formal Target)
When Wave 4 (SkillHubCore Admin & Governance) remediation commences:
1. **Adopt Option 2 (Sliding Refresh Rotation)** to align SHC Admin with enterprise OWASP standards and tenant learner security practices.
2. Reduce `accessToken` TTL to 15 minutes (`aud: 'shc-admin'`).
3. Deploy `/api/auth/refresh` in `apps/skillhubcore-admin` proxying to `api/shc/auth/refresh`.
4. Implement atomic single-use refresh token rotation in `people_db` (`defaultDb`).
5. Wire `useAutoRefresh` hook in `apps/skillhubcore-admin/src/app` to rotate tokens silently every 10 minutes while active.
6. Retain `AdminLockScreen.tsx` for client inactivity / physical terminal protection.

## 5. File Whitelist & Consumer Boundaries for Wave 4 Implementation

When authorized for implementation in Wave 4, modifications MUST be strictly bounded to the following files:

### A. New BFF Route:
- `apps/skillhubcore-admin/src/app/api/auth/refresh/route.ts` (Handles refresh mutation, origin guard, and cookie rotation).

### B. BFF Cookie & Proxy Helpers:
- `apps/skillhubcore-admin/src/lib/admin-session-cookies.ts` (Support atomic rotation of `accessToken` and `refreshToken`).
- `apps/skillhubcore-admin/src/lib/upstream-proxy.ts` (Proxy upstream to `api/shc/auth/refresh`).

### C. Client Auto-Refresh Integration:
- `apps/skillhubcore-admin/src/components/auth/AuthRefreshProvider.tsx` (Mount background interval for active tabs).
- `apps/skillhubcore-admin/src/store/auth-store.ts` (Synchronize last active time and refresh status).

### D. Upstream API Server SHC Refresh Handler:
- `apps/api-server/src/modules/auth/token-refresh.service.ts` (Add `people_db` strict admin account verification for `brand: 'skillhubcore'`).

## 6. Acceptance Test Specification (For Wave 4)

1. **Test SHC-REFRESH-01 (Positive Rotation):**
   - Submit valid `admin_refreshToken` with `aud: 'shc-admin'`.
   - Returns 200 with new 15m `admin_accessToken` and rotated `admin_refreshToken`.
   - Parent refresh token is marked consumed in `people_db`.
2. **Test SHC-REFRESH-02 (Anti-Replay / Reuse Detection):**
   - Submitting already-consumed `admin_refreshToken` rejects with 401 and revokes session family.
3. **Test SHC-REFRESH-03 (Tenant Isolation):**
   - Submitting `shc-admin` refresh token to tenant refresh endpoint (`skillup` or `realtutorialhub`) fails closed.
4. **Test SHC-REFRESH-04 (Deactivated Admin):**
   - If admin user is blocked or role revoked in `people_db`, refresh rejects with 403 Forbidden.
