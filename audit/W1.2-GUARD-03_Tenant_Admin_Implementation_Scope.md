## 1. Executive Summary & Objective

This specification establishes the source-backed, reviewable implementation scope for hardening the low-level tenant administrator authorization helper `_verifyAdmin` and reconciling its caller chain across both the API gateway proxy (`apps/api-server/src/proxy.ts`) and route-level helpers (`apps/api-server/src/modules/auth/admin-audience.util.ts`).

In accordance with accepted GUARD-02 architecture:
- `_verifyAdmin` is formally defined as a **tenant-local administrator authorization helper** (`brand: 'skillup' | 'realtutorialhub'`).
- It must enforce strict principal preconditions (canonical tenant brand, non-empty tenant subject, consistent admin token class, and scoped `admin` audience) fail-closed *before* executing any database queries.
- Before deploying strict helper enforcement, the API gateway proxy (`proxy.ts`) must undergo targeted routing adaptation so that valid non-tenant callers (such as infrastructure callers accessing `/api/factory` or `/api/analytics/admin`) are branched safely to their own permission checks and are never misrouted into tenant `_verifyAdmin`.

### Core Architectural Principles:
- **Least Privilege & Secure Defaults:** A token lacking explicit administrative class claims or audience must never obtain administrative authority, even if its database record holds administrative roles.
- **Separation of Concerns:** Tenant administrator verification (`_verifyAdmin`) is strictly decoupled from infrastructure authorization (`PERMISSIONS.ADMIN_PANEL`) and SkillHubCore governance (`hasSkillHubCoreAdminAccess`).
- **High Cohesion & Low Coupling:** Gateway routing (`proxy.ts`) and route-level guards (`admin-audience.util.ts`) maintain distinct, explicit branch boundaries without leaking SHC people IDs or infra roles into tenant RBAC tables.
- **Source-Backed Evidence & Realism:** Distinguish observed source behavior from approved policy; treat external caller landscape as UNKNOWN where unverified rather than assuming external consumers do not exist.

## 2. Caller Architecture: Gateway Proxy vs Route Guard Layers

To avoid conflation between layers, we distinguish the three distinct evaluation layers in `apps/api-server`:

1. **Layer 1: Gateway Proxy (`apps/api-server/src/proxy.ts:81-173`)**
   - Intercepts non-exempt, non-auth requests before Next.js route execution.
   - Derives `scope` (`'admin' | 'user' | 'infrastructure'`) and `expectedAudience` (`'admin' | 'user' | 'infra' | 'shc-admin'`) from `x-portal-identity` and `pathname`.
   - Executes `TokenService.verifyAdminAccessToken(_token, { audience: expectedAudience })` for admin/infra scopes.
   - Selects a routing branch:
     - `isShcAdminRoute`: `(pathname.startsWith('/api/admin') || pathname.startsWith('/api/factory')) && portalIdentity === 'shc-admin'` -> verifies SHC brand and roles in-memory.
     - `isInfraRoute`: `pathname.startsWith('/api/admin') && portalIdentity === 'infrastructure'` -> verifies `RBACService.hasPermission(roles, PERMISSIONS.ADMIN_PANEL)`.
     - `isAdminRoute`: `(pathname.startsWith('/api/admin') && !pathname.startsWith('/api/admin/auth') && portalIdentity !== 'infrastructure') || (pathname.startsWith('/api/factory') && portalIdentity !== 'shc-admin') || pathname.startsWith('/api/analytics/admin')` -> **invokes `_verifyAdmin(_payload)`**.
2. **Layer 2: Route-Level Guard (`apps/api-server/src/modules/auth/admin-audience.util.ts`)**
   - Executed inside specific Next.js route handlers (e.g. `/api/admin/*`, `/api/factory/save`).
   - `getAdminAudience(_req)`: derives `expectedAud` (`'shc-admin' | 'infra' | 'admin'`) from `x-portal-identity`.
   - `verifyAdminOrInfraToken(_req)`: verifies token via `TokenService.verifyAdminAccessToken(scopedToken, { audience: expectedAud })`.
   - `requireAdminRouteAccess(_req)`:
     - If `audience === 'shc-admin'`: checks SHC brand and roles in-memory. Does NOT call `_verifyAdmin`.
     - If `audience === 'infra'`: **bypasses `_verifyAdmin`** and returns payload directly.
     - If `audience === 'admin'`: calls `_verifyAdmin(payload)`.
   - *Standalone Route Handlers:* Routes like `/api/analytics/admin/topic-skill-heatmap` do *not* call `requireAdminRouteAccess`; they invoke `TokenService.verifyAdminAccessToken(token)` directly (defaulting to audience `'admin'`) and then evaluate `PERMISSIONS.ANALYTICS_VIEW`.
3. **Layer 3: Tenant Authorization Helper (`apps/api-server/src/modules/auth/rbac.service.ts:11-67`)**
   - `export async function _verifyAdmin(_payload: TokenPayload): Promise<boolean>`
   - Low-level helper that queries tenant `users` and `userRoles` tables in PostgreSQL.

## 4. Key Counterexamples & Root Cause Analysis

The source evaluation reveals three concrete counterexamples that invalidate any assumption that `_verifyAdmin` is never reached by non-tenant callers:

1. **Factory Infrastructure Callers (`/api/factory/*` with `portalIdentity: infrastructure`):**
   - Predicate in `proxy.ts:128`: `const isInfraRoute = pathname.startsWith('/api/admin') && portalIdentity === 'infrastructure';`
   - Because `pathname` starts with `/api/factory`, `isInfraRoute` evaluates to `false`.
   - `isShcAdminRoute` evaluates to `false` (portalIdentity is `'infrastructure'`).
   - Line 130: `isAdminRoute = ... (pathname.startsWith('/api/factory') && portalIdentity !== 'shc-admin') ...` evaluates to `true`!
   - Proxy executes line 159: `const hasAdminAccess = await _verifyAdmin(_payload);`.
   - **Impact of Strict Helper:** If `_verifyAdmin` is hardened to reject `aud !== 'admin'` *without* adapting `proxy.ts`, legitimate infrastructure calls to `/api/factory/save` and `/api/factory/check-duplicates` will be rejected with HTTP 403 at the proxy layer.
2. **Analytics Infrastructure Callers (`/api/analytics/admin/*` with `portalIdentity: infrastructure`):**
   - `isInfraRoute` does not include `/api/analytics/admin`.
   - `isAdminRoute` includes all `pathname.startsWith('/api/analytics/admin')` indiscriminately.
   - Proxy calls `_verifyAdmin(_payload)` with `aud: 'infra'`.
3. **Analytics SHC Callers (`/api/analytics/admin/*` with `portalIdentity: shc-admin`):**
   - Predicate in `proxy.ts:125-127`: `isShcAdminRoute = (pathname.startsWith('/api/admin') || pathname.startsWith('/api/factory')) && portalIdentity === 'shc-admin';`
   - Does not include `/api/analytics/admin`.
   - `isAdminRoute` evaluates to `true`.
   - Proxy calls `_verifyAdmin(_payload)` with `aud: 'shc-admin'`.
   - In current code, `_verifyAdmin` silently coerces brand to `'realtutorialhub'` and attempts to query the RTH `users` table with the SHC user ID.

## 5. Minimal Future Routing Adaptation Specification

Before deploying strict precondition enforcement in `_verifyAdmin`, the following bounded routing adaptation must be scheduled and implemented in `apps/api-server/src/proxy.ts`.

### 5.1 Required Gateway Proxy Predicate Adaptation (`apps/api-server/src/proxy.ts`)

```ts
// Proposed minimal adaptation in proxy.ts (DO NOT IMPLEMENT IN BATCH 06)

const isAdministrativePath =
  pathname.startsWith('/api/admin') ||
  pathname.startsWith('/api/factory') ||
  pathname.startsWith('/api/analytics/admin');

// 1. Unified Infrastructure Route Predicate
const isInfraRoute = isAdministrativePath && portalIdentity === 'infrastructure';

// 2. Unified SkillHubCore Governance Route Predicate
// Note: Analytics admin endpoints are tenant-specific analytics. SHC admin access
// to tenant analytics is NOT granted by inference. SHC is permitted only on admin & factory.
const isShcAdminRoute =
  (pathname.startsWith('/api/admin') || pathname.startsWith('/api/factory')) &&
  portalIdentity === 'shc-admin';

// 3. Explicit Denial for Unsupported Combinations
const isUnsupportedShcRoute =
  pathname.startsWith('/api/analytics/admin') && portalIdentity === 'shc-admin';

// 4. Strict Tenant Admin Route Predicate
const isAdminRoute =
  isAdministrativePath &&
  !pathname.startsWith('/api/admin/auth') &&
  portalIdentity !== 'infrastructure' &&
  portalIdentity !== 'shc-admin';
```

### 5.2 Explicit Decisions for Supported and Unsupported Combinations

1. **Supported Combinations:**
   - `(admin path, portalIdentity: 'admin' | default)` -> Route to `_verifyAdmin`. Supported brands: `skillup`, `realtutorialhub`.
   - `(admin | factory | analytics/admin path, portalIdentity: 'infrastructure')` -> Route to `RBACService.hasPermission(roles, PERMISSIONS.ADMIN_PANEL)`. Bypasses `_verifyAdmin`.
   - `(admin | factory path, portalIdentity: 'shc-admin')` -> Route to `hasSkillHubCoreAdminAccess` (brand: `skillhubcore`, role: `admin | super_admin | infrastructure`). Bypasses `_verifyAdmin`.
2. **Unsupported Combinations (Fail Closed with HTTP 403):**
   - `(analytics/admin path, portalIdentity: 'shc-admin')` -> Denied at gateway with HTTP 403 (`Forbidden: SkillHubCore portal cannot access tenant analytics`). Never reaches `_verifyAdmin`.
   - `(admin | factory | analytics path, portalIdentity: 'user')` -> Denied at gateway with HTTP 403 (`Forbidden: Administrative privileges required`).
   - Unknown or malformed `portalIdentity` -> Evaluates to default `'user'` scope and rejected fail-closed.

### 5.3 External Caller Landscape & Legacy Limits

- In-repo callers have been audited (`apps/skillup-web`, `apps/realtutorialhub-web`, `apps/admin-web`, `packages/*`).
- **External & Deployed Consumers:** Classified strictly as **UNKNOWN (unproven absence)**. We do not assert that no external scripts, cron jobs, or monitoring harnesses invoke these paths.
- To protect unknown external callers while maintaining security:
  - Preserved routes continue to accept valid bearer tokens with explicit `x-portal-identity` headers.
  - The proxy must log structured warnings on any legacy caller relying on implicit portal defaults before any future deprecation.

## 6. Target Policy Specification for `_verifyAdmin`

Once the gateway routing adaptation in Section 5 is in place, `_verifyAdmin` functions as a strictly shielded tenant-admin helper:

```mermaid
flowchart TD
    Start([_verifyAdmin(payload)]) --> CheckBrand{Canonical Tenant Brand?<br/>skillup or realtutorialhub}
    CheckBrand -- No --> DenyFailClosed[Return false<br/>Log warning: invalid_tenant_brand]
    CheckBrand -- Yes --> CheckSubject{Non-Empty Subject?<br/>userId trimmed > 0}
    CheckSubject -- No --> DenyFailClosed
    CheckSubject -- Yes --> CheckClass{Consistent Class?<br/>tokenType === 'admin' &<br/>isAdmin === true}
    CheckClass -- No --> DenyFailClosed
    CheckClass -- Yes --> CheckAudience{Valid Admin Audience?<br/>scalar 'admin' or<br/>['admin', 'internal']}
    CheckAudience -- No --> DenyFailClosed
    CheckAudience -- Yes --> Step0{Step 0: DB Account Active?<br/>select isBlocked from users}
    Step0 -- Missing or Blocked --> DenyFailClosed
    Step0 -- DB Throws --> CatchError[Catch error -> Return false fail-closed]
    Step0 -- Active & Not Blocked --> Step1[Step 1: Fast Path<br/>isAdmin === true]
    Step1 --> GrantAccess([Return true])
```

### 6.1 Precondition Rules (Evaluated in Order)

1. **Canonical Tenant Brand:**
   - Must strictly equal `'skillup'` or `'realtutorialhub'` (lowercase string).
   - Any other value (`'skillhubcore'`, empty string, null, undefined, unknown brand) immediately returns `false`.
   - **Zero silent fallback** to `'realtutorialhub'`.
2. **Non-Empty Tenant Subject:**
   - `typeof _payload.userId === 'string' && _payload.userId.trim().length > 0`.
   - Empty, whitespace, null, or non-string `userId` returns `false` before database access.
3. **Runtime Token Class Consistency:**
   - `_payload.tokenType` must strictly equal `'admin'`.
   - `_payload.isAdmin` must strictly equal boolean `true`.
   - Any contradictory claim (`tokenType: 'user'` with `isAdmin: true`, or `tokenType: 'admin'` with `isAdmin: false`) returns `false`.
4. **Audience Specification:**
   - **Scalar:** Must strictly equal `'admin'`.
     - Reject `'user'`, `'infra'`, `'shc-admin'`, empty string, null, undefined.
   - **Array Audience:**
     - All elements must be non-empty strings.
     - Must include `'admin'`.
     - Permitted elements: `['admin']` or `['admin', 'internal']` (order immaterial).
     - Must NOT contain `'user'`, `'infra'`, `'shc-admin'`, or unknown strings.
     - Empty array returns `false`.
5. **Account Lookup & Failure Semantics (Step 0):**
   - Query `users` table in `authContext.tables.users` where `id === _payload.userId`.
   - If user not found: return `false`.
   - If `isBlocked === true`: return `false`.
   - If database query throws: catch error, log structured warning, return `false` (fail-closed).
6. **Fast-Path & Obsolete Role Fallback (Steps 1 & 2):**
   - Under the hardened precondition `isAdmin === true`, once Step 0 verifies the user is active, Step 1 (`if (isAdminInToken === true) return true;`) immediately returns `true`.
   - **Step 2 (`userRoles` query) becomes obsolete** and safely deprecated, eliminating uncaught database exception risks.

### 7.2 Regression Criteria Across All Combinations
1. **Regression Control 1 (Admin Route + Admin Portal):** Legitimate tenant-admin succeeds via `_verifyAdmin`.
2. **Regression Control 2 (Admin Route + Infra Portal):** Infrastructure caller succeeds via `proxy.ts:isInfraRoute` and `requireAdminRouteAccess:infra`, bypassing `_verifyAdmin`.
3. **Regression Control 3 (Admin Route + SHC Portal):** SHC admin succeeds via `proxy.ts:isShcAdminRoute` and `requireAdminRouteAccess:shc-admin`, bypassing `_verifyAdmin`.
4. **Regression Control 4 (Factory Route + Infra Portal):** Infrastructure caller accessing `/api/factory/save` succeeds via adapted `isInfraRoute` without hitting `_verifyAdmin`.
5. **Regression Control 5 (Factory Route + SHC Portal):** SHC caller accessing `/api/factory/*` succeeds via `isShcAdminRoute` without hitting `_verifyAdmin`.
6. **Regression Control 6 (Analytics Route + Infra Portal):** Infrastructure caller accessing `/api/analytics/admin/*` succeeds via adapted `isInfraRoute` without hitting `_verifyAdmin`.
7. **Regression Control 7 (Analytics Route + SHC Portal):** SHC caller accessing `/api/analytics/admin/*` is rejected fail-closed with HTTP 403 at proxy, never leaking into tenant DB.
8. **Regression Control 8 (Learner Token at Any Admin Route):** Learner token (`aud: 'user'`, `tokenType: 'user'`) rejected fail-closed at token verification before `_verifyAdmin` or DB query.
