## 1. Executive Summary & Objective

This specification establishes the source-backed, reviewable implementation scope for hardening the low-level tenant administrator authorization helper `_verifyAdmin` and reconciling its caller chain across both the API gateway proxy (`apps/api-server/src/proxy.ts`) and route-level helpers (`apps/api-server/src/modules/auth/admin-audience.util.ts`).

In accordance with accepted GUARD-02 architecture:
- `_verifyAdmin` is formally defined as a **tenant-local administrator authorization helper** (`brand: 'skillup' | 'realtutorialhub'`).
- It must enforce strict principal preconditions (canonical tenant brand, non-empty tenant subject, consistent admin token class, and scoped `admin` audience) fail-closed *before* executing any database queries.
- Before deploying strict helper enforcement, the API gateway proxy (`proxy.ts`) must undergo targeted routing adaptation so that valid non-tenant callers (such as infrastructure callers accessing `/api/factory` or `/api/analytics/admin`) are branched safely to their own permission checks and are never misrouted into tenant `_verifyAdmin`.

### Core Architectural Principles:
- **Least Privilege & Secure Defaults:** A token lacking explicit administrative class claims or audience must never obtain administrative authority, even if its database record holds administrative roles.
- **Separation of Concerns:** Tenant administrator verification (`_verifyAdmin`) is strictly decoupled from infrastructure authorization (`PERMISSIONS.ADMIN_PANEL`, `PERMISSIONS.ANALYTICS_VIEW`) and SkillHubCore governance (`hasSkillHubCoreAdminAccess`).
- **High Cohesion & Low Coupling:** Gateway routing (`proxy.ts`) and route-level guards (`admin-audience.util.ts`) maintain distinct, explicit branch boundaries without leaking SHC people IDs or infra roles into tenant RBAC tables.
- **Source-Backed Realism:** Distinguish observed source behavior from proposed policy. The external caller landscape remains UNKNOWN where unverified.

## 2. Caller Architecture: Gateway Proxy vs Route Guard Layers

To avoid conflation between layers, we distinguish the three distinct evaluation layers in `apps/api-server`:

1. **Layer 1: Gateway Proxy (`apps/api-server/src/proxy.ts:81-173`)**
   - Intercepts non-exempt, non-auth requests before Next.js route execution.
   - Evaluates `portalIdentity = request.headers.get('x-portal-identity') ?? 'user'`.
   - Derives `scope` (`'admin' | 'user' | 'infrastructure'`) and `expectedAudience` (`'admin' | 'user' | 'infra' | 'shc-admin'`) using both `portalIdentity` and `pathname`.
   - Executes `TokenService.verifyAdminAccessToken(_token, { audience: expectedAudience })` for admin/infra scopes.
   - Evaluates branch predicates:
     - `isShcAdminRoute`: `(pathname.startsWith('/api/admin') || pathname.startsWith('/api/factory')) && portalIdentity === 'shc-admin'`.
     - `isInfraRoute`: `pathname.startsWith('/api/admin') && portalIdentity === 'infrastructure'`.
     - `isAdminRoute`: `(pathname.startsWith('/api/admin') && !pathname.startsWith('/api/admin/auth') && portalIdentity !== 'infrastructure') || (pathname.startsWith('/api/factory') && portalIdentity !== 'shc-admin') || pathname.startsWith('/api/analytics/admin')` -> **invokes `_verifyAdmin(_payload)`**.
2. **Layer 2: Route-Level Guards & Handlers**
   - **`requireAdminRouteAccess(_req)` (`admin-audience.util.ts`):** Used across `/api/admin/*` and `/api/factory/*`. Calls `verifyAdminOrInfraToken(_req)` (enforcing audience matching `getAdminAudience(_req)`), then handles `shc-admin` in-memory, allows `infra` through via bypass, and calls `_verifyAdmin(payload)` for `admin` audience.
   - **Standalone Analytics Handlers (`apps/api-server/src/app/api/analytics/admin/*`):** These routes (e.g. `topic-skill-heatmap/route.ts:38`) do **not** call `requireAdminRouteAccess`. They invoke `TokenService.verifyAdminAccessToken(token)` **with no options**.
     - **Actual Verifier Behavior without Options (`packages/auth/src/token.service.ts:424-426`):** When `options?.audience` is omitted, the verifier does **not** default to `aud: 'admin'` and does **not** reject infra. Instead, it permits any token whose audience is either `'admin'` OR `'infra'` (`audValues.some(aud => aud !== 'admin' && aud !== 'infra')`), then asserts identity claims and requires `tokenType === 'admin'`.
     - **Route Cookie Extraction:** Calls `getAccessToken(req, { scope: 'admin' })`, which checks `admin_accessToken`, then falls back to `infra_accessToken`, then `Authorization: Bearer`.
     - **Route RBAC Check:** Enforces `RBACService.hasPermission(roles, PERMISSIONS.ANALYTICS_VIEW)`.
3. **Layer 3: Tenant Authorization Helper (`apps/api-server/src/modules/auth/rbac.service.ts:11-67`)**
   - `export async function _verifyAdmin(_payload: TokenPayload): Promise<boolean>`
   - Low-level helper that queries tenant `users` and `userRoles` tables in PostgreSQL.

## 4. Infrastructure Adaptation & Active-Account Policy Decision

### 4.1 The Security & Eligibility Trade-off
In current source:
- When an infrastructure caller accesses `/api/factory` or `/api/analytics/admin`, the request falls through `isAdminRoute` to `_verifyAdmin(_payload)`.
- Step 0 of `_verifyAdmin` queries the tenant database (`select isBlocked from users where id = _payload.userId`).
- If the user record is missing or `isBlocked === true`, access is denied fail-closed.
- **Architectural Risk:** If future adaptation in `proxy.ts` simply routes all infrastructure callers directly to `RBACService.hasPermission(roles, PERMISSIONS.ADMIN_PANEL)`, it would **silently eliminate the tenant active-account / blocked-account check** currently enforced on factory and analytics paths!

### 4.2 Explicit Policy Decision for Infrastructure Callers
1. **Option 1: Preserve Active-Account Eligibility via Dedicated Helper (SELECTED by Sol):**
   - Infrastructure tokens mapped to a tenant staff identity must still be verified as active (not blocked) in the tenant database before modifying factory content or viewing tenant analytics.
   - Implement a lightweight, non-privileged helper `_verifyActiveAccount(userId, brand)` that performs Step 0 without role fallback.
2. **Option 2: Token-Only Service Principal (NOT AUTHORIZED; requires a separate explicit architectural waiver):**
   - If infrastructure callers are strictly machine-to-machine background services that do not correspond to individual user rows in `users`, platform architecture must explicitly record this waiver: service tokens bypass tenant user row lookups and rely entirely on cryptographic signing, expiration, and role permissions (`ADMIN_PANEL`, `ANALYTICS_VIEW`).
3. **Preservation of Route-Specific Permissions:**
   - A gateway-level `ADMIN_PANEL` check must **never replace** route-specific permissions. Routes like `/api/analytics/admin/*` require `PERMISSIONS.ANALYTICS_VIEW`, and `/api/factory/*` routes require factory-specific authorizations. Both must remain enforced.

## 7. Target Policy Specification for `_verifyAdmin`

Once the gateway routing adaptation in Section 6 is implemented, `_verifyAdmin` executes as a strictly shielded helper:

1. **Canonical Tenant Brand:** Must strictly equal `'skillup'` or `'realtutorialhub'`. Any other brand (including `'skillhubcore'`) returns `false` fail-closed. Zero silent fallback to RTH.
2. **Non-Empty Tenant Subject:** `typeof _payload.userId === 'string' && _payload.userId.trim().length > 0`.
3. **Runtime Token Class Consistency:** `_payload.tokenType === 'admin'` AND `_payload.isAdmin === true`.
4. **Audience Specification:**
   - Scalar: strictly `'admin'`.
   - Array: must contain `'admin'`, permitted elements `['admin']` or `['admin', 'internal']`. Must NOT contain `'user'`, `'infra'`, or `'shc-admin'`.
5. **Account Lookup & Failure Semantics (Step 0):**
   - Query `users` table where `id === _payload.userId`.
   - If missing or `isBlocked === true`: return `false`.
   - If database query throws: catch error, log structured warning, return `false` (fail-closed).
6. **Obsolete Role Fallback Deprecation:**
   - Under `isAdmin === true` precondition, Step 2 (`userRoles` query) is dead code for valid tokens and is formally deprecated.

### 8.2 Regression Criteria Across All Combinations
1. **Control 1 (Admin Route + Admin Portal):** Legitimate tenant-admin succeeds via `_verifyAdmin`.
2. **Control 2 (Admin Route + Infra Portal):** Infrastructure caller succeeds via `isInfraRoute` and `requireAdminRouteAccess:infra`, bypassing `_verifyAdmin`.
3. **Control 3 (Admin Route + SHC Portal):** SHC admin succeeds via `isShcAdminRoute` and `requireAdminRouteAccess:shc-admin`, bypassing `_verifyAdmin`.
4. **Control 4 (Factory Route + Infra Portal):** Infrastructure caller accessing `/api/factory/save` succeeds via adapted `isInfraRoute` without hitting `_verifyAdmin`.
5. **Control 5 (Analytics Route + Infra Portal):** Infrastructure caller accessing `/api/analytics/admin/*` passes token verification and evaluates `ANALYTICS_VIEW` without hitting `_verifyAdmin`.
6. **Control 6 (Analytics Route + SHC Portal):** SHC caller accessing `/api/analytics/admin/*` is rejected fail-closed with HTTP 403 at proxy, never leaking into tenant DB.
7. **Control 7 (Legacy Path Caller without Header):** Admin caller navigating to `/api/admin/*` without `x-portal-identity` succeeds if presenting valid admin token.
8. **Control 8 (Learner Token at Any Admin Route):** Learner token (`aud: 'user'`, `tokenType: 'user'`) rejected fail-closed at token verification before `_verifyAdmin` or DB query.


## Sol final scope decision - 2026-11-04

GUARD-03 tenant-admin scoping is accepted subject to these implementation requirements,
which take precedence over illustrative snippets or table shorthand above:

- Select Option 1. Newly separated infra factory/analytics branches must retain the
  existing tenant-local missing/blocked-account and DB-error denial before authorization.
  Reuse one non-privileged account-eligibility reader in rbac.service.ts; do not copy
  that query into the proxy or introduce a parallel session engine. Canonical tenant
  brand and non-empty local subject must be validated before this lookup. No service-
  identity waiver is approved. Preserve the already-distinct /api/admin infra contract;
  do not silently extend new tenant DB checks into unrelated/default-DB service paths.
- Preserve actual handler authorization, including ANALYTICS_VIEW where present and
  requireAdminRouteAccess in the inspected factory/save route. Do not invent a
  FACTORY_MANAGE permission or infer every factory handler uses the same contract.
- Preserve missing-header path-based admin compatibility. Header selection chooses a
  verification contract; only verified signed claims plus eligibility/permissions grant
  access. A learner denial may occur at signature, audience or class validation; exact
  audience-error assertions require a cryptographically valid signature for that verifier.
- Shared tenant account eligibility and strict tenant-admin principal checks have
  different responsibilities. Strict admin preconditions must not be reused to deny
  legitimate infra classes before their separate eligibility/permission checks.

This closes the scoping ticket only with the learner-purpose scope. No production
helper/proxy change or security/runtime acceptance is granted by this document.
