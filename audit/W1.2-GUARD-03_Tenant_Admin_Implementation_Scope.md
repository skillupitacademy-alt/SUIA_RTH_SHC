## 1. Executive Summary & Objective

This specification establishes the minimal, reviewable runtime assignment for hardening the low-level tenant admin authorization helper `_verifyAdmin` and reconciling its call chain (`requireAdminRouteAccess`, `verifyAdminOrInfraToken`, and API server `proxy.ts`).

In accordance with the accepted GUARD-02 architecture contract, `_verifyAdmin` is formally defined as a **tenant-local administrator authorization helper**. It must enforce strict principal preconditions (brand validity, non-empty tenant subject, token class consistency, and audience scoping) fail-closed *before* executing any database queries.

### Guiding Principles Applied:
- **Least Privilege & Secure Defaults:** A token lacking explicit administrative class claims or audience must never obtain administrative authority, even if the database record holds administrative roles.
- **Separation of Concerns:** Tenant administrator verification (`_verifyAdmin`) is decoupled from infrastructure access (`verifyAdminOrInfraToken`) and SkillHubCore governance (`hasSkillHubCoreAdminAccess`).
- **High Cohesion & Low Coupling:** Gateway routing (`proxy.ts`) and route-level helpers (`admin-audience.util.ts`) maintain explicit branch boundaries without leaking SHC people IDs or infra roles into tenant RBAC tables.

## 2. Actual Source Call Graph & Current Invariants

### 2.1 Low-Level Helper (`apps/api-server/src/modules/auth/rbac.service.ts:11-67`)
```ts
export async function _verifyAdmin(_payload: TokenPayload): Promise<boolean>
```
1. **Current Vulnerabilities & Defects:**
   - **Silent Brand Fallback:** `const brand = _payload.brand === 'skillup' ? 'skillup' : 'realtutorialhub';` silently coerces any foreign, malformed, or missing brand (including `'skillhubcore'`) to `'realtutorialhub'`. This risks querying SHC `db-people` identifiers against the RTH PostgreSQL tenant database.
   - **Missing Class & Audience Checks:** `_verifyAdmin` does not inspect `_payload.aud` or `_payload.tokenType`.
   - **Database Fallback Elevation:** If an active learner (`aud: 'user'`, `tokenType: 'user'`, `isAdmin: false`) is granted an admin role in the database, Step 0 passes (account active), Step 1 is bypassed, and Step 2 (`userRoles` query) returns `true`. If `_verifyAdmin` were called directly without gateway shielding, a learner token would be treated as an administrative token.
   - **Asymmetric Exception Handling:** Step 0 catches DB errors and returns `false`. Step 2 is outside the try/catch block and propagates uncaught database exceptions.

### 2.2 Caller 1: Route-Level Guard (`apps/api-server/src/modules/auth/admin-audience.util.ts`)
- `getAdminAudience(_req)`:
  ```ts
  const portalIdentity = _req.headers.get('x-portal-identity') ?? 'admin';
  if (portalIdentity === 'shc-admin') return 'shc-admin';
  return portalIdentity === 'infrastructure' ? 'infra' : 'admin';
  ```
- `verifyAdminOrInfraToken(_req, token?)`:
  - Retrieves token scoped to `scope: 'admin'`.
  - Executes `TokenService.verifyAdminAccessToken(scopedToken, { audience: expectedAud })`.
  - Enforces cryptographic validity, expiration, and audience match (`expectedAud`).
- `requireAdminRouteAccess(_req)`:
  - Calls `verifyAdminOrInfraToken(_req)`.
  - If `audience === 'shc-admin'`: checks `brand === 'skillhubcore' && isAdmin === true && roles.includes(...)` in-memory. Does NOT call `_verifyAdmin`.
  - If `audience === 'infra'`: **bypasses `_verifyAdmin` completely** and returns `payload` directly.
  - If `audience !== 'infra'` (i.e. `audience === 'admin'`): calls `await _verifyAdmin(payload)`.

### 2.3 Caller 2: API Gateway Proxy (`apps/api-server/src/proxy.ts:81-173`)
- Evaluates `portalIdentity = request.headers.get('x-portal-identity') ?? 'user'`.
- Scopes token to `'admin'` or `'infrastructure'` based on `portalIdentity` and route path.
- Verifies token via `TokenService.verifyAdminAccessToken(token, { audience: expectedAudience })`.
- Explicit branch routing:
  - `isShcAdminRoute`: validates SHC brand and roles in-memory. Does NOT call `_verifyAdmin`.
  - `isInfraRoute`: validates `RBACService.hasPermission(roles, PERMISSIONS.ADMIN_PANEL)`. Does NOT call `_verifyAdmin`.
  - `isAdminRoute`: invokes `await _verifyAdmin(_payload)`. Fails with HTTP 403 if `false`.

## 3. Compatibility & Routing Adaptation Analysis

### 3.1 Does Any Infra Path Reach `_verifyAdmin`?
- **Analysis:**
  - In `apps/api-server/src/proxy.ts`, `isInfraRoute` is evaluated at line 148, ahead of `isAdminRoute` at line 158. Infra requests execute the `RBACService.hasPermission` check and do not fall through to `_verifyAdmin`.
  - In `apps/api-server/src/modules/auth/admin-audience.util.ts`, `requireAdminRouteAccess` explicitly branches:
    ```ts
    } else if (audience !== 'infra') {
      const hasAdminAccess = await _verifyAdmin(payload);
    ```
    Infra tokens (`audience === 'infra'`) bypass `_verifyAdmin`.
- **Finding:** Currently, no production route passes `aud: 'infra'` into `_verifyAdmin`.
- **Routing Adaptation Requirement:**
  - Before strictly enforcing `aud === 'admin'` in `_verifyAdmin`, we must ensure that no route handler invokes `_verifyAdmin` directly on an infra-scoped request without setting `x-portal-identity: infrastructure`.
  - All existing admin route handlers in `apps/api-server/src/app/api/admin/...` use `requireAdminRouteAccess(_req)`.
  - If an infra caller accesses a route protected by `requireAdminRouteAccess` with `x-portal-identity: infrastructure`, it is handled safely by the `audience === 'infra'` bypass.
  - To prevent privilege confusion, `_verifyAdmin` must reject `aud: 'infra'` fail-closed.

### 3.2 Does Any SHC Path Reach `_verifyAdmin`?
- **Analysis:**
  - In `proxy.ts`, `isShcAdminRoute` branches at line 133 and terminates with 403 or passes without calling `_verifyAdmin`.
  - In `requireAdminRouteAccess`, `audience === 'shc-admin'` branches at line 64 and returns without calling `_verifyAdmin`.
- **Finding:** No valid SHC path reaches `_verifyAdmin`. If an SHC token presents at a tenant admin route without `x-portal-identity: shc-admin`, `_verifyAdmin` must immediately reject it fail-closed based on `brand !== 'skillup' && brand !== 'realtutorialhub'`.

## 4. Target Policy Specification for `_verifyAdmin`

The hardened helper must execute strict precondition checks before performing any database query:

```mermaid
flowchart TD
    Start([_verifyAdmin(payload)]) --> CheckBrand{Canonical Brand?<br/>skillup or realtutorialhub}
    CheckBrand -- No --> DenyFailClosed[Return false<br/>Log warning: invalid_brand]
    CheckBrand -- Yes --> CheckSubject{Non-Empty Subject?<br/>userId trimmed > 0}
    CheckSubject -- No --> DenyFailClosed
    CheckSubject -- Yes --> CheckClass{Consistent Class?<br/>tokenType === 'admin' &<br/>isAdmin === true}
    CheckClass -- No --> DenyFailClosed
    CheckClass -- Yes --> CheckAudience{Valid Audience?<br/>scalar 'admin' or<br/>['admin', 'internal']}
    CheckAudience -- No --> DenyFailClosed
    CheckAudience -- Yes --> Step0{Step 0: DB Account Active?<br/>select isBlocked from users}
    Step0 -- Missing or Blocked --> DenyFailClosed
    Step0 -- DB Throws --> CatchError[Catch error -> Return false]
    Step0 -- Active & Not Blocked --> Step1[Step 1: Fast Path<br/>isAdmin === true]
    Step1 --> GrantAccess([Return true])
```

### 4.1 Precondition Rules (Evaluated in Order)

1. **Canonical Tenant Brand:**
   - Must strictly equal `'skillup'` or `'realtutorialhub'` (lowercase string).
   - Any other value (`'skillhubcore'`, empty string, null, undefined, unknown brand) immediately returns `false`.
   - **Zero silent fallback** to `'realtutorialhub'`.

2. **Non-Empty Tenant-Local Subject:**
   - `typeof _payload.userId === 'string' && _payload.userId.trim().length > 0`.
   - Empty, whitespace, null, or non-string `userId` returns `false` before database access.

3. **Runtime Token Class Consistency:**
   - `_payload.tokenType` must strictly equal `'admin'`.
   - `_payload.isAdmin` must strictly equal boolean `true`.
   - Any contradictory claim (`tokenType: 'user'` with `isAdmin: true`, or `tokenType: 'admin'` with `isAdmin: false`) immediately returns `false`.

4. **Audience Specification:**
   - **Scalar:** Must strictly equal `'admin'`.
     - Reject `'user'`, `'infra'`, `'shc-admin'`, empty string, null, undefined.
   - **Array Audience:**
     - All elements must be non-empty strings.
     - Must include `'admin'`.
     - Permitted array elements: `['admin']` or `['admin', 'internal']` (order immaterial).
     - Must NOT contain `'user'`, `'infra'`, `'shc-admin'`, or unknown strings.
     - Empty array returns `false`.

5. **Account Lookup & Failure Semantics (Step 0):**
   - Query `users` table in `authContext.tables.users` where `id === _payload.userId`.
   - If `_users.length === 0`: return `false` (user does not exist in tenant DB).
   - If `_users[0].isBlocked === true`: return `false` (user account blocked).
   - If database query throws: catch error, log structured error, return `false` (fail-closed).

6. **Fast-Path & Obsolete Role Fallback (Steps 1 & 2):**
   - Under the hardened precondition `isAdmin === true`, once Step 0 verifies the user is active, Step 1 (`if (isAdminInToken === true) return true;`) immediately returns `true`.
   - **Step 2 (`userRoles` query) becomes dead code** for valid tokens. Tokens with `isAdmin === false` are rejected at preconditions and never reach Step 2.
   - Step 2 should be formally marked deprecated or safely removed in the implementation patch to eliminate the uncaught exception risk.

   - Learner token (`aud: 'user'`, `tokenType: 'user'`, `isAdmin: false`) -> returns `false`.

   - Infra token (`aud: 'infra'`, `tokenType: 'admin'`, `isAdmin: true`) -> returns `false`.

   - Empty/whitespace subject (`userId: '   '`) -> returns `false`.
   - Contradictory array audience (`aud: ['admin', 'user']`) -> returns `false`.
3. **Database State Controls:**
   - Non-existent user ID in DB -> returns `false`.
   - Blocked user (`isBlocked: true`) -> returns `false`.
   - DB query exception during Step 0 -> caught and returns `false`.

## 6. Rollout & Compatibility Risks

1. **Risk:** Legacy administrative tokens minted before strict class enforcement might lack `tokenType`.
   - **Mitigation:** Inspect `TokenService.generateTokens`. All tokens minted across the codebase include `tokenType: isAdmin ? 'admin' : 'user'`.
2. **Risk:** Infrastructure routes calling `_verifyAdmin` directly.
   - **Mitigation:** Confirmed that infrastructure calls route via `requireAdminRouteAccess` (which bypasses `_verifyAdmin`) or `proxy.ts` (which checks `PERMISSIONS.ADMIN_PANEL`). Neither passes infra tokens to `_verifyAdmin`.
3. **Direct Helper Weakness vs Reachable Exploit:**
   - Although `_verifyAdmin` in isolation fails open for promoted learner tokens, the gateway proxy (`proxy.ts:122`) and route verifier (`admin-audience.util.ts:40`) currently reject learner tokens via `verifyAdminAccessToken({ audience: 'admin' })` *before* reaching `_verifyAdmin`.
   - Hardening `_verifyAdmin` provides defense-in-depth against direct unshielded invocations.
