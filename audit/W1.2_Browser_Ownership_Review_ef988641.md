## 1. Exit cleanup bypasses marker refusal

SafeQualificationReporter.onEnd first invokes safeCleanupRunDirectory, but then always
registers process.once('exit'). That callback recursively deletes ownedOutputDir when
lexically beneath parentDir and containing only .last-run.json (or nothing). It does
NOT validate the run ID/token/marker or ancestor links. It runs even when the validated
cleanup refused an unowned directory. The 'harmless terminal metadata' case must not
become a second, weaker deletion authority.

Sol executed the actual reporter on a private temp parent/foreign-run/.last-run.json,
with a deliberately absent ownership marker and mismatched token. process.once was
intercepted to capture the callback; fs.rmSync was intercepted before any deletion.
Invoking the exit callback attempted removal of the unowned directory: TRUE. Fake file
preserved: TRUE. Probe exit 0. Only the private probe file and directories were then
removed with exact nonrecursive operations. Existing workspace reports were untouched.

Minimal fix: remove the unvalidated exit hook. It is acceptable to retain non-sensitive
.last-run.json metadata in an isolated run directory and state this honestly, rather
than weaken cleanup solely to claim 'zero artifacts'. If terminal cleanup is retained,
every deletion must use the same validated ownership boundary; no lexical exception.
No raw-secret artifact may be retained under the guise of harmless metadata.

## 2. Allocation may overwrite an existing run's ownership

allocateOrValidateRunDirectory(create=true) checks a run ID, then reuses an existing
directory and writes/overwrites .auth-run-ownership.json with the supplied/new token.
It does not prove existing ownership before overwriting. A valid-looking RUN_ID can
claim an existing run beneath the fixed parent and Playwright may clean that directory
before tests run. Random default allocation is unique, but explicit/reused IDs are not.

Create a fresh run directory atomically; on existence, reject unless its existing
marker/run/token are validated against the caller's expected allocation. Do not read
an arbitrary existing marker token and call that caller authority. Do not rewrite
foreign or mismatched markers. Child runs must allocate their own ID rather than
inherit/claim the parent's run. Keep configuration validation before runner cleanup.
The parentDir test override is not a production config escape; keep it limited to
explicit isolated test allocations and do not expose arbitrary deletion roots via env.
