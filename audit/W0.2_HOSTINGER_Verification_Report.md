Failure during repository validation or dirty source detection cannot leave stale success receipts.

In addition, non-interactive pipeline execution support (`-NonInteractive`, `-Yes`, and `$env:NON_INTERACTIVE`) was added to `deploy-smart.ps1` with fail-closed semantics for lint/type errors.

## 4. Key Fixes Applied During Final Verification

1. **PowerShell `Start-Process` Win32 Compatibility**:
   - In `enforce-shc-quality-gate.ps1`, changed from `Start-Process -FilePath "pnpm"` (which threw `%1 is not a valid Win32 application` on Windows due to `pnpm.cmd` batch script wrapping) to `Push-Location $RepositoryRoot; & $gateCommand @gateArgs; $exitCode = $LASTEXITCODE; Pop-Location`. Works uniformly across Windows and Linux.
2. **Ambiguous `-o` Parameter in Stubs**:
   - In test stubs, removed `param([Parameter(ValueFromRemainingArguments)]$Args)` which caused PowerShell to misinterpret `docker save -o` as ambiguous common parameter `-OutVariable` / `-OutBuffer`. Simple `$args` array access resolved this cleanly.
3. **Non-Interactive Execution Support**:
   - Added `[switch]$NonInteractive` and `[switch]$Yes` parameters in `deploy-smart.ps1`, as well as checking `$env:NON_INTERACTIVE -eq '1'`. Allows automated execution in CI/headless runners while preserving fail-closed behavior on lint/type errors.
