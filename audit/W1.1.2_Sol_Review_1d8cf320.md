## Source findings confirmed by Sol

- Existing GET/DELETE /api/auth/sessions and DELETE
  /api/auth/sessions/[sessionId] routes call GlobalLogoutService. The device UI
  is not evidence that backend routes are absent; the investigation missed them.
- GlobalLogoutService.revokeSession calls revokeById(sessionId) at line 113.
  TokenRepository.revokeById conditionally includes userId only if supplied.
  The route obtains userId from the token, but that ownership value is dropped
  at the repository call. This is a demonstrated missing ownership predicate;
  end-to-end exploitability has not been executed against a live system.
- A separate POST /api/auth/logout-all imports the generic injected-repository
  SessionService. The container lazily calls new token() with no arguments, so
  an unresolved generic repository is a genuine source wiring concern. Do not
  infer deployed reachability or execution from this source observation alone.
- TokenRefreshService verifies the refresh JWT later, after looking up the hash
  and updating last-used state. Tracing its claim/session/tenant consistency is
  warranted. Hash-only lookup of a high-entropy token is not itself evidence of
  cross-user vulnerability; identify the missing authority comparison and the
  full route/guard/rotation path before claiming an exploit.
