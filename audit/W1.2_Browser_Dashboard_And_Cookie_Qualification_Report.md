## 7. Resolution of PROXY-01: Local Learner Login Redirect Scope

During the initial review, Sol identified that unauthenticated requests to `/dashboard` on local development hosts redirected to production origins (`https://user.skillupitacademy.com/login` and `https://user.realtutorialhub.com/login`) because `NEXT_PUBLIC_LOGIN_URL` was unset and the proxies hardcoded production fallbacks.

- **Resolution (commit `a8fb0772`):**
  - Updated [`apps/skillup-web/src/proxy.ts`](file:///E:/onlinewebsites/quiz-platform/apps/skillup-web/src/proxy.ts) and [`apps/realtutorialhub-web/src/proxy.ts`](file:///E:/onlinewebsites/quiz-platform/apps/realtutorialhub-web/src/proxy.ts) to omit the hardcoded production fallback when `NEXT_PUBLIC_LOGIN_URL` is unset.
  - The underlying `createAuthProxy` helper in `src/share-branding/middleware/authProxy.ts` already correctly resolves `new URL('/login', request.url)` when `brandLoginUrl` is omitted.
  - Exported `isPublicAuthRoute` from both entrypoints.
- **Verification:**
  - `apps/skillup-web/src/__tests__/proxy.test.ts`: 5 passed.
  - `apps/realtutorialhub-web/src/__tests__/middleware.test.ts`: 8 passed.
  - Live server verification: HTTP GET to `http://skillup.localhost:3009/dashboard` returns HTTP 307 with `location: /login?redirect=%2Fdashboard` (resolving against `http://skillup.localhost:3009`).
  - Chromium browser tests: unauthenticated navigation to `/dashboard` resolves to `http://skillup.localhost:3009/login?redirect=%2Fdashboard` and `http://realtutorialhub.localhost:3003/login?redirect=%2Fdashboard`.
