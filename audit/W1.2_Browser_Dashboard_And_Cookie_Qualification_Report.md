## 7. Architectural Defect Discovery: Next.js 16 Proxy Unauthenticated Redirect

During source tracing and execution of Tasks A and B, a boundary defect was discovered in the Next.js 16 proxy configuration:

- **Source Locations:**
  - [`apps/skillup-web/src/proxy.ts`](file:///E:/onlinewebsites/quiz-platform/apps/skillup-web/src/proxy.ts#L3) (line 3): `const LOGIN_URL = process.env.NEXT_PUBLIC_LOGIN_URL ?? 'https://user.skillupitacademy.com/login';`
  - [`apps/realtutorialhub-web/src/proxy.ts`](file:///E:/onlinewebsites/quiz-platform/apps/realtutorialhub-web/src/proxy.ts#L3) (line 3): `const LOGIN_URL = process.env.NEXT_PUBLIC_LOGIN_URL ?? 'https://user.realtutorialhub.com/login';`
- **Observed Behavior:**
  When an unauthenticated request hits a protected route (`/dashboard`), `createAuthProxy` invokes `getLoginUrl(request, redirectPath, options.brandLoginUrl)`. Because `NEXT_PUBLIC_LOGIN_URL` is unset in the local environment, the fallback hardcodes an absolute production URL (`https://user.skillupitacademy.com/login` / `https://user.realtutorialhub.com/login`). The server responds with HTTP 307 pointing to production.
- **Safety Interception:**
  In a real browser, following this redirect takes the user out of the local development/test environment onto the public production domain. In our qualification harness, `installNetworkOriginGuard` in [`tests/e2e/auth-qualification/helpers/readiness.ts`](file:///E:/onlinewebsites/quiz-platform/tests/e2e/auth-qualification/helpers/readiness.ts) intercepted this outgoing production request and aborted it fail-closed with `net::ERR_BLOCKED_BY_CLIENT`.
- **Engineering Principle Violation:**
  Violates Brand Isolation, Separation of Concerns, and KISS. Local requests should redirect relatively (`/login`) or resolve against the active request host (`http://skillup.localhost:3009/login`), rather than hardcoding production hostnames.
- **Recommended Follow-up Ticket:**
  `W1.2-PROXY-01: Next.js Proxy Unauthenticated Redirect Local Host Scope Correction`. Update `LOGIN_URL` to fallback to relative `'/login'` or `new URL('/login', request.url)`. Since runtime code edits were prohibited during this qualification batch, this was not changed.
