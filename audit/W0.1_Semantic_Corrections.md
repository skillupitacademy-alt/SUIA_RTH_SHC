## Defects Corrected

### 1. RTH-ILS-009: Block Visit Accepts Unknown Block Identity

**Previous Mapping (INCORRECT):**
- Primary Root Cause: RC-EVENT-01 (Event reliability)
- Description: "telemetry retry and deduplication issue"

**Actual Finding (Lines 26699-26720):**
> In `learning-progress.service.ts`, lines 636–680, `recordBlockVisit()` looks up the requested block in the tutorial content. When the block is not found, `expectedTimeSec` remains `null`, but the method still calls the repository's `upsert()`. This can record visits for block identities that do not exist in the retrieved content.

**Corrected Mapping:**
- **Primary Root Cause:** RC-TUTORIAL-01 (Tutorial/progress model)
- **Related Root Causes:** RC-CONTRACT-01 (Contract drift)
- **Description:** "Block visit accepts unknown block identity; recordBlockVisit() persists visits for non-existent blocks"
- **Notes:** "When block not found in tutorial content, expectedTimeSec remains null but repository upsert() still executes; can record visits for block identities that don't exist in canonical content"

**Rationale:** This is a tutorial content validation issue, not an event reliability issue. The service fails to enforce canonical block identity before persisting progress data.

### 2. RTH-ILS-010: Missing Content Can Produce Zero Completion Requirements

**Previous Mapping (INCORRECT):**
- Primary Root Cause: RC-EVENT-01 (Event reliability)
- Description: "telemetry failure handling issue"

**Actual Finding (Lines 26759-26780):**
> In `learning-progress.hierarchy-resolution.ts`, lines 60–62, `resolveRequiredBlocks()` returns an empty array if a section or its block content is unavailable. The service subsequently evaluates the completion policy using that array. For an intended instructional page, an empty required-block set may be legitimate; for a missing or malformed published document, it may represent a content-integrity failure. We must distinguish those cases explicitly.

**Corrected Mapping:**
- **Primary Root Cause:** RC-TUTORIAL-01 (Tutorial/progress model)
- **Related Root Causes:** RC-CONTRACT-01 (Contract drift)
- **Description:** "Missing content can produce zero completion requirements; resolveRequiredBlocks() returns empty array for unavailable sections"
- **Notes:** "Service evaluates completion policy using that empty array; must distinguish legitimate block-free content from missing/malformed published documents; safe policy rejects invalid published content"

**Rationale:** This is a tutorial content contract issue where missing content masquerades as complete content. The completion model fails to distinguish intentional empty content from content-integrity failures.
