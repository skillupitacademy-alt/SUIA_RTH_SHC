- **Invariants Verified:**
  1. Identical email (`learner@example.test`) and colliding local user ID (`'100'`) authenticate independently against their respective in-memory tenant stores.
  2. SUIA credentials authenticate against SUIA store only and resolve SUIA profile.

  7. Fixture sensitivity check confirms that wrong-store adapter routing is detected and fails.

### 2.2 Task E: FIXTURE-02 (Real Admin-Guard Principal Boundary)
```bash
node node_modules/vitest/vitest.mjs run --dir apps/api-server/src/modules/auth/__tests__ fixture-02-admin-guard.test.ts
```
- **Passed:** 10/10 tests in 23ms.
- **Invariants Verified:**
  1. Legitimate tenant admin token passes cryptographic check and Step 0 active check in tenant DB.
  2. Correctly signed learner token is rejected fail-closed at cryptographic token verification *before* any database query is executed (DB queries = 0).
  3. Promoted learner account (possessing `admin` role in database) presenting an in-flight learner token is rejected at the token boundary; the database role query is never reached (`mockSelectRoles` called 0 times).
  4. Missing tokens throw `unauthorized('Unauthorized')`.
  5. Invalid signature / forged tokens throw cryptographic verification errors.
  6. Incompatible audience (`aud: 'shc-admin'` at tenant admin route) throws `Audience mismatch`.
  7. Valid SHC admin token with `x-portal-identity: shc-admin` is evaluated in-memory under its distinct contract and bypasses `_verifyAdmin`.
  8. SHC admin token lacking admin roles throws `forbidden`.
  9. Valid infra token with `x-portal-identity: infrastructure` passes under its distinct infra contract.
  10. Blocked admin in tenant DB throws `forbidden('Admin access only')`.
