## 1. Architectural Trust Boundaries & Header Overwrite Matrix

In accordance with `audit/FinalAechitecture.md`, the platform comprises three primary network execution boundaries:
1. **Client / Browser Boundary:** Untrusted public ingress. Authenticates via HTTP-only cookies (`accessToken`, `refreshToken`, `admin_accessToken`, `admin_refreshToken`).
2. **Edge BFF / Cloudflare Gateway Boundary (`workerd:8787` / `proxy.ts`):** Validates incoming credentials, establishes request brand (`x-brand`) and public host (`x-original-host`), strips hop-by-hop headers, and signs or attaches internal transit credentials.
3. **Internal API Server Boundary (`localhost:3000`):** Enforces route-level RBAC, tenant database connection isolation (`skillup` vs `realtutorialhub` vs `skillhubcore`), and validates service-to-service secrets.

### Distinct Internal Header & Secret Mapping

The system utilizes three distinct internal secrets that must not be conflated:

| :--- | :--- | :--- | :--- |
| `x-internal-key` | `apps/api-server/src/proxy.ts` (lines 99, 102) | `process.env.INTERNAL_API_KEY` | Proxy-level system bypass key. Evaluated before token checks. If matches, sets `isSystemBypass = true`. **Defect noted:** When invalid, proxy unsets bypass and downshifts to user token evaluation. |
| `x-internal-secret` | `apps/api-server/src/middleware/internal-auth.middleware.ts` (lines 28-35), `apps/api-server/src/middleware/gateway-auth.middleware.ts` (lines 35-42) | `process.env.INTERNAL_API_SECRET` | Service-to-service internal RPC secret. Validated with constant-time equality check; sets `authMode: 'internal'`. Direct caller without this secret receives 401/403. |

## 2. Route Reachability, Exemption Pipeline & CSRF Interactions

A critical security architectural distinction exists between **Pipeline Execution** (`proxy.ts` -> route middleware -> handler) and **Direct Route Invocation**:

### The Gateway Exemption Pipeline (`apps/api-server/src/proxy.ts`)

In `apps/api-server/src/proxy.ts`:
- **Line 61-69 (`isGatewayExemptRoute`):** Routes matching `/api/health`, `/api/workflows`, `/api/auth`, `/api/tutorial`, `/api/search`, `/api/telemetry`, `security/report`, or `/api/logs/client` bypass the proxy's token enforcement at line 81 (`if (!isAuthRoute && !isGatewayExemptRoute)`).
- **Line 72-79 (CSRF Mutation Guard):**
  ```ts
  if (!isAuthRoute) {
    if (!isSecurityReport && !isWorkflowRoute) {
      const csrfResponse = await csrfProtection(request);
      if (csrfResponse !== null && csrfResponse !== undefined) {
        return corsMiddleware(request, csrfResponse);
      }
    }
  }
  ```

### CSRF Handling on Exempt Tutorial Mutations (`POST /api/tutorial/progress`)

- Although `/api/tutorial` is exempt from proxy token enforcement via `isGatewayExemptRoute`, it **is NOT exempt from CSRF protection**!
- Any `POST /api/tutorial/progress` request passing through the proxy must provide a valid CSRF cookie and matching `x-csrf-token` header; otherwise, line 75 rejects the mutation with HTTP 403 Forbidden.
- Once CSRF validation passes (or if the route is reached directly), the request reaches `POST` in `apps/api-server/src/app/api/tutorial/progress/route.ts`.
- Under the B08-E bounded containment, `route.ts` line 187 calls `authenticateLearnerRequest(request)` before reading the request body or executing store operations, ensuring cryptographic token attestation occurs regardless of proxy exemption.

## 3. Absent Tenant Discriminators & Colliding-ID Vulnerabilities

Multi-tenancy isolation in the repository relies on database connection switching (`getAuthBrandContext`), but several tables and routes lack an explicit brand discriminator column in their schema:

| Table / Route / Entity | Missing Discriminator Column | Primary Key / Lookup Key | Risk / Exploit Preconditions | Architectural Invariant Required |
| :--- | :--- | :--- | :--- | :--- |
| `jobs` table (`JobsService`) | Missing `brand` column | `jobId` (UUID/string) | If an export job is created with `userId: 'user-100'`, an attacker on another tenant who also possesses local ID `'user-100'` can query or download the artifact. | Job records must store `brand` or enforce global UUID uniqueness across all tenants. |
| `exams` table (`exams.exportUrls`) | Missing tenant column | `examId` (string) | Direct lookup by `examId` only checks `exam.userId === payload.userId`. If local IDs collide across brands, cross-brand access succeeds. | Exam lookups must include brand context or tenant foreign keys. |
| `export/download/route.ts` | No tenant verification in handler | `jobId` or `examId` | Lines 53 and 76 check `job.userId !== payload.userId` and `exam.userId !== payload.userId`, but do NOT check `payload.brand`. | Handler must verify `job.brand === payload.brand` and `exam.brand === payload.brand`. |
| `tutorial_progress` table (`TutorialProgressRepository`) | Missing `brand` column in raw table schema | `(userId, subtopicId)` | Progress entries stored by composite `(userId, subtopicId)` without brand partition. In B08-E containment, `route.ts` derives brand from verified token and passes `brandId` to `TutorialService`. | Repository and table schema must include explicit `brand` partition column. |
