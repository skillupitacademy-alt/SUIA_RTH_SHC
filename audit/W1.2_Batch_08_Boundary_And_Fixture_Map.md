## 1. Architectural Trust Boundaries & Header Overwrite Matrix

In accordance with `audit/FinalAechitecture.md`, the platform comprises three primary network execution boundaries:
1. **Client / Browser Boundary:** Untrusted public ingress. Authenticates via HTTP-only cookies (`accessToken`, `refreshToken`, `admin_accessToken`, `admin_refreshToken`).
2. **Edge BFF / Cloudflare Gateway Boundary (`workerd:8787` / `proxy.ts`):** Validates incoming credentials, establishes request brand (`x-brand`) and public host (`x-original-host`), strips hop-by-hop headers, and signs or attaches internal transit credentials.
3. **Internal API Server Boundary (`localhost:3000`):** Enforces route-level RBAC, tenant database connection isolation (`skillup` vs `realtutorialhub` vs `skillhubcore`), and validates service-to-service secrets (`INTERNAL_API_SECRET`, `GATEWAY_TRUST_SECRET`).

### Header Validation & Overwrite Authority

| Header | Ingress Origin | Intermediate Layer Handling | Upstream API Layer Handling | Vulnerability / Drift Notes |
| :--- | :--- | :--- | :--- | :--- |
| `x-user-id` | Client (untrusted) | Set by Gateway after JWT verification (`sub`/`userId`). | Trusted by certain legacy endpoints (`/api/tutorial/progress`) without independent signature re-verification. | **Critical Risk (B08-E):** If route is called directly or bypasses Gateway JWT check, attacker can forge subject. |
| `x-brand` | Client (untrusted) | Resolved from Host/platform header by BFF/Gateway. | Used to bind database schema/pool. Fallback to default in legacy routes (`realtutorialhub`). | Must strictly match authenticated token's signed `brand` claim. |
| `x-internal-secret` | Client (untrusted) | Injected by BFF/Gateway for internal S2S calls. | Validated against `INTERNAL_API_SECRET` in `internal-auth.middleware.ts` and `gateway-auth.middleware.ts`. | If invalid, must fail closed without fallback to untrusted bearer/cookie credentials. |
| `x-gateway-secret` | Client (untrusted) | Injected by Gateway for verified edge calls. | Validated against `GATEWAY_TRUST_SECRET` in `internal-auth.middleware.ts`. | Must fail closed if forged or mismatched. |
| `x-portal-identity` | Client (untrusted) | Carried in client requests (`user`, `admin`, `shc-admin`, `infrastructure`). | Read by `proxy.ts` to choose audience scope (`user` vs `admin` vs `shc-admin` vs `infra`). | **Security Boundary:** Header claim alone CANNOT elevate privilege; token cryptographic verification against `expectedAudience` must succeed. |

## 2. Route Reachability: Middleware-Plus-Route vs Direct Route Invocation

A critical distinction exists in Next.js between **Direct Route Handler Invocation** (unit/integration test importing and calling `GET(req)` or `POST(req)`) and **Reachable Pipeline Execution** (`proxy.ts` middleware -> route middleware wrapper -> route handler):

1. **Proxy Interception (`apps/api-server/src/proxy.ts`):**
   - Applies to `/api/*` except `isGatewayExemptRoute` (`/api/tutorial`, `/api/health`, `/api/workflows`, `/api/auth`, `/api/search`, `/api/telemetry`).
   - For non-exempt routes, enforces CSRF for mutations and token verification via `TokenService.verifyUserAccessToken` / `verifyAdminAccessToken`.
   - **Exemption Gap:** Because `/api/tutorial` is explicitly listed in `isGatewayExemptRoute` (lines 51, 65 of `proxy.ts`), requests to `/api/tutorial/progress` bypass `proxy.ts` token enforcement entirely!
2. **Direct Handler Invocation:**
   - Routes like `/api/tutorial/progress/route.ts` extract `req.headers.get('x-user-id')` directly. When invoked directly in tests without mock middleware, or when reached via exempt proxy path, unvalidated headers are accepted.
3. **Internal Auth Middleware (`withGatewayAuth`, `validateRequest`, `blockDirectAccess`):**
   - Routes wrapping handlers with `withGatewayAuth` or calling `validateRequest` reject requests lacking valid transit secrets. Routes omitting these wrappers are exposed.
