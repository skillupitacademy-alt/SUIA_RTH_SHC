## 2. Detailed Technical Corrections

### 2.1 Connected Tenant Fixture Repair
- **File**: [`apps/api-server/src/modules/auth/__tests__/global-logout.service.tenant-isolation.test.ts`](file:///E:/onlinewebsites/quiz-platform/apps/api-server/src/modules/auth/__tests__/global-logout.service.tenant-isolation.test.ts)
- **Problem**: In commit `b1bf6656`, `getAuthBrandContext` returned `tables.refreshTokens` as a string literal (`'mock_refresh_tokens_table'`). When `TokenRepository.revokeById` evaluated `this.refreshTokensTable.id`, it resolved to `undefined`, causing the predicate to stringify as `'undefined'`. Consequently, zero rows were updated in the test adapter, causing 3/3 tests to fail.
- **Solution**:
  1. Declared hoisted schema objects:
     ```typescript
     const rthTable = { id: 'rth_refresh_tokens.id', userId: 'rth_refresh_tokens.userId' };
     const suiaTable = { id: 'suia_refresh_tokens.id', userId: 'suia_refresh_tokens.userId' };
     ```
  2. Enhanced `TenantFixtureAdapter` to validate that the SQL predicate contains exactly 2 conditions, requires operator `eq`, and only permits fields `id` and `userId`. Unknown operators and fields throw immediate errors.
  3. Tracked `updateCalls` on each adapter to prove that the selected brand table was updated while the opposing tenant adapter received zero update calls.
  4. Explicitly instantiated real `TokenRepository` and real `GlobalLogoutService` rather than passing `undefined` to fallback on the global container.
- **Result**:
  ```text
   ✓ src/modules/auth/__tests__/global-logout.service.tenant-isolation.test.ts (3 tests) 6ms
  ```

  4. Formed a disposable mutant by removing ONLY `, eq(this.refreshTokensTable.userId, userId)`, retaining runtime validation of the supplied actor identity.

  6. Verified that the mutant permits User A to wrongfully revoke User B's session (`revoked === true`), demonstrating sensitivity to the omitted owner predicate.
  7. Verified that the unmodified production code fails closed and leaves User B's session untouched (`revoked === false`).

## 3. Engineering Acceptance Evidence Matrix

| Principle | Architectural Application | Source File & Test Verification |
| :--- | :--- | :--- |
| **SRP** | Separation of persistence predicates from business orchestration. | `token.repository.ts` owns SQL where-clause; `global-logout.service.ts` routes tenant DB and logs audit events. |
| **OCP** | Open for tenant database binding without modifying query generation. | `TokenRepository.withDb(dbClient, tables)` returns a brand-bound instance using identical AST query logic. |
| **LSP** | Brand-bound repositories are fully substitutable for default repositories. | `GlobalLogoutService` treats `brandTokenRepo` identically whether bound or default. |
| **DIP** | Direct dependency injection into `GlobalLogoutService`. | `new GlobalLogoutService(realTokenRepo, mockUserRepo, mockAuditService)` allows seamless in-memory testing without network or live database IO. |
| **Least Privilege & Secure Defaults** | Revocation requires verified user identity; foreign attempts affect 0 rows. | Attempting cross-user revocation produces an atomic WHERE predicate matching zero records and updates zero rows. |
| **Fail Closed** | Missing, undefined, empty, or non-string owner identity throws immediately. | `TokenRepository.revokeById` throws `W1.2-SESS-01: userId is required...` prior to any database update. |
| **Single Authority** | User identity is sourced strictly from verified JWT tokens. | `[sessionId]/route.ts` extracts `payload.userId` from cryptographic verification; ignores client headers/body. |
| **Testability** | Deterministic AST predicate evaluation against isolated in-memory stores. | `StatefulTestAdapter` applies real `and(eq(id), eq(userId))` predicates without needing external databases. |
