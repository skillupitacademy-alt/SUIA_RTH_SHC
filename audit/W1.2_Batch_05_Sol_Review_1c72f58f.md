### D1 - replace raw output forwarding, not more secret-specific regexes

SafeQualificationReporter still emits the first raw error line after regex filtering
and forwards arbitrary stdout/stderr through the same filter. The submitted child test
uses password=... and a SENTINEL_ prefix that its regex explicitly recognizes; it does
not test a generic sensitive value. A bare error, locator call log or secret split
across stdout chunks can bypass the classifier.

Sol ran a new disposable offline test: throw Error with an unlabelled fake credential
string. Child runner exited 1; the intended test reached FAIL; captured runner output
contained the fake credential: TRUE. Only boolean results were emitted; temporary test
file was removed. A first attempt used a Windows path filter and did not establish
execution; rerun used the filename and verified the intended FAIL callback.

Minimal correction: emit only fixed, allowlisted scenario/project IDs, status, duration,
safe reason codes and counts. Suppress arbitrary test stdout/stderr and error/stack
text rather than regex-forwarding it. Treat dynamic titles/global errors as untrusted.
No raw raw-message callback or attachment contents in evidence. Do not add framework
or logging dependencies. Redaction helpers may remain for offline utility tests but
must not be the evidence security boundary. Remove 'Zero-Leakage' guarantees unsupported
by capture behavior. Deliberately fail with bare opaque, split-chunk, cookie and JSON
fake values; assert none in child stdout/stderr or recursively retained artifacts.
Require intended failure, not configuration/no-tests/import failure. Source sentinel
values must be synthetic and never supplied real credentials.

### D2 - enforce the readiness fields that are currently only collected

getReadinessRecord exposes buildRevision/projectOrigins/accountsAvailable, but
checkReadinessPrerequisites never validates the build or explicit project origins.
The context calls it without requiredAccountVars; accounts are checked only inside
the body AFTER browser launch. Config still defaults guessed ports. Chromium presence
is inferred from any matching cache directory, not the executable expected by the
installed Playwright. Correct these concrete omissions before accepting readiness:

- Require explicit per-project origin and tested-build/controlled-fixture provenance,
  plus that project's approved account availability, before allocating browser/page.
  Keep discovery/offline tests usable with no credentials; do not dump manifests/env.
- Define allowed origins for each controlled journey/API target; local/.local hostname
  membership alone is not authorization to send credentials to every local service.
- Use installed Playwright's expected executable path availability, not arbitrary
  cache revision presence. No install/provisioning in this correction task.
- Report skipped/incomplete qualification as NOT EXECUTED/incomplete in the safe
  summary; exit 0 for diagnostic skips is not runtime PASS.

### D3 - API requests are outside BrowserContext.route protection

installNetworkOriginGuard installs context.route only. Specs use page.request.post/get,
an APIRequestContext that is not intercepted by BrowserContext.route. It can follow
redirects without that browser interception. Service-worker-owned requests are also
not a reliable context.route boundary unless workers are blocked for qualification.

Use a small guarded API-request helper: resolve/validate an exact allowed origin before
sending, disable automatic redirects (maxRedirects: 0) and validate/reject each Location
before any explicit follow-up. Guard page/custom contexts before requests and block
service workers. Do not remove necessary API checks, silently pass a redirect or open
real endpoints to test this. Add offline/local fake-transport tests demonstrating unsafe
destinations never receive a request, including redirects and non-default ports.
Avoid generic wrappers unrelated to this test folder.
