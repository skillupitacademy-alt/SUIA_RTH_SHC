## Accepted design

For the scoped generic SUIA/RTH user/admin path: validate explicit routing context,
verify token signature/expiry/audience and consistent principal class, compare
canonical brand and stored subject, and deny invalid requests before session/user
state writes. Only absent brand is a legacy candidate, requiring a verified token,
matching subject and an active unexpired row in the selected store. Successors
carry canonical brand; legacy no-jti acceptance is preserved. No issuer migration.

Strict repository eligibility reads distinguish missing user, blocked/deleted
user, successful empty roles and query failure. Do not swallow authorization-query
errors or load optional profiles on the critical path. Preserve the original three
constructor dependency positions when adding userRepo. SQL remains in the
repository; authorization policy remains in the service.

Learner successors remain user-scope, without administrative flags or role claims.
Tenant-admin successors require a current admin/super_admin/infrastructure role;
otherwise deny refresh without claiming parent revocation. Reads are point-in-time,
not atomic with administrative actions. Existing eight-hour access signing and
seven-day refresh signing/rolling row behavior remain unchanged.
