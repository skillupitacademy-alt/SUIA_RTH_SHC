## R1-R6 disposition and final editorial qualifications

The author corrected the principal R1-R6 failures: SHC resolver acceptance, inherited shared-client refresh logic, unmounted specialized auth helpers, owner hostnames, conditional unauthorized-event handling, metadata interleaving, replay evidence limits and committed whitespace. The final acceptance commit also makes the following bounded documentation corrections rather than sending another broad rewrite back to the implementer:

- Generic tenant auth uses brand-bound skillup/RTH clients; default @quiz/db is preserved for default/test paths. The generic skillhubcore brand maps to default auth tables, not the people credential store.
- SHC login's credential lookup is in db-people; its audit call can use the default auth context. Missing refresh persistence is a source finding, not proof of all deployed database contents. With an absent matching row, generic lookup rejects before JWT verification; a matching active row still meets the route-selected user/admin/infra versus shc-admin audience conflict.
- Shared client refresh destination depends on getApiUrl/NEXT_PUBLIC_API_URL/default /api. SHC's inherited refresh request logic does not establish a working GUI-local route or deployed upstream path. No environment values were read.
- Specialized Redis key is skillhubcore:refresh:${familyId}. The inspected service entry point does not mount createAuthRoutes. Library behavior is not deployed browser evidence.
- The active API proxy system bypass checks x-internal-key/INTERNAL_API_KEY and Bearer CRON_SECRET. A separate internal-secret helper is not the same as cookie bypass in that proxy. Downstream guards still require their own tracing.
- A known revoked record is not proof of consumption. Even an unfiltered lookup cannot distinguish logout, rotation and other revocation causes from the current boolean/timestamps. Proposed diagnostics use a revoked-record category, not token_already_consumed inferred from revoked=true.
- Post-commit fallback is a conditional availability/failure scenario, not an established critical exploit. A parent retry returns 401 only under the stated same-store/context assumptions; deployed flags, ingress, cookie delivery and network traces remain unknown.
- Role-fast-path behavior is not current DB-role revalidation on every admin request. Tenant RBAC helper proposals do not authorize passing SHC people IDs into tenant tables, altering infrastructure flow, or changing JWT audience array compatibility.
- Existing eight-hour generic access lifetime is not a new short-lived/immediate-revocation guarantee. SHC persistence/portal policy requires its own contract; candidate admin hosts and fixed ports are not substituted for the owner matrix.

Historical author reports and earlier failed reviews remain provenance. This acceptance and the updated register supersede their pending/failed statuses. Policy proposals remain proposals.
