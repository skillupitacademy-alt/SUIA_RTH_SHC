## Blocking findings

1. **Post-build commit comparison cannot establish drift.** In
   `build-save-images.ps1`, postBuildCommit and preBuildCommit are both
   populated after the entire build loop. A new clean commit during Docker
   build will normally make both equal the new HEAD. Capture the immutable
   expected commit before any build (and compare to the verified receipt),
   then compare the actual post-build HEAD to that original value. Abort
   packaging/upload on mismatch. Recheck before publication as authorized.
2. **Direct invocation skips association validation.** InvocationId defaults
   to an empty string and is checked only if supplied. A direct call can
   reuse the same-tag receipt from an earlier invocation. For selected SHC,
   require and validate current association or execute the same gate helper
   to create a fresh association. Validate gate identity and UTC timing/order/
   freshness as well; these fields currently exist but are not verified.
   Fail closed on missing/wrong-type fields, not just unequal values.
3. **Old success survives some failed attempts.** Helper invalidation occurs
   only after rev-parse and clean-tree checks. A failed dirty-tree or Git-error
   attempt leaves the old success receipt intact. Invalidate the applicable
   prior receipt safely before fallible gate preparation, and ensure no
   publication path can reuse evidence from an unsuccessful attempt.
4. **Tests do not cover the reviewed deployment/build path.** The current
   test file has four helper scenarios producing eight assertions. It never
   executes deploy-smart.ps1 or build-save-images.ps1 and cannot establish
   SkipChecks handling, mixed/default/direct builder enforcement, receipt
   rejection, post-build drift or prevention of upload. Add executable tests
   of the actual scripts/helper policy, stubbing side effects only. Test the
   missed committed-HEAD drift and direct invocation explicitly.
5. **Publication association is incomplete.** Manifest qualityGateEvidence
   records only service, filename and verified=true. It does not record the
   verified full source commit, invocation, receipt digest or gate profile;
   the receipt itself is not among the uploaded artifacts. Bind the validated
   receipt/provenance to the actual artifact manifest without claiming that
   a filename or editable boolean authenticates it. Revalidate before upload,
   and reject stale artifacts after a failed same-tag build.
