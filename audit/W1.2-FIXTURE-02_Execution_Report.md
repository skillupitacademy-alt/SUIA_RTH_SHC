## 1. Executive Summary & Test Intent

This report documents the execution of **`W1.2-FIXTURE-02`** following the required audience/token-class isolation corrections.

The purpose of this test suite is to exercise the actual administrative verification guard chain:
```
NextRequest -> requireAdminRouteAccess(_req) -> verifyAdminOrInfraToken(_req) -> verifyAdminAccessToken(scopedToken, { audience }) -> _verifyAdmin(payload)
```

## 2. Key Corrections & State Isolation Controls

In accordance with Sol's review findings:
1. **Separation of Cryptographic Key Failure from Audience / Token-Class Failure:**
   - In baseline commit `2e473285`, learner tokens were signed with `ACCESS_SECRET` and verified against a distinct `ADMIN_SECRET`, causing tests to fail at signature verification (`ERR_JWS_SIGNATURE_VERIFICATION_FAILED`).
   - In this corrected suite, we introduce a **shared-key configuration** (`ADMIN_SECRET === ACCESS_SECRET`) to simulate the supported production fallback (`ADMIN_JWT_SECRET ?? JWT_SECRET`).
   - Under shared keys, signature verification **succeeds** against the admin verifier. We then prove that:
     - Promoted learner accounts fail strictly with `Audience mismatch: expected admin, got user`.
     - Tokens with wrong audience fail strictly with `Audience mismatch: expected admin, got ...`.
     - Tokens with wrong token class fail strictly with `Invalid admin token type`.
2. **Database Query Entry Spying (`mockDbSelectEntry`):**
   - The brand DB context now spies on `db.select(fields)` call entry (`mockDbSelectEntry`), rather than only inspecting final mock resolution.
   - We assert that on every early token rejection (signature, audience, tokenType, missing token), `mockDbSelectEntry` is called **0 times**.
3. **Container State Restoration:**
   - The test captures `originalContainerTokenService = container.get(TokenService)`.
   - In `afterEach`, it executes `container.register(TokenService, originalContainerTokenService)`.
   - No instances leak into subsequent test suites, and no unrelated container singletons are reset.
4. **Fixture Sensitivity Control (Control 12):**
   - Verifies that if audience validation were missing or bypassed, a promoted learner token would reach privileged database logic. The test explicitly verifies that the active audience check prevents this leakage.
