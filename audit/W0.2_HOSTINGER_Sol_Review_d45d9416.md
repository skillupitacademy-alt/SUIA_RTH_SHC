## Remaining blockers

1. **Tests exercise a duplicate policy.**
   `scripts/__tests__/test-w0-2-hostinger-control-flow.ps1` defines a
   handwritten Invoke-MockBuilder implementing selected validation rules.
   Scenarios invoke that function, not build-save-images.ps1. It never invokes
   deploy-smart.ps1. Scenario 10 directly calls Remove-Item to simulate
   invalidation, and the default-selection scenario simulates selection.
   A passing suite does not validate the production control flow, SkipChecks,
   drift during build or no-upload behavior. Replace copied policy with tests
   of actual entrypoints or a shared production policy module, stubbing only
   external effects. Include a clean commit made by the Docker stub during
   building, failed Git commands, direct/default selection, and upload traces.

2. **Publication is not revalidated and referenced evidence is not retained.**
   deploy-smart.ps1 still checks only existence of archive/checksum/manifest
   before scp of those three files. The receipt named by qualityGateEvidence
   is not uploaded. Manifest metadata is not matched to current invocation,
   expected source and actual archive before publication. Retain the receipt
   with release artifacts or embed its validated content in the manifest.
   Compare the validated receipt bytes/digest across build and publication,
   validate manifest/receipt/current-source association and local archive
   checksum before any upload. Reject stale same-tag outputs after failure.
   Preserve compatibility with the runtime loader unless separately required.

3. **Freshness accepts future receipts.** Builder rejects age >60 minutes but
   accepts arbitrary future completion times (negative age). Reject future or
   invalid timing with an explicit bounded clock-skew policy; enforce the
   chosen freshness policy at publication. Add tests against real validation.

4. **Invalidation does not yet precede every Git failure.** The helper performs
   rev-parse --git-dir before removing old success. A Git failure at that point
   leaves previous evidence. Invalidate safely after filesystem/path validation
   but before Git/gate preparation, or make failed-attempt receipts unusable
   by an equivalent explicit mechanism. Test that actual failure path.
