## Flow-Specific Identity Mappings

### Signup Flow (apps/api-server/src/modules/auth/signup.service.ts)

**Producer Path:**

1. **Brand User Created:** Line 67, `brandUserRepo.create()` → returns brand user with `id` (brand user ID).
2. **Identity Bridge Called:** Line 88-96, `bridge.syncUser({ externalId: newUser.id, externalBrand: brand, email, platform: brand })`.
3. **People DB Projection:** Identity bridge inserts `db-people.users` with `externalId=newUser.id`, `platform=brand`, `email=email` → returns `shadowUserId`.
4. **Link Stored:** Line 102, `bridge.updateShadowUserId(brandDb, brandUsers, newUser.id, result.shadowUserId)` → brand user's `shadowUserId` column updated.

**Failure Case:** If `email` already exists in people DB (different tenant), insert fails on unique constraint (line 63 of 0000_perpetual_microbe.sql migration). Error logged as `identity_bridge_sync_failed` (line 100-121). Signup completes in brand DB but shadow projection missing.

### Login Flow (apps/api-server/src/modules/auth/login.service.ts)

**Producer Path:**

1. **Brand User Lookup:** Line 123, `brandUserRepo.findWithDetails(email)` → returns brand user with `id` and `shadowUserId` (nullable).
2. **Ensure Shadow ID:** Line 173, `ensureShadowUserId(user, brand)` → checks if `user.shadowUserId` exists; if not, calls identity bridge (lines 41-60).
3. **Token Generation:** Lines 178-185, `tokenService.generateAccessToken({ userId: user.id, originalUserId: user.id, shadowUserId, email, roles, isAdmin, tokenType, brand })`.

**Identifier Semantics:**
- `userId` = `originalUserId` = brand user ID (tenant-scoped).
- `shadowUserId` = people DB projection ID (SHC cross-reference).
- `brand` = tenant context.

**Token Claims Verified:** `assertIdentityClaims` (token.service.ts line 118-129) enforces both `shadowUserId` and `originalUserId` are non-empty strings.

### Identity Bridge Lookup Flow (packages/identity-bridge/src/UserIdentityBridgeService.ts)

**Lookup Query:** Lines 19-30

```sql
SELECT id, email FROM users
WHERE externalId = :brandUserId
  AND platform = :tenantContext
  AND deletedAt IS NULL
LIMIT 1
```

**Unique Index:** `idx_users_external_id_platform` on `(externalId, platform)` ensures one projection per brand user per tenant.

**Translation:**
- `externalId` (people DB) ← `brandUserId` (brand DB)
- `platform` (people DB) ← `tenantContext` (brand DB, token claim)
- `id` (people DB) → `shadowUserId` (token claim)

### Cross-Service Header Flow (apps/faculty-app/src/proxy.ts lines 75-80)

**Producer:** BFF extracts identity from verified token.

**Headers Set:**
- `x-user-id` ← `payload.shadowUserId`
- `x-shadow-user-id` ← `payload.shadowUserId`
- `x-original-user-id` ← `payload.originalUserId`
- `x-brand` ← `payload.brand`
- `x-platform` ← `payload.brand`

**Consumer Validation Required:** Services must validate `X-Gateway-Secret` before trusting identity headers (Audit Finding SU-TUTORIAL-002).
