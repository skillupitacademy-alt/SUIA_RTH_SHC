## 1. Executive Summary & Review Correction Remediation (R1–R3 & Ownership Bypasses)

Per governing reviews `audit/W1.2_Browser_Preparation_Sol_Review_5a0581f0.md` (`3f7c773f`) and `audit/W1.2_Browser_Ownership_Review_ef988641.md` (`38f10f61`), this report records the comprehensive implementation and verification of the required preparation boundaries and run ownership protections:

### R1 — Run-Owned Cleanup, Path Containment & Output Ownership Security
- **Atomic Run Allocation (`allocateOrValidateRunDirectory`):** Creates directories atomically (`fs.mkdirSync(runDir, { recursive: false })` and `fs.writeFileSync(markerPath, ..., { encoding: 'utf-8', flag: 'wx' })`). If `runDir` already exists on disk, allocation strictly refuses to overwrite existing runs or markers. Existing run directories can only be claimed if the caller explicitly passes `expectExisting: true` (or inherited worker process) AND proves valid existing ownership matching both `runId` and `ownershipToken`.
- **Foreign Directory & Marker Content Preservation:** Allocation against an existing foreign directory with a valid-looking run ID is rejected fail-closed before any marker is written or files touched. Similarly, claiming an owned run with a mismatched token is rejected fail-closed, leaving original marker content completely untouched.
- **Fixed Harness Artifact Parent & Pre-Config Validation:** Defined `FIXED_HARNESS_ARTIFACTS_PARENT` (`tests/e2e/auth-qualification/.run-artifacts`). `allocateOrValidateRunDirectory` executes **before** returning Playwright configuration. Arbitrary caller-supplied directory paths are prohibited; run IDs must be strictly alphanumeric (`/^[a-zA-Z0-9_-]{1,64}$/`). Path traversal (`..`), absolute escapes, roots, or slashes throw `[OWNERSHIP_SAFETY_VIOLATION]` fail-closed before Playwright can touch or clean anything.
- **Run Ownership Marker / Token:** Every allocated run directory creates `.auth-run-ownership.json` containing `harness: 'auth-qualification-run'`, `runId`, `pid`, `ownershipToken`, `parentDir`, `runDir`, and `createdAt`. Playwright's artifact output is nested in `artifacts/` subfolder, ensuring the ownership marker at the run directory root is never purged by Playwright initialization.
- **Sole Cleanup Authority & Unvalidated Exit Hook Removal:** Completely removed the unvalidated `process.once('exit')` hook in `safe-reporter.ts`. Terminal metadata (`.last-run.json`) is never used as secondary deletion authority. `safeCleanupRunDirectory` in `onEnd()` is the sole cleanup invocation, requiring full token validation, ancestor check, and parent containment before unlinking. If an unowned directory or mismatched token is provided (as in Sol's probe), deletion is REFUSED fail-closed without invoking `fs.rmSync`.
- **Deep Ancestor & Realpath Containment:** `hasSymlinkOrJunctionAncestor` inspects every path component from the target up to root/parent using `lstatSync`. `isSafelyContainedInOwnedDir` resolves `realpathSync` and verifies that no component along the path is a symbolic link or directory junction. Regular files beneath a symlink/junction ancestor are strictly rejected as non-contained.
- **Selective Attachment Unlinking:** `SafeQualificationReporter.onTestEnd` only unlinks attachments that satisfy deep path containment within `ownedOutputDir`. Arbitrary attachment sources outside the run directory are never deleted.
- **Preservation of Workspace Reports:** Eliminated `fs.rmSync` on `test-results`. `reporter.onEnd()` cleans up only the verified unique run directory, leaving the shared workspace `test-results` untouched.
- **Allowlisted Scenario & Project Output:** Dynamic test titles, raw error strings, locator stacks, DOM dumps, and unlisted project names are replaced with static allowlisted scenario IDs (`AQ-*`, `SENTINEL-*`), allowlisted project names (`sentinel-checks`, `suia-chromium`, `rth-chromium`, `shc-chromium`), and fixed reason codes (`[INTENDED_OR_ASSERTION_FAILURE]` / `[TEST_TIMEOUT]`).
- **Complete Stdout/Stderr Suppression:** Test runner completely suppresses arbitrary test `stdout` and `stderr` streams, emitting generic fixed execution notices on error.
- **Empirical Proof:** Verified via `SENTINEL-04` (child-process deliberate failure probe with fake title secret, bare errors, split stdout/stderr chunks, sibling run preservation, and owned artifacts; runner exited code 1, zero leakage, safe reason code emitted, foreign canary preserved) and `SENTINEL-05` (comprehensive offline test suite proving: 1. arbitrary-root traversal refusal before config creation, 2. existing foreign directory refusal with zero marker writes and file preservation, 3. existing owned run refusal with wrong token and marker preservation, 4. mismatched token + terminal metadata reporter refusal, 5. parent/child/sibling run separation and parent preservation, and 6. ancestor NTFS junction escape rejection).

### R2 — Exact-Origin Policy for Browser Routing & API Dispatch
- **Browser Route Guard (`installNetworkOriginGuard`):** Browser context route guard intercepts every outgoing request and compares target origin against the project's explicit qualified origin set (`allowedOrigins`).
- **Unapproved Local Port/Host Abort:** Strictly aborts unapproved local ports and hostnames (including `http://unapproved.localhost:61999/receive`, foreign localhost ports, and external domains) with `await route.abort('blockedbyclient')`.
- **Userinfo Credential Rejection:** Rejects userinfo credentials (`user:pass@host`) in both configured URLs and outgoing request URLs fail-closed.
- **Guarded API Dispatch (`guardedApiFetch`):** Preserves `maxRedirects: 0`, origin safety validation, and explicit `Location` header inspection on 3xx redirect responses.
- **Service Worker Blocking:** Configured `serviceWorkers: 'block'` across all browser contexts.
- **Empirical Proof:** Verified via `SENTINEL-06` (offline route guard probe using mock context: `unapproved.localhost:61999` aborted, userinfo URL aborted, production domain aborted, approved project origin continued) and `SENTINEL-07` (offline mock verifying `guardedApiFetch` rejection of non-matching origins and 302 redirects).

### R3 — Pre-Launch Account Prerequisites & Unsupported Scenarios
- **Project Account Mapping:** Wired `PROJECT_ACCOUNT_MAP` into `checkReadinessPrerequisites` mapping each project to its required synthetic environment variables (`TEST_SUIA_LEARNER_*`, `TEST_RTH_LEARNER_*`, `TEST_SHC_ADMIN_*`).
- **Pre-Launch Evaluation:** Evaluated in `context` fixture **before** invoking `playwright.chromium.launch()`. If account variables are unset, the test is marked `SKIPPED / NOT EXECUTED` immediately with zero browser launches.
- **Unknown Projects Fail Closed:** Projects outside `KNOWN_PROJECTS` fail closed before launch.
- **Negative Test Scoping:** Negative tests declare explicit empty account requirements (`requiredAccountVars: []`), allowing execution without credentials but still requiring certified build revision (`TEST_BUILD_REVISION`), isolated environment flag (`TEST_ISOLATED_ENVIRONMENT`), explicit qualified origin, and Chromium availability.
- **Immediate Skip for Unsupported Specs:** Unsupported scenarios (`AQ-04-SHC`, `AQ-07`, `AQ-08`, `AQ-09`, `AQ-10`) do not request `{ auth }` fixture (`async ({}, testInfo) => { testInfo.skip(...) }`), skipping immediately at the root level without browser fixture allocation.
- **Empirical Proof:** Verified via `SENTINEL-08` (fake browser launch counter: counter remains 0 when account variables or build revision are missing or project is unknown; counter increments only when certified prerequisites are met).
