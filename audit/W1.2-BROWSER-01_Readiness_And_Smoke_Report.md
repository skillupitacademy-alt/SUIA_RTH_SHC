## 3. Dedicated Test Harness Architecture

The test harness was created entirely within the whitelisted path `tests/e2e/auth-qualification/**`:

```
tests/e2e/auth-qualification/
├── playwright.auth-qualification.config.ts  # Dedicated config (workers: 1, retries: 0, traces/screens off)
├── helpers/
│   ├── sanitized-evidence.ts                # Regex-based JWT/secret redactor, safe cookie assert, requirePrerequisites
│   └── test-credentials.ts                 # Safe env-based credential loader (no hardcoded credentials)
├── fixtures/
│   └── auth.fixtures.ts                     # Isolated browser context fixture with automatic cookie clearing
├── 01-learner-suia-login.spec.ts            # AQ-01: SUIA learner login, dashboard, protected API
├── 02-learner-rth-login.spec.ts             # AQ-02: RTH learner login, dashboard, protected API
├── 03-admin-shc-login.spec.ts               # AQ-03: SHC administrator login, admin route protection
├── 04-token-refresh-flow.spec.ts            # AQ-04: SUIA/RTH active refresh + SHC stateless gap documentation
├── 05-logout-session-contract.spec.ts       # AQ-05: Logout cookie clearance, refresh token revocation
├── 06-negative-credentials.spec.ts          # AQ-06: Invalid credentials fail-closed, zero-cookie state
├── 07-blocked-account-refresh.spec.ts       # AQ-07: Blocked account refresh rejection (REFRESH-06)
├── 08-same-email-tenant-isolation.spec.ts   # AQ-08: Same-email independence across SUIA and RTH
├── 09-account-switching-boundary.spec.ts    # AQ-09: Account switching without state leakage
└── 10-cross-tenant-authorization-denial.spec.ts # AQ-10: Learner token denied on admin/foreign tenant routes
```

### Key Security & Configuration Decisions
1. **Sequential Execution:** `workers: 1` and `fullyParallel: false` guarantee zero race conditions between concurrent authentication states.
2. **Zero Retry Policy:** `retries: 0` ensures that isolation or authorization failures are never masked by automatic test retries.
3. **Artifact Suppression:** `trace: 'off'`, `video: 'off'`, `screenshot: 'off'` prevent passwords, session cookies, or access JWTs from being persisted to disk.
4. **Environment Isolation Guards:** Every test calls `requirePrerequisites(...)` before taking action. If synthetic fixtures or test credentials are not present, the test skips cleanly rather than making unauthenticated calls or throwing unhandled errors.
