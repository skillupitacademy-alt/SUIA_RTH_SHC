after HTTP 429 with unbounded Retry-After-derived sleep. It does not record the 429
as a distinct outcome in fixed-code evidence. Do not present that as a clean first-attempt

does not prove no live session was created. For 429 use a safe explicit throttled/
incomplete status, or a separately documented single bounded retry with delay capped
and preserved attempt history. No retries on invalid credentials/security assertions.
Source-derived event/hydration readiness is preferable to claiming a fixed 1s sleep
proves readiness, but no broad login framework rewrite is requested.

The log shows raw list reporter overrides and error-context.md debugging during live
credentialed runs. This does not prove a leak occurred, but it invalidates blanket
'zero secrets emitted' certification without inspection. Inventory only affected
artifact paths/time windows and inspect locally for exposure using boolean findings;
never display/copy raw contents. Preserve unrelated evidence. Report whether prohibited
capture/debug output was used and what can/cannot be verified. Do not delete all reports
to manufacture zero-artifact evidence, or rotate live credentials without owner direction.
