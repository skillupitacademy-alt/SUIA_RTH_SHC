## Architecture Amendment Summary

### Before: Global Learner Identity Model

**Key assumptions in FinalAechitecture.md sections 3, 4:**
- "Your global identity model should separate the identity of a person from their relationship with a brand"
- "Student identity: One global identity, with explicit membership and access for each brand"
- "Global account: A student has one global identity"
- "Brand membership: The student can have an RTH membership, a SUIA membership, or both"
- Onboarding flow: "Create or verify the student's global identity" → "Assign the required brand memberships"

**Conceptual model:** `people_prod` owns global learner identity; brand databases reference `global_user_id`; brand membership as relationship to global identity.

### After: Independent Tenant Learners + SHC Infrastructure Projection

**Key principles in amended FinalAechitecture.md:**
- "The identity architecture distinguishes infrastructure identity (SHC people DB projection) from tenant learner identity (brand-owned user accounts)"
- "SUIA (`skillup`) and RTH (`realtutorialhub`) own independent learner identities and records"
- "Equal learner IDs or email addresses across tenants identify independent learners, not the same person"
- "No automatic account linking or credential sharing occurs"
- "The people DB (`people_prod`) maintains shadow projections of tenant learners for cross-platform service coordination"
- "The shadow ID is a cross-reference, not a replacement canonical learner identity"

**Conceptual model:** Tenant databases own learner identity; `people_prod` maintains optional infrastructure projections with `(externalId, platform)` mapping; controlled explicit linking only where required.

## Owner-Approved Architecture Direction

From `audit/W1.1_Architecture_Decision_For_Owner_Approval.md`:

1. SUIA (`skillup`) and RTH (`realtutorialhub`) own independent learner accounts, credentials/session boundaries and learner records
2. The same person can have two independent accounts; matching email/IDs never link accounts or confer access
3. Qualified learner reference includes verified platform and local learner ID; existing `platform`/`brand` values used (no duplicate `tenantId` by default)
4. SHC may retain platform-specific infrastructure projections; projection is service cross-reference, not shared global account
5. `shared` describes resource scope requiring authorization; never learner authority or implicit cross-tenant permission

**Exclusions:** No schema changes, credential/session changes, migration execution, data cleanup, token redesign, impersonation, SSO, cross-tenant automatic linking, deployment or main merge authorized in W1.1.
