## Decisions and required corrections

1. Run the canonical command from the repository root via a fixed executable
   and argument list. Do not use `Invoke-Expression`. Resolve paths from
   `$PSScriptRoot`, not the caller's current directory. A command-start failure
   must fail closed; inspect exit status immediately.
2. Step 4.5 before Docker build is approved, outside every SkipChecks branch.
   Check applicable source cleanliness before any SHC gate/legacy validation
   command as well. No failure can be overridden interactively or with Force,
   SkipChecks, NoCache or a new bypass flag.
3. Resolve and validate actual selected services first, including the builder's
   default-service expansion. Enforcement must use canonical resolved names,
   not only the raw Services argument. Builder invocation directly must not
   omit SHC validation when Services is empty or contains mixed services.
4. Evidence is transient release output. Use a versioned JSON contract with
   canonical service, full 40-character source commit, imageTag as a separate
   identifier, gate identity, UTC start/completion times, invocation/release
   association, PASS status and numeric exitCode 0. Capture the exact quality
   command/profile and bind the receipt to the current source and selected
   artifact. Do not compare a caller-supplied tag to an equally caller-supplied
   evidence field and call that source verification.
5. Validate receipt schema, canonical service, source commit, gate, exit status,
   invocation association and freshness. Remove/invalidate prior success
   before a new gate attempt; a later failure must not reuse old success.
   Missing, malformed, wrong-service, stale or mismatched receipts fail closed.
   Resolve the evidence path once under the release directory and pass it
   explicitly or derive it consistently. Write atomically after success.
6. A local JSON file is an operational receipt, not an authenticated service
   credential or proof against a malicious local operator. Do not advertise
   tamper-proof provenance or trust arbitrary editable PASS files. Direct
   builder calls require valid current-invocation evidence or must execute
   the same verification helper; they cannot bypass the gate.
7. Use `git -C <repo>` and reject nonzero exits from rev-parse/status. Check
   full HEAD and source state before and after the gate, immediately before
   build and after build before packaging/publishing/upload. Stage/tag changes
   must also invalidate evidence. A Git error is not a clean tree.
8. Explain the build-input boundary: tracked/untracked source, ignored build
   outputs and intentional environment/config inputs. Never log secrets or
   arbitrarily exempt tracked source. Prefer a pinned immutable build context;
   if using guarded working-tree builds, document the concurrency limits and
   fail on detected drift instead of claiming immutable-source guarantees.
9. Preserve the canonical quality command. Evidence must not qualify altered
   source merely because lint/typecheck/build generated tracked-file changes.
   Diagnose such changes and correct generation/verification deliberately.
10. Connect receipts to the actual manifest service/image record and archive
    integrity metadata at the appropriate stage. Do not put secrets in receipts
    or modify the current runtime loader's contract without reviewed need.
    Invalidate/reject artifacts on drift; verify receipts/artifacts before
    upload. Same-tag stale artifacts cannot stand in for a new failed build.
11. Report other selected services as 'not qualified by this SHC gate;
    enforcement pending' rather than 'no gate required'. Current scope remains
    SHC only. SUIA/RTH and combined qualification stay separately PLANNED.
