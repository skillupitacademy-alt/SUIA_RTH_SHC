## Root Cause (RC-ID-01)

**Original defect:** `TokenRepository.revokeById` accepted an optional `userId` parameter and conditionally added it to the WHERE clause. The service layer (`GlobalLogoutService.revokeSession`) did not pass the verified user ID, resulting in an unscoped revocation that could affect sessions owned by any user with a matching session ID.

**Security impact:** A learner knowing another learner's session ID could potentially revoke that session, even though the API route had already verified the caller's identity and RBAC permissions.

**Finding reference:** SU-SESSION-010

## Implementation Changes

### Changed Production Files

#### 1. `apps/api-server/src/modules/auth/repositories/token.repository.ts`

**Before (vulnerable):**
```typescript
async revokeById(id: string, userId?: string) {
  const conditions = [eq(this.refreshTokensTable.id, id)];
  if (userId) {
    conditions.push(eq(this.refreshTokensTable.userId, userId));
  }
  await this.dbInstance.update(this.refreshTokensTable)
    .set({ revoked: true })
    .where(and(...conditions));
}
```

**After (secured):**
```typescript
async revokeById(id: string, userId: string) {
  // Runtime validation: fail closed if owner identity is missing/invalid
  if (typeof userId !== 'string' || userId.trim().length === 0) {
    throw new Error('W1.2-SESS-01: userId is required for session revocation');
  }

  // Single atomic update with both session ID and owner ID in WHERE clause
  await this.dbInstance.update(this.refreshTokensTable)
    .set({ revoked: true })
    .where(and(
      eq(this.refreshTokensTable.id, id),
      eq(this.refreshTokensTable.userId, userId)
    ));
}
```

**Key changes:**
- Made `userId` parameter required (TypeScript signature)
- Added runtime validation: throws before database operation if userId is missing, empty, whitespace-only, or not a string
- Always includes both `id` and `userId` in the WHERE clause
- Removed conditional predicate logic

#### 2. `apps/api-server/src/modules/auth/global-logout.service.ts`

**Before:**
```typescript
await brandTokenRepo.revokeById(sessionId);
```

**After:**
```typescript
// 🔐 W1.2-SESS-01: Pass verified brand-local userId to enforce ownership
await brandTokenRepo.revokeById(sessionId, userId);
```

**Key changes:**
- Service now passes the verified `userId` (received from authenticated route) to the repository
- This `userId` comes from the JWT payload verified by `TokenService.verifyAccessToken`
- Updated method documentation to clarify owner-scoped behavior

### Other Callers Audited

**Other services:** No other production code calls `revokeById`.

## Changed Behavior and Response Semantics

### Successful Revocation (Own Session)

**Before:** HTTP 200, session revoked  
**After:** HTTP 200, session revoked (unchanged)

### Attempted Revocation of Another User's Session

**Before:** HTTP 200, foreign session potentially revoked (VULNERABLE)  
**After:** HTTP 200, safe no-op (database UPDATE returns 0 affected rows, API returns success)

**Rationale:** The API does not disclose whether the session exists or belongs to another user. This prevents information leakage while ensuring the caller's session is not revoked by mistake.

### Missing/Invalid userId (Accidental Service Bug)

**Before:** Session revoked without ownership check  
**After:** Error thrown at repository boundary, no database operation

### Repeated Revocation

**Before:** Idempotent (safe)  
**After:** Idempotent (safe, unchanged)
