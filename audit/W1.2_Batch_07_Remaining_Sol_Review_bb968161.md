## S1 - Origin comparison is still broader than the accepted policy

logout-all compares parsedOrigin.host against a hand-built set containing request host,
its port-stripped form, both tenant .test hosts and guessed localhost ports. It never
compares scheme. These production-source constants were introduced for fixtures without
an approved tenant-origin mapping. Exact host membership is insufficient for exact
origin validation.

Actual-route offline probes with valid signed user cookies observed HTTP 200 for both
a mismatched scheme on the same host/port and https://skillup.test targeting a local
RTH endpoint. Both expected HTTP 403 before count or revocation. No network request was
sent to those origins. This establishes handler-policy failures using fixture requests.
It does not establish a deployed browser exploit or actual third-party cookie delivery.

Use canonical full origins derived from the actual request or an existing explicitly
trusted tenant-aware origin policy. Include scheme, hostname and port. Reject invalid
Origin syntax, userinfo and ambiguous origins according to that contract. Keep the
positive same-origin control and justified bearer-only programmatic compatibility.

## S2 - Credential selection changed the original precedence

TokenService.getAccessToken without scope checks user/admin/infra cookies before the
Authorization fallback. The rewritten route instead verifies Bearer first and labels
the request non-cookie-authenticated even when an authoritative cookie is present.
A valid fixture cookie plus valid Bearer plus foreign Origin returned HTTP 200.

The prior correction wording requested invalid-Bearer fail-fast while also preserving
credential precedence. Sol resolves that ambiguity here by selecting the existing
cookie-first precedence. Determine origin protection from the selected credential.
An additional valid or invalid Bearer header cannot displace a selected cookie or
waive its origin check. Pure Bearer requests retain their normal verification behavior.
This selection supersedes the earlier blanket invalid-Bearer-first instruction.

## S3 - Stateful fixture revokes its foreign-tenant canary

The new tokenStore contains colliding userId 100 in skillup and realtutorialhub, but
its repository revokeAll/getUserSessions methods filter only by userId. withDb returns
the same object. The fixture therefore revokes RTH's row during a skillup operation.
The assertions also filter only by userId and count that foreign revocation as success.

Adding an independent canary assertion to the exact submitted fixture reproduced this
failure. The canary expected rth-sess-1.revoked=false but observed true. This is a defect
in the submitted adapter and claimed isolation evidence. Actual physical repository
isolation was outside that fixture and is not inferred to be broken by this result.

Create genuinely tenant-bound adapters and assert all foreign-tenant/unrelated-user
rows remain unchanged, including presence and count snapshot through the actual route
where practical. The submitted audit-absorption test merely installs another no-op
mock and never fails an insert. The revokeAll error test throws before mutation and
does not establish commit-then-error behavior. Replace those claims with actual real-
service and real-AuditService failure controls, using isolated persistence adapters.
The actual service's absorbed-audit semantics and unknown outcome must be exercised.
