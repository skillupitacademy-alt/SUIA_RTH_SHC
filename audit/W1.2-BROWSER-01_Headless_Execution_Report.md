## 4. Source-Derived Adjustments & Findings

During headless qualification, four source-derived alignments were identified and implemented:

1. **Post-Login Redirection Target**:
   - `AuthPage.tsx` checks `sessionState.onboardingCompleted`. When incomplete, it navigates to `/onboarding` rather than `/dashboard`. URL regex assertions were broadened to `/\/dashboard|\/onboarding|\/learn|\/account/` to accurately reflect the real application flow.
2. **Protected User API Endpoint**:
   - In SUIA (`apps/skillup-web`) and RTH (`apps/realtutorialhub-web`), current user profile data is served via `/api/profile` (BFF handler) rather than `/api/auth/me`. Tests were updated to target `/api/profile`, which returns the authenticated user's email and ID.
3. **SHC Admin Protected Endpoint**:
   - In SHC (`apps/skillhubcore-admin`), admin access was verified against `/api/admin/domains`, guarded by `requireAdminRequest`. Valid admin cookies return HTTP 200 with domain records; unauthenticated requests return HTTP 401.
4. **Rate Limit Handling**:
   - The API server enforces brute-force rate limiting (`{ limit: 5, windowMs: 60000 }` per `withRateLimit` on `/api/auth/login`). `loginViaUI` was enhanced to detect HTTP 429 and the `retry-after` header, pausing gracefully until the window clears before resubmitting.
