## 2. Execution History & Attempt Ledger

In accordance with Sol Review requirement R1, the execution history is disclosed transparently, separating earlier failed attempts, investigations, and debugging runs from the final completed run.

### Phase 1: Initial Attempts & Triage
1. **Rate Limiting (HTTP 429)**: Initial execution attempts encountered HTTP 429 rate limit responses on `/api/auth/login`. The API server enforces brute-force protection (`limit: 5, windowMs: 60000`). When multiple test specs submitted logins within 60 seconds, requests were throttled.
2. **Hydration Timeouts**: On initial loads, Playwright clicked the submit button before Next.js client hydration attached the form `onSubmit` handler, resulting in form submission delays.
3. **Raw Reporter Invocations**: During initial triage, manual probe runs used `--reporter=list` and error-context inspections to diagnose 429 throttling and redirection paths. These debugging runs were superseded by the allowlisted safe reporter.

### Phase 2: Harness Alignment & Adjustments
1. **Rate Limit Handling**: Enhanced `loginViaUI` in `fixtures/auth.fixtures.ts` to detect HTTP 429, respect `retry-after` with a bounded cooldown (capped at 30s), allow at most a single retry for valid credentials, and strictly refuse retries on invalid-credential negative security tests.
2. **Endpoint Alignment**: Reconciled endpoint targets: SUIA and RTH frontends query `/api/profile` (BFF) rather than `/api/auth/me`. SHC queries `/api/admin/auth/me` or `/api/admin/domains`.
3. **Redirection Scope**: Reconciled landing URL assertions to accommodate `/onboarding` for learner accounts where onboarding is incomplete.
