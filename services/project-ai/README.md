# Project AI Service

FastAPI service for AI-driven development orchestration.

## Architecture

**Architectural Rule:**
- TypeScript D1-D8 scanners = deterministic repository facts layer
- Python/FastAPI = AI orchestration control plane

This service **READS** the TypeScript-generated snapshot. It does **NOT** scan the repository independently or open source files directly.

## Setup

### Prerequisites

- Python 3.11+
- TypeScript snapshot generated by `@quiz/project-llm-discovery`

### Installation

```bash
cd services/project-ai

# Install dependencies
pip install -e .

# Install dev dependencies
pip install -e ".[dev]"
```

### Configuration

The service expects the TypeScript snapshot at:
```
<workspace-root>/packages/project-llm-discovery/output/snapshot.json
```

Set `WORKSPACE_ROOT` environment variable to override the default path.

## API Endpoints

### Health Check

```http
GET /health
```

Returns service status, version, and timestamp.

### Snapshot Access

```http
GET /snapshot
```

Returns the complete TypeScript-generated snapshot.

```http
GET /snapshot/metadata
```

Returns snapshot metadata only (timestamps, scanner versions).

### Evidence Access

```http
GET /evidence
```

Returns all evidence records from the snapshot.

```http
GET /evidence/{evidence_id}
```

Returns a specific evidence record by ID.

**Example:**
```bash
curl http://localhost:8000/evidence/file:apps/admin/package.json
```

### Task Management

```http
POST /tasks/plan
```

Create a new planning task.

**Request Body:**
```json
{
  "description": "Implement user authentication",
  "context": {
    "priority": "high"
  }
}
```

```http
GET /tasks/{task_id}
```

Get task status by ID.

```http
POST /tasks/{task_id}/approve
```

Approve a task waiting for approval (transitions to IMPLEMENTING state).

```http
POST /tasks/{task_id}/reject
```

Reject a task waiting for approval (transitions to REJECTED state).

## Task States

Tasks flow through the following states:

1. **CREATED** - Task created, not yet started
2. **DISCOVERY** - Analyzing snapshot for relevant evidence
3. **PLANNING** - Generating implementation plan
4. **WAITING_FOR_APPROVAL** - Plan ready, awaiting human review
5. **IMPLEMENTING** - Executing approved plan
6. **TESTING** - Running tests to verify implementation
7. **VERIFYING** - Final quality checks
8. **COMPLETED** - Successfully completed
9. **FAILED** - Unrecoverable error occurred
10. **BLOCKED** - Blocked by external dependency
11. **REJECTED** - Plan rejected by reviewer

## Architecture Notes

### Snapshot Reading, Not Repository Scanning

The discovery client enforces the architectural boundary:

```python
class DiscoveryClient:
    """
    Client for reading TypeScript-generated discovery snapshots.
    
    NEVER scan files or run shell commands here.
    All repository facts come from TypeScript D1-D8 scanners.
    """
```

### LLM Integration Points

LLM integration is stubbed in M2.8. Look for `TODO: LLM_INTEGRATION` comments in:
- `app/orchestration/workflow_engine.py`
- `app/orchestration/agent_registry.py`

### In-Memory Task Storage

Tasks are stored in-memory for M2.8. Production implementation (M3+) will use:
- PostgreSQL for task persistence
- Redis for task queues
- Event sourcing for audit trail
