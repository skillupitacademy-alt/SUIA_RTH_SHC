# R6-A P0 report-generation security correction

13 November 2026. Scope is the owner's narrow source/test authorization for the existing report trigger. The owner reports GitHub commit be6d1f1430304187792841ed9852616661b89a90. Current local files were independently hashed in `.evidence/r6-report-p0/baseline.json`. Git CLI was not used, local HEAD was not inferred, and authorship of the owner's later commit is not attributed here.

The producer previously supplied a literal placeholder internal credential when its key was absent and selected a production host when its API URL was absent. It also appended the report path incorrectly for an origin-only API setting, ignored unsuccessful HTTP statuses and logged raw network exceptions. Missing receiver configuration does not itself establish an authentication bypass, because the receiver compares a nonempty supplied key with its configured key. The demonstrated defect is unsafe outbound credential/destination selection and inadequate failure handling.

The authoritative receiver is `apps/api-server/src/app/api/generate-report/route.ts`, exporting `POST /api/generate-report`. Its internal contract is `x-internal-key` matched against `INTERNAL_API_KEY`. Its independent learner contract verifies the token, brand, persisted exam owner and completed exam state. The receiver implementation and these checks were preserved.

Existing configuration uses `NEXT_PUBLIC_API_URL` for the API server. The infrastructure specification describes this setting, and `docs/infrastructure/02-PHYSICAL-INFRASTRUCTURE.md` shows an `/api` base. Other configuration examples use an origin-only base. The observer now supports both forms, including trailing slashes, and requests the existing `/api/generate-report` route. An explicitly supplied API path prefix retains its base-path semantics. No destination host is selected when configuration is absent.

Missing key, missing URL or invalid URL produces a warning and zero outbound requests. A configured request rejected by HTTP or network failure produces a sanitized error diagnostic. Response bodies, raw exceptions, URLs and credentials are omitted from these diagnostics. `redirect: 'error'` prevents automatic forwarding of the internal header to a redirect destination. The timeout bounds the optional fetch using the platform's AbortSignal implementation.

Report triggering remains an optional asynchronous consequence of `EXAM_COMPLETED`. The callback deliberately does not await the report request. Configuration failure, HTTP failure, network failure and a pending request therefore do not reject completion-event delivery. Event-bus tests verify that other completion observers still run. This change does not add a retry store or guarantee report delivery. A skipped or failed report requires the existing configured report path or an existing authorized caller to try again.
