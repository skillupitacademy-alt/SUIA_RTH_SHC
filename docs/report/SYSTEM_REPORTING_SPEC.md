# System Reporting Specification

Based on the [Architecture Lifecycle](file:///d:/onlinewebsites/quiz-platform/docs/pages/exams/architecture_lifecycle.md), this specification defines the official reports generated by the Quiz Platform. All reports are driven by the **Intelligence Hub** (`results_by_dimension`).

---

## 1. The Core Reporting Dimensions
Insights are sliced across four primary axes:

| Dimension | Table Source | Purpose | Visual Representation |
| :--- | :--- | :--- | :--- |
| **Hierarchy** | `domains` / `subjects` | Broad curriculum proficiency. | Progress Bars & Pie Charts |
| **Skill** | `skills` | Granular ability assessment (e.g., SQL Joins). | Heatmaps & Lists |
| **Category** | `skill_category` | Behavioral & Competency groupings. | Radar (Spider) Charts |
| **Nature** | `mapping_type` | Academic vs. Applied balance. | 3-Way Venn or Bar Charts |

## 2. Official Report Types

### A. Executive Proficiency Radar
*   **Detailed Guide**: [BEHAVIORAL_RADAR_REPORT.md](file:///d:/onlinewebsites/quiz-platform/docs/report/BEHAVIORAL_RADAR_REPORT.md)
*   **Goal**: Provide a high-level view of a candidate's competency "Profile."
*   **Data Axis**: `skill_category` (Technical, Cognitive, Process).
*   **Metric**: Weighted score based on skill `weight`.

### B. The Mapping Trinity (Nature of Knowledge)
*   **Detailed Guide**: [NATURE_OF_KNOWLEDGE_REPORT.md](file:///d:/onlinewebsites/quiz-platform/docs/report/NATURE_OF_KNOWLEDGE_REPORT.md)
*   **Goal**: Distinguish between "knowing" and "doing."
*   **Data Axis**: `mapping_type` (Conceptual, Technical, Practical).
*   **Metric**: Accuracy multiplied by weight.

### C. Skill Proficiency Matrix
*   **Detailed Guide**: [SKILL_COMP_MATRIX_REPORT.md](file:///d:/onlinewebsites/quiz-platform/docs/report/SKILL_COMP_MATRIX_REPORT.md)
*   **Goal**: Detailed list of specific technical strengths.
*   **Data Axis**: Granular `skills`.

### D. Curriculum Mastery Analysis
*   **Detailed Guide**: [CURRICULUM_MASTERY_REPORT.md](file:///d:/onlinewebsites/quiz-platform/docs/report/CURRICULUM_MASTERY_REPORT.md)
*   **Goal**: Assessment of mastery across Domains, Subjects, and Topics.

### D. Complexity & Time Efficiency Report
*   **Goal**: Analyze performance under pressure vs. difficulty.
*   **Data Axis**: `questions.difficulty` + `exam_questions.response_metadata`.
*   **Insight**: "Candidate scores 90% on Expert Technical questions but takes 3x the estimated time."

### E. Topic-Weight Distribution (The "Heal" Report)
*   **Goal**: Identify if the question pool correctly covers the exam blueprint.
*   **Data Axis**: `topics.weight` vs. `question_skills` coverage.
*   **Use Case**: System health auditing for Content Managers.

### F. High-Fidelity PDF Analytic Report
*   **Goal**: Provide a professional, multi-page downloadable summary for users and admins.
*   **Features**: Scalable PDF generation using `puppeteer-core`, stored in Vercel Blob/Cloudflare R2.
*   **Structure**: 7-page report including Executive Summary, Subject Breakdown, Complexity Ladder, and Question Audit.

## 3. Weighted Scoring Logic

The **Scoring Engine** does not treat all correct answers equally. The score for a dimension is calculated as:

$$Dimension Score = \frac{\sum (QuestionWeight \times IsCorrect)}{\sum (QuestionWeight)}$$

Where:
*   **QuestionWeight** is derived from the `weight` (1-10) of the primary skill associated with that question.
*   **IsCorrect** is 1 for success, 0 for failure.

This ensures that failing a **Weight: 10** (Critical) question impacts the score more heavily than failing a **Weight: 2** (Fringe/Bonus) question.
